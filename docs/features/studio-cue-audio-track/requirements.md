# 记住转写时的音轨 需求

## 目标与范围

多音轨的视频（例如原声 + 配音、原声 + 同传）转写时可以选择音轨，但选择没有保存：之后试听、连续播放、波形与重新识别都固定解码**第一条**音轨，可能与转写所用的音轨不同（未手动选择时，转写还会优先使用标为默认的音轨）。本次让转写生成的文档**记住转写实际使用的音轨**，之后的原声相关功能都用这条音轨，并在“原始音频”面板中显示。

对应 `docs/TODO.md`「字幕工作台：听原声校对的后续 → 记住转写时的音轨」。

来源：2026-10-11 用户：“你上面说的这些建议都挺好的，可以记录到一个TODO文档，然后再逐一处理”；随后“跑完后提交并推送，然后继续下一项”。

## 范围外

- 为导入的字幕或手动选择的媒体单独选择音轨（仍为第一条；若文档记住了转写音轨，手动重新选择文件时沿用，见 R-TRACK-02）。
- 已有的转写文档（本次之前生成）补记音轨：无法得知当时的选择，仍为第一条。

### R-TRACK-01 转写文档记住所用音轨

| 字段 | 值 |
| --- | --- |
| 来源 | TODO「转写时选的音轨目前未保存」 |
| 状态 | active |
| 批次 | I1 |

#### 说明

- 入队时按探测结果确定实际使用的音轨：用户选择的音轨；未选择时与转写相同的自动规则（唯一的默认音轨，否则第一条）。
- 转写完成生成文档时，文档来源信息记下该音轨：在媒体音轨中的序号（第几条音轨，从 1 开始），以及语言、标题（探测到时）。
- 只有一条音轨的媒体同样记下（序号 1），行为与现在相同。

#### 验收标准

- AC-TRACK-01-1: 选择第 2 条音轨转写后，生成文档的来源音轨序号为 2，并带有探测到的语言与标题；未选择且第 2 条为唯一默认音轨时同样记为 2；都不是默认时记为 1。
- AC-TRACK-01-2: 旧文档（没有音轨信息）照常读取、编辑与导出；文档校验拒绝不合法的序号（小于 1 或超过媒体音轨上限）。

#### 边界与异常

- 音轨信息属于文档来源，与其他来源字段一样不可编辑；导出不受影响。

### R-TRACK-02 原声功能使用记住的音轨

| 字段 | 值 |
| --- | --- |
| 来源 | TODO「多音轨文件试听固定播放第一条音轨」 |
| 状态 | active |
| 批次 | I1 |

#### 说明

- 试听、连续播放、波形与重新识别解码文档记住的音轨（FFmpeg 选择第 N 条音频流）；没有记住时为第一条。
- 适用于转写时的原文件，以及用户为该文档手动选择的媒体（常见于原文件移动后重新选择同一视频）；若所选文件没有这条音轨，改用第一条，不报错。
- “原始音频”面板在文件名下显示所用音轨（如“音轨 2 · ja · 通訳音声”）；未记住音轨时不显示。

#### 验收标准

- AC-TRACK-02-1: 一个两条音轨（第 1 条 440 Hz、第 2 条 880 Hz）的文件，以第 2 条转写的文档试听时解码到 880 Hz；以第 1 条转写的文档解码到 440 Hz。
- AC-TRACK-02-2: 为记住第 2 条音轨的文档手动选择只有一条音轨的文件时，试听解码第一条，不报错。
- AC-TRACK-02-3: 界面上转写时选择第 2 条音轨，完成后打开文档，“原始音频”面板显示“音轨 2”及其语言与标题。

#### 边界与异常

- 导入字幕按同名匹配到的媒体不受影响（第一条）。
