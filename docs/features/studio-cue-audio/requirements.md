# 字幕片段原始音频试听 需求

## 目标与范围

在字幕工作台校对、修订字幕时，可以就地试听某条（或连续几条）字幕对应时间段的**原始媒体音频**，用来核对听写、断句、时间和译文是否贴合原声，而不必切到播放器手动拖进度条。

覆盖：

- 文档与原始媒体的关联：转写文档自动使用转写时的媒体文件；导入的字幕文件自动匹配同目录同名的媒体文件，也可由用户手动选择/更换/取消关联。
- 按需从硬盘截取片段音频：每次试听由主进程用应用自带的 FFmpeg 只解码所需时间段，不复制、不缓存整份媒体，不在磁盘留下临时文件。
- 试听入口：字幕预览列表的每一行（含放大预览）、右键/更多菜单与键盘快捷键、AI 修订建议（改字建议与合并/删除/改时间建议）、术语一致性检查中的每处出现。

来源：2026-10-11 用户：“字幕工作台中的部分地方（比如字幕预览列表中的每一行、某些AI修订或类似建议/显示某些字幕片段时）需要支持一下播放片段的原始音频的功能（如果有/能找到/能匹配到原始音频的话）……主要是为了能让用户更方便地结合原始媒体来审计/修订字幕。可以设计一下实现一下（先写文档再开发）”。

## 范围外

- 完整媒体播放器（视频画面、拖动进度条、倍速、音量、波形图、跟随播放滚动）。
- 按音频自动对齐/调整时间轴；全局时间偏移设置。
- 选择多音轨文件中的某条音轨：本次固定播放第一条音频流（转写时选的音轨目前未持久化）。
- 字幕导入前的预览（双语识别候选、批量导入列表）、执行记录与知识试译中的字幕行。
- Agent 工具中的试听。

### R-AUDIO-01 文档关联原始媒体

| 字段 | 值 |
| --- | --- |
| 来源 | 2026-10-11 用户请求（见目标与范围）：“如果有/能找到/能匹配到原始音频的话” |
| 状态 | active |
| 批次 | I1 |

#### 说明

每个文档最多关联一个原始媒体文件，按以下优先顺序确定：

1. **手动关联**：用户通过系统文件选择框选择的媒体文件（任何文档都可以；转写文档的原文件移动后也用它重新关联）。
2. **转写来源**：转写文档自动使用转写时读取的媒体文件（已有的私有来源记录）。
3. **同名匹配**：导入的字幕文件，在其所在目录中查找“同名”媒体文件：去掉字幕扩展名后与媒体文件名（去扩展名）相同；或字幕名再去掉一个语言/版本后缀（如 `.en`、`.zh-CN`、`.chs`、`.eng`、`.forced`、`.sdh`，最多去两段）后相同。只有唯一的最佳匹配时才采用；多个同级候选时视为未匹配。

媒体文件身份（路径与文件标识）在关联时记录，每次试听前复核；文件被移动、删除或修改后显示为“不可用”，不会去播放别的文件。媒体路径只在主进程内使用，渲染进程只看到文件名、关联方式与状态。

#### 验收标准

- AC-AUDIO-01-1: 转写生成的文档在原媒体文件未变动时，状态为“已关联（转写来源）”并显示媒体文件名；把该文件移走或改动后，状态变为“不可用”，并提供“选择媒体文件…”。
- AC-AUDIO-01-2: 导入 `Show.S01E01.en.srt` 且同目录有唯一的 `Show.S01E01.mkv` 时，状态为“已关联（同名匹配）”；同目录有两个同级候选（如 `.mkv` 与 `.mp4`）或没有媒体文件时，状态为“未关联”。
- AC-AUDIO-01-3: 用户通过“选择媒体文件…”选择任意受支持扩展名的文件后状态为“已关联（手动选择）”，并在重启应用后保持；“取消关联”后回到自动规则（转写来源/同名匹配/未关联）；取消文件选择框不改变现状。
- AC-AUDIO-01-4: 渲染进程得到的状态与结果中不包含媒体文件的完整路径；只允许当前窗口已打开的文档查询与修改关联，其它文档 ID 被拒绝。

#### 边界与异常

- 受支持的媒体扩展名：常见视频 `mp4 m4v mkv mov avi wmv flv webm ts m2ts mts mpg mpeg 3gp` 与音频 `mp3 m4a aac wav flac ogg oga opus wma ac3 eac3 dts amr aiff aif caf`。文件内容是否可解码在试听时才知道。
- 关联不会改变文档内容与修订号，不影响导出、翻译与撤销历史；删除文档时一并删除私有关联记录。
- 手动选择的文件不校验与字幕是否同源（时长等不作硬性检查）。

### R-AUDIO-02 按字幕片段截取音频

| 字段 | 值 |
| --- | --- |
| 来源 | 2026-10-11 用户请求：“当然不可能把所有音频都缓存到应用里，肯定是动态去硬盘上读取的吧” |
| 状态 | active |
| 批次 | I1 |

#### 说明

渲染进程以 `文档 + 字幕 ID`（一条或连续多条的首尾）或 `文档 + 明确时间段`（AI 建议中的新时间）请求一段音频。主进程按文档当前内容确定时间段：

- 开始 = 首条字幕开始时间；结束 = 末条字幕结束时间。结束时间未知（LRC 等）时取下一条更晚开始的字幕的开始时间，没有则开始 + 5 秒；转写文档不超过媒体时长。
- 前后余量（用户偏好：无 / 0.3 秒 / 1 秒，默认 0.3 秒）向两侧扩展，开始不小于 0。
- 单次片段最长 120 秒（不含余量），超出时只截前 120 秒并在结果中标明。

主进程用应用自带并已校验的 FFmpeg 从媒体文件直接解码该时间段为单声道 48 kHz 16 位 PCM，在内存中封装为 WAV 返回；不写临时文件。同一窗口新的试听请求会取消尚未完成的上一个。

#### 验收标准

- AC-AUDIO-02-1: 对时间为 00:25:00.250 → 00:25:04.750 的字幕、余量“无”时，返回的 WAV 时长为 4.5 秒（±1 个采样块），内容取自媒体对应位置（用已知频率分段的测试音频验证）；余量 0.3 秒时为 5.1 秒，开始时间为 0 的字幕不产生负的开始。
- AC-AUDIO-02-2: 结束时间未知的 LRC 字幕播放到下一条更晚字幕的开始；最后一条播放 5 秒；超过 120 秒的连续选择只截前 120 秒并标记已截断。
- AC-AUDIO-02-3: 未关联、媒体不可用、没有音频流、解码失败、FFmpeg 运行时不可用这几种情况分别返回可区分的原因，不抛出未处理异常，不影响文档。
- AC-AUDIO-02-4: 快速连续请求时，前一个尚未完成的解码被取消（进程结束），只有最后一个请求返回音频；试听后应用数据目录与系统临时目录中没有残留的片段文件。

#### 边界与异常

- 明确时间段请求必须是整数毫秒、开始 ≥ 0、结束 > 开始；不合法时拒绝。
- FFmpeg 运行时只在首次试听时校验一次并在本次会话复用；可执行文件变化或启动失败时重新校验。
- 单次解码有超时（20 秒）与输出上限（按时间段计算的字节数 + 余量）；超出即中止并报告解码失败。

### R-AUDIO-03 字幕预览列表中试听

| 字段 | 值 |
| --- | --- |
| 来源 | 2026-10-11 用户请求：“比如字幕预览列表中的每一行” |
| 状态 | active |
| 批次 | I1 |

#### 说明

- 每行序号位置在悬停、键盘当前行或播放中显示“播放/停止”按钮；播放中按钮带进度环，所在行有轻微标识。
- 快捷键 `P`：播放/停止所选字幕——单条时播放该条；选中多条且相邻时从第一条播放到最后一条；不相邻时播放当前（焦点）行。
- 字幕右键菜单与行“更多”菜单中有“播放原始音频”项（显示快捷键 P）。
- 列表顶部工具栏有“原始音频”按钮，打开小面板：关联状态（文件名与关联方式）、选择/更换媒体文件、取消关联、前后余量。
- 同一时间只播放一段：开始新的试听会停止当前的；切换文档、离开工作台时停止。
- 放大预览中的列表同样可用。

#### 验收标准

- AC-AUDIO-03-1: 有可用媒体时，悬停某行可见播放按钮，点击后该按钮变为加载中再变为播放中（带进度），播放到片段末尾自动回到空闲；再次点击或按 P 立即停止。
- AC-AUDIO-03-2: 键盘选中相邻 3 条后按 P，播放从第 1 条开始到第 3 条结束的连续片段；右键菜单“播放原始音频”与 P 行为一致；正在编辑文字或时间时按 P 输入字母而不触发播放。
- AC-AUDIO-03-3: 未关联或不可用时不显示行内播放按钮，菜单项禁用并说明原因，按 P 时打开“原始音频”面板，说明未找到原始媒体并可选择文件；选择后无需刷新即可试听。
- AC-AUDIO-03-4: 播放 A 行时点击 B 行播放，A 立即停止、B 开始；切换到另一文档或离开工作台后不再有声音；放大预览中行内按钮与 P 可用。
- AC-AUDIO-03-5: 在 1280×860 浅色与 786×660 深色下，按钮不改变行高与列宽、不遮挡序号以外的内容，面板不超出窗口；控件有可读名称、键盘可达。

#### 边界与异常

- 播放失败（解码失败等）时按钮显示错误图标，提示原因，几秒后或下次操作恢复。
- 翻译任务进行中不影响试听（只读操作）。

### R-AUDIO-04 AI 修订与一致性检查中试听

| 字段 | 值 |
| --- | --- |
| 来源 | 2026-10-11 用户请求：“某些AI修订或类似建议/显示某些字幕片段时” |
| 状态 | active |
| 批次 | I1 |

#### 说明

- AI 修订结果中：每条改字建议可试听对应字幕；合并建议试听合并后的整段时间；删除建议试听被删字幕；改时间建议试听**建议的新时间段**。
- 术语一致性检查的每处出现可试听对应字幕（可能属于其他文档，按该文档自己的媒体关联）。
- 与预览列表共用同一个播放器（同一时间一段）；关闭对话框时停止。

#### 验收标准

- AC-AUDIO-04-1: AI 修订结果中点击某条建议的播放按钮只播放、不勾选/取消该建议；改时间建议播放建议的新时间段，合并建议播放首条开始到末条结束。
- AC-AUDIO-04-2: 一致性检查中其它文档的出现按该文档的媒体关联播放；该文档没有可用媒体时该处不显示播放按钮（行首留空对齐），不报错。
- AC-AUDIO-04-3: 关闭修订或一致性检查对话框时停止正在播放的片段。

#### 边界与异常

- 当前文档未关联媒体时，修订结果中不显示播放按钮（与预览列表一致）。

### R-AUDIO-05 不打扰与资源约束

| 字段 | 值 |
| --- | --- |
| 来源 | 项目约定：自动化 UI 测试默认安静运行（docs README「运行测试」、FK-PIT-0188）；R-AUDIO-02 的“动态读取” |
| 状态 | active |
| 批次 | I1 |

#### 说明

- 自动化 UI 测试（quiet / inactive 窗口模式）中应用整体静音，试听测试不发出声音。
- 渲染进程只缓存最近 6 段已解码片段（重复试听同一段立即播放），文档修订或关联变化后不再使用旧片段。

#### 验收标准

- AC-AUDIO-05-1: 以默认 quiet 模式启动的 Electron 测试中 Chromium 处于静音（`mute-audio`），而播放状态与进度照常推进；visible 模式不静音。
- AC-AUDIO-05-2: 连续试听 10 段不同片段后渲染进程只保留 6 个片段对象 URL，被淘汰的已释放；文档修订变化后再试听会重新向主进程请求。

#### 边界与异常

- 静音只作用于测试窗口模式（quiet / inactive），不改变用户正常运行时的音频。
- 缓存只在渲染进程内存中，关闭窗口即释放，不写磁盘。
