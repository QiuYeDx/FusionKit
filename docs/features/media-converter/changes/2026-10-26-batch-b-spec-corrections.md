# 变更：批次 B 实测带来的规格纠正

日期：2026-10-26

## 来源与分类

- **来源：** 实施 I1 的批次 B 时（T-ENCODE-02/03/04 的实现者与独立评审），在随附 ffmpeg 与本机 RTX 4070 Ti SUPER 上实测发现以下问题。证据见 `records/i1/T-ENCODE-02.md`、`T-ENCODE-03.md`、`T-ENCODE-04.md` 及其 evidence 文件。
- **分类：** spec-correction（原文有错或不准确）。范围没有扩大，也没有新增用户可见功能。由协调者在已批准的 I1 范围内纠正，同时刷新批准摘要，并在交接时告知用户。

## 行为

| 条目 | 旧 | 新 | 原因 |
| --- | --- | --- | --- |
| AC-ENCODE-02-2 尺寸前置条件 | NVENC 宽 ≥ 144、高 ≥ 120 | 按编码器的实测范围：NVENC 的 H.264 宽 145–4096、高 ≥ 49；HEVC 宽 ≥ 129、高 ≥ 33；AV1 宽 ≥ 129、高 ≥ 65；HEVC/AV1 每边 ≤ 8192；MF 硬件同 NVENC；libopenh264 面积 ≤ 4096×2304 | 原值只来自 3 个尺寸样本。选错编码器会导致它在本会话被降级（AC-ENGINE-03-3） |
| AC-ENCODE-03-2 未标记色彩推定 | 短边 < 720 为 BT.601 | 宽 ≥ 1280 或高 > 576 为 BT.709，否则为 BT.601 | 原规则把 1280×544 这类宽银幕 720p 裁切标为 BT.601，与 mpv 等常见播放器的推定相反，导致颜色偏移 |
| AC-ENCODE-04-5 同编码转换 | 目标码率不高于源码率时直接复制 | 目标码率不低于源码率时直接复制；低于源码率时重新编码以减小体积 | 原文方向写反了。原意是避免「同编码重新编码到更高码率」（调研中的反模式），而不是禁止用户把 320k MP3 转成更小的 MP3 |

设计层面的同步调整（不改 AC）：

- **engine §2 旋转角：** 只从 Display Matrix 读取。ffmpeg 8 的自动旋转会忽略旧式 `rotate` 标签；如果仍读取这个标签，规划器缩放时会交换宽高，导致画面变形。
- **encode §7 输出上限：** 重新编码的视频，上限改为 max(源体积 × 4, 1.0 bpp × 像素速率 × 时长) × 1.05 + 16 MiB。原来的 0.15 bpp 会被 MF 等编码器在「画质优先」档实际达到的码率突破（实测约 1.6 bpp）。
- **encode §5 ALAC 声道布局：** 对 ALAC 不支持的布局，改为重混到最接近的 ALAC 布局，不再只改标签。只改标签会把后置声道标成中置声道（实测）。
- **encode §2 MKV 行：** matroska 封装器拒收的音频编码（如 s302m）不直接复制：转换时转为 Opus，提取时解码为 WAV。
