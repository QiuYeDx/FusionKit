# encode 需求

需求行为只在这里定义；业务目标来源于 [brd.md](../../brd.md)。不要在 tasks 或 record 中另写一套期望。

## 目标与范围

encode 是编码策略层，以纯函数为主。

- **输入**：媒体信息、任务设置、能力表。
- **输出**：
  - 每条流的处理方式：复制、编码或丢弃；
  - 滤镜链；
  - 封装参数；
  - 完整的 ffmpeg 参数；
  - 每个输出的字节上限；
  - 给用户看的处理计划摘要。

当前批次 I1 覆盖以下内容：

- 容器 × 编码兼容矩阵、任务 × 媒体类型矩阵、流规划；
- 视频压缩的简单模式、编码器选择与降级链、参数表与校准；
- 视频正确性：旋转、色彩、HDR、VFR、隔行；
- 音频转换与提取；
- 视频内音频的处理；
- 「不变大」与无意义转换。

## 范围外

- 目标大小（R-ENCODE-07）、感知画质目标（R-ENCODE-08）、压缩前预估（R-ENCODE-09）：I2。
- 高级编码参数（R-ENCODE-10）、高级滤镜与音频处理（R-ENCODE-11）、GIF/WebP 与无损裁剪（R-ENCODE-12）：I3。
- 帧率上限：I3 的高级设置。
- Opus/OGG 封面写入（I1 只提示会丢失）。
- 保留杜比视界 RPU。
- 烧录字幕、调色、去水印。

## 需求

### R-ENCODE-01 兼容矩阵、任务矩阵与流规划

| 字段 | 值 |
| --- | --- |
| 来源 | BR-01, BR-02 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

不能依赖 ffmpeg 的默认流映射，原因有三：

- 默认只保留一条音轨；
- 会把封面当视频；
- MP4 会因数据流而失败。

规划器要逐条决定每条流的去留，并在开始前说明会丢失什么。

#### 验收标准

- AC-ENCODE-01-1: 用同一组「媒体信息 + 任务设置 + 能力表」反复调用规划器，结果始终相同。结果包括：每条流的处理（复制；编码，含编码器与参数；丢弃，含原因）、滤镜链、封装参数、每个输出的字节上限，以及完整的 ffmpeg 参数数组。每种夹具组合都有快照测试。
- AC-ENCODE-01-2: 生成的参数始终使用显式映射：主视频 `0:V:0`、全部音轨、目标容器能容纳的字幕。不使用默认映射，不使用 `-map 0`。数据流（tmcd、gpmd 等）一律丢弃。封面图不作为主视频。
- AC-ENCODE-01-3: 字幕与附件按目标容器处理：
  - **MP4/MOV**：文本字幕转为 mov_text。其中带样式、定位或重叠事件的 ASS/SSA 附警告 `subtitle_styling_lost`。图形字幕（PGS、VobSub、DVB）丢弃，在摘要中逐条列出。字体附件丢弃并说明。HEVC 写 `hvc1` 标签。写 `+faststart`。
  - **WebM**：只允许 VP8/VP9/AV1 视频、Opus/Vorbis 音频、WebVTT 字幕，其余转码或丢弃并说明。
  - **MKV**：保留全部字幕与附件；mov_text 与其他没有 Matroska CodecID 的字幕（如 eia_608）转为 SRT 并说明。
- AC-ENCODE-01-4: 用 ffprobe 比较输出与源，以下内容一致：全局元数据与章节；MKV 中每条音轨与字幕的语言、标题、默认/强制标记；MP4/MOV 中每条音轨与字幕的语言、强制标记、音轨默认标记，标题写入并比较 `handler_name`。源没有默认字幕时，MP4 封装会把第一条字幕标为启用，这一点在摘要中注明，不算不一致。
- AC-ENCODE-01-5: 开始前请求处理计划摘要，能看到：
  - 将使用的编码器（友好名称）；
  - 每条流如何处理；
  - 会丢失什么，以及原因；
  - 是否只换封装；
  - 警告列表。
- AC-ENCODE-01-6: 任务 × 媒体类型矩阵如下，空着的格子即生成计划。

  | 任务 | video | video_no_audio | audio | audio_with_cover |
  | --- | --- | --- | --- | --- |
  | 压缩视频 | | | `task_not_applicable` | `task_not_applicable` |
  | 转换为视频格式 | | | `no_video_stream` | `no_video_stream` |
  | 转换为音频格式 | 抽取并编码默认音轨 | `no_audio_stream` | | |
  | 提取音频 | | `no_audio_stream` | `task_not_applicable` | `task_not_applicable` |

  每个格子都有规划器夹具测试。
- AC-ENCODE-01-7: 「转换格式」需要重新编码视频时（流不兼容，或关闭了「尽量只换封装」），按目标容器选编码：
  - MP4 与 MOV：§3 的 H.264 降级链；MOV 源中的 ProRes 可以复制。
  - WebM：libsvtav1 10-bit（§3 的 AV1 参数表），音频为 Opus。
  - MKV：默认复制；必须重新编码时用 §3 的 AV1 降级链。

  转换任务的档位与压缩档位同名同值。`cpu_weak_encoder` 与 `no_encoder_available` 同样适用。每种容器都有快照夹具。
- AC-ENCODE-01-8: 「压缩视频」的输出容器可选「自动 / MP4 / MKV」，默认为「自动」。源满足以下任一条件时，自动选 MKV；否则选 MP4：
  - 有带样式、定位或重叠事件的 ASS/SSA；
  - 有图形字幕；
  - 有附件。

#### 边界与异常

- 无法满足的组合返回带原因码的错误，不生成参数，例如容器不支持任何可用的视频编码器、杜比视界 Profile 5。

### R-ENCODE-02 视频压缩简单模式、编码器选择与校准

| 字段 | 值 |
| --- | --- |
| 来源 | BR-02 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

用户只做三个选择，编码器与参数由本模块根据能力表决定：

- 压缩档位：画质优先 / 均衡 / 体积优先；
- 输出编码：最小体积（AV1）/ 苹果与较新设备（HEVC）/ 最大兼容（H.264）；
- 分辨率上限（默认保持原始）。

参数初值见 design 的参数表，I1 末尾用真实样片校准（AC-ENCODE-02-6）。

#### 验收标准

- AC-ENCODE-02-1: 选「最小体积（AV1）」时，默认使用 libsvtav1，preset 6，`yuv420p10le`，GOP 约 5 s，CRF 按档位与输出分辨率取 design 参数表中的值。打开「使用显卡加速」且有实测可用的 AV1 硬件编码器时，按 av1_nvenc → av1_qsv → av1_amf 选第一个可用的，使用它的恒定质量档位参数。
- AC-ENCODE-02-2: 选「苹果与较新设备（HEVC）」或「最大兼容（H.264）」时，按降级链选第一个满足以下三个条件的编码器：实测可用；本会话未降级；满足尺寸前置条件（NVENC 宽 ≥ 144、高 ≥ 120；libkvazaar 宽高为 8 的倍数，必要时向下取整）。
  - HEVC：nvenc → qsv → amf → mf（硬件）→ libkvazaar
  - H.264：nvenc → qsv → amf → mf（硬件）→ mf（软件）→ libopenh264

  落到 libkvazaar、mf（软件）或 libopenh264 时，摘要提示 `cpu_weak_encoder`。
- AC-ENCODE-02-3: 分辨率上限按短边计算（旋转后的方向），例如 1080p 表示短边 ≤ 1080。保持宽高比，输出宽高为偶数（libkvazaar 为 8 的倍数）。源不超过上限时不缩放，任何情况下都不放大。
- AC-ENCODE-02-4: 用 ffprobe 检查输出：
  - H.264：8-bit，profile 为 High（包括 MF 编码器）；
  - HEVC 硬件编码：10-bit 实测可用时为 Main10，否则为 8-bit；
  - libkvazaar：8-bit；
  - AV1：10-bit；
  - 关键帧间隔约为 5 s（±1 s）。
- AC-ENCODE-02-5: 每个「编码目标 × 档位 × 编码器」组合生成的参数数组与 design 参数表一致，有快照测试，覆盖全 NVENC、仅 CPU、仅 QSV、仅 AMF、NVENC 降级等能力组合。另外在本机，对每个实测可用的编码器按三档各编码一次 2 s 小样：输出都能解码，体积严格递减（画质 > 均衡 > 体积），`level+warning` 日志中没有 `Invalid option`、`Error parsing option`、`auto-selecting format`。
- AC-ENCODE-02-6: 在 A-07 的校准样片上，以默认设置（AV1 软件编码）压缩，满足以下条件：
  - 三档的输出体积严格递减；
  - 各档 VMAF v0.6.1 的中位数：画质优先 ≥ 95，均衡 ≥ 93，体积优先 ≥ 90；
  - 「均衡」档下，每个不是高度压缩源的样片，输出都小于源。

  用户逐档观看后，确认「均衡」档没有明显的画质损失。这是最终门槛。
- AC-ENCODE-02-7: 「压缩视频」默认输出编码的规则（Q-01 选项 B）：
  - 能力表中有任一可用的 HEVC 硬件编码器（hevc_nvenc / hevc_qsv / hevc_amf / hevc_mf 硬件，8-bit 或 10-bit 均可）时，默认「苹果与较新设备（HEVC）」；
  - 没有时，默认「最大兼容（H.264）」；
  - AV1 只在用户主动选择「最小体积（AV1）」时使用。
  
  默认值由纯函数 `defaultCompressCodec(caps)` 计算，主进程通过快照提供给界面。用户选择过输出编码后，以用户的选择为准。

#### 边界与异常

- 能力探测未完成时，不能开始压缩任务。
- 所选编码在本机没有任何可用编码器时，返回 `no_encoder_available`，并给出替代建议。

### R-ENCODE-03 视频正确性：旋转、色彩、HDR、可变帧率、隔行

| 字段 | 值 |
| --- | --- |
| 来源 | BR-02 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

避免压缩和转换中最常见的悄悄出错：方向错误、颜色偏移、HDR 发灰或过曝、音画不同步、隔行条纹。

#### 验收标准

- AC-ENCODE-03-1: 带旋转元数据的竖屏视频重新编码后，用 ffprobe 检查：像素已经旋转，不再依赖显示矩阵，方向正确。只换封装时，保留原显示矩阵。
- AC-ENCODE-03-2: 用 ffprobe 检查输出的色彩原色、传递特性、矩阵与范围：
  - 这些值通过 `setparams` 显式写入，与源一致；
  - 源没有标记时，按分辨率推定（< 720p 为 BT.601，否则 BT.709）并写入；
  - 全范围（pc 或 yuvj*）源无论是否缩放，都经 `scale=in_range=pc:out_range=tv` 转换为有限范围。转换后测得的像素范围在有限范围内：10-bit 时 YMAX ≤ 940。
- AC-ENCODE-03-3: HDR10 或 HLG 源：
  - 输出为 AV1，或 10-bit 实测可用的 HEVC 时，保留 HDR：BT.2020 + PQ/HLG 标记，HDR10 的 Mastering Display 与 Content Light Level 仍在，送入编码器的像素格式为 10-bit。
  - 输出为 H.264，或只能做 8-bit 编码时，先用 zscale 色调映射为 BT.709 SDR，摘要中附 `hdr_tonemapped`。
- AC-ENCODE-03-4: 杜比视界：
  - Profile 5，或基础层兼容 id 为 0 的源，请求重新编码时被拒绝，原因码 `dolby_vision_p5_unsupported`。
  - Profile 7/8 按其 HDR10/HLG 基础层处理，去掉 RPU，摘要中附 `dolby_vision_rpu_dropped`。
- AC-ENCODE-03-5: 可变帧率源（`r_frame_rate` 与 `avg_frame_rate` 不同）输出时保持原时间戳（`-fps_mode passthrough`），输出时长与源相差不超过 max(0.1 s, 0.5%)。场序标记为隔行的源，重新编码时加 `bwdif` 去隔行。

#### 边界与异常

- I1 只信任探测到的场序标记，自动检测隔行（idet）在 I3。
- 4:2:2 与 4:4:4 源统一转为 4:2:0，摘要中附 `chroma_subsampled`。

### R-ENCODE-04 音频转换与提取

| 字段 | 值 |
| --- | --- |
| 来源 | BR-01 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

覆盖个人用户常见的音频需求：无损转便携格式、统一格式、从视频中取出音频、保留标签与封面。

#### 验收标准

- AC-ENCODE-04-1: 音频转换的目标与参数按「高 / 标准 / 小」三档设置，与 design 的音频参数表一致（快照测试）：

  | 格式 | 编码 | 高 / 标准 / 小 |
  | --- | --- | --- |
  | MP3 | libmp3lame VBR，写 ID3v2.3 | `-q:a` 0 / 2 / 5 |
  | M4A（AAC） | 原生 aac CBR | 256 / 192 / 128 kbps |
  | Opus | libopus VBR | 160 / 128 / 96 kbps |
  | FLAC | — | 压缩级别 5 / 5 / 8 |
  | WAV | PCM，保持源位深，`-rf64 auto` | — |
  | ALAC（.m4a） | 保持源位深 | — |

  单声道源的有损码率取 design 表中的单声道值。
- AC-ENCODE-04-2: 「提取音频」默认无损复制，扩展名按原音轨编码选取：

  | 原音轨编码 | 输出 |
  | --- | --- |
  | aac | .m4a |
  | mp3 | .mp3 |
  | opus | .opus |
  | vorbis | .ogg |
  | flac | .flac |
  | alac | .m4a |
  | 小端或压扩 PCM（u8、s16le、s24le、s32le、f32le、f64le、alaw、mulaw） | .wav |
  | 大端 PCM | .aiff |
  | pcm_bluray、pcm_dvd 及其他 PCM | 无损转为同位深的小端 PCM .wav，摘要中注明 |
  | 其他（ac3、eac3、dts、truehd 等） | .mka |

  有多条音轨时，默认取默认音轨（没有则取第一条）。打开「全部音轨」后，每条音轨各输出一个文件，文件名带序号；语言码符合 `^[a-z]{2,3}$` 时也带上语言。输出格式除「保持原音轨」外，还可选 MP3、M4A、Opus、FLAC、WAV、ALAC。
- AC-ENCODE-04-3: 标签与封面：
  - MP3 有 ID3v2.3 标签与封面（APIC）。
  - M4A 有用户标签（标题、艺术家等）与封面。
  - FLAC 有标签与封面。
  - Opus/OGG 保留标签；封面在 I1 丢弃，摘要中附 `cover_dropped`。
  - 源容器的品牌标签（`major_brand` 等）不会被复制进 MP3、FLAC、Opus 的标签。
  - 目标格式会丢章节时（FLAC、WAV、Ogg Vorbis），开始前提示；MP3 与 Opus 保留章节。
- AC-ENCODE-04-4: 声道与采样率：
  - 送入 libopus 时，布局必须是该声道数对应的标准布局（单声道、立体声、3.0、四声道、5.0、5.1、6.1、7.1）。side/back/wide 同义布局用 `channelmap` 改标签；其他布局（2.1、3.1、4.0、quad(side) 等）重混到最接近的标准布局；超过 8 声道下混到 7.1。
  - AAC 不需要改布局。
  - MP3 只支持双声道，多声道源下混，摘要中附 `downmixed_to_stereo`。
  - Opus 输出 48 kHz。AAC 的源采样率高于 48 kHz 时，用 soxr 降到 48 kHz。其他情况保持源采样率。
  - 每条输出音轨用自己的 `-filter:a:<n>` 链，不使用全局或重复的 `-af`。
- AC-ENCODE-04-5: 有损源转为无损格式（如 MP3 → FLAC/WAV）时，计划标记需要确认 `lossy_to_lossless`，提示「不会提升音质，文件会变大」，用户确认后才能开始。源与目标编码相同、且目标码率不高于源时，改为直接复制；如果封装也相同，判定为已是目标格式。

#### 边界与异常

- WAV 的位深：浮点源保持 32 位浮点；整数源超过 24 位时用 32 位整数。
- AMR 与 WMA 只作为输入。

### R-ENCODE-05 视频内音频的处理

| 字段 | 值 |
| --- | --- |
| 来源 | BR-01, BR-02 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P1 |

#### 说明

能直通的音轨直通，避免反复有损编码；不能直通的，按容器选编码重新编码。

#### 验收标准

- AC-ENCODE-05-1: 音轨能否直接复制，先看编码是否在目标容器的兼容清单中：MP4/MOV 为 AAC、MP3、AC3、E-AC3、ALAC；MKV 为全部；WebM 为 Opus、Vorbis。
  - **转换任务**：编码在清单中的音轨，无论码率多少，一律直接复制。例如 MKV（H.264 + AAC，码率未知）转 MP4 时只换封装。
  - **压缩任务**：除了在清单中，还要码率不高于档位码率的 1.25 倍才直接复制。码率按流码率 → `tags.BPS` 的顺序取，都没有时视为不满足。
- AC-ENCODE-05-2: 需要重新编码的音轨，MP4/MOV 用 AAC，MKV/WebM 用 Opus，码率按 design 的「视频内音频」表，依档位与声道数选取。声道数保持不变；超过 8 声道时下混到 7.1。采样率与声道布局规则同 AC-ENCODE-04-4。

#### 边界与异常

- 压缩任务中，无损音轨（FLAC、PCM、TrueHD）和 DTS 总是重新编码。

### R-ENCODE-06 「不变大」与无意义转换

| 字段 | 值 |
| --- | --- |
| 来源 | BR-02, BR-03 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P1 |

#### 说明

压缩后变大的结果和什么都没改变的转换，都不应该产生新文件。

#### 验收标准

- AC-ENCODE-06-1: 「压缩视频」开启「不比原文件小时丢弃」（默认开启）时，计划把输出字节上限设为源体积的 98%。编码中达到上限或完成后输出 ≥ 源体积的 98%，都不发布，状态为已跳过，原因 `not_smaller`，临时文件被删除。关闭此项后正常发布。
- AC-ENCODE-06-2: 「转换格式」满足以下两个条件时，不运行 ffmpeg，直接标为已跳过，原因 `already_target`：
  - 源的容器标识（`format_name` + MP4 系 `major_brand` + Matroska DocType + 扩展名）与目标封装相同；
  - 所有流都会被直接复制。

  因此：MOV 转 MP4 只换封装，MKV 转 WebM 不会被跳过，全部流复制的 MP4 转 MP4 会被跳过。

#### 边界与异常

- 已跳过的条目可以「仍然转换」，即带上 `override` 重试。

### R-ENCODE-07 目标大小

| 字段 | 值 |
| --- | --- |
| 来源 | BR-04 |
| 状态 | deferred |
| 批次 | I2 |

## 约束

- 规划器与参数构建都是纯函数：不读文件系统、不启动进程，输入全部显式传入。
- 不使用 GPL 滤镜（如 cropdetect、hqdn3d），不使用 SVT-AV1 的 `tune=5`。
- 参数表的初值来自公开资料与本机实测。T-ENCODE-05 校准后，把结果写回 design 参数表，并在 record 中记录变更。
- 警告、跳过与错误原因码都是英文 snake_case，在 `src/media-converter/contract.ts` 中定义为封闭枚举，由 workbench 经 i18n 映射显示。编码器 id 由 workbench 映射成友好名称。
