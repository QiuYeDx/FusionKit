# workbench 需求

需求行为只在这里定义；业务目标来源于 [brd.md](../../brd.md)。不要在 tasks 或 record 中另写一套期望。

## 目标与范围

workbench 是「音视频转换」工具在渲染进程中的部分，包括：

- 工具入口与注册；
- 添加文件与媒体信息展示；
- 任务类型与简单设置；
- 开始前说明处理结果；
- 队列、进度与结果；
- 引擎状态与硬件加速说明；
- 中文、英文、日文、繁体中文四种语言的文案。

当前批次 I1 覆盖 Windows 上简单模式的主流程。

## 范围外

- 目标大小与平台预设、压缩前预估、预览对比、完成后的画质报告（R-WORKBENCH-06，I2）。
- 高级设置、命令预览、自定义预设、单个文件覆盖设置、并发数设置（R-WORKBENCH-07，I3）。
- 帮助页、README、官网与更新日志（R-WORKBENCH-08，I5）。
- macOS 上的完整界面：I4 之前只显示「暂不支持此平台」。
- 添加文件夹：I1 拒绝并给出提示。
- 应用内播放器：I1 只展示媒体信息。I2 的「播放样片对比」改用系统播放器，或用应用内 `<video>` 播放 H.264/AV1。

## 需求

### R-WORKBENCH-01 工具入口与注册

| 字段 | 值 |
| --- | --- |
| 来源 | BR-01, BR-02 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

工具列表新增「媒体工具」分区，放入「音视频转换」磁贴，路由为 `/tools/media/converter`。

#### 验收标准

- AC-WORKBENCH-01-1: 在 Windows 上打开工具列表时：
  - 能看到「媒体工具」分区和「音视频转换」磁贴，磁贴有图标、媒体类工具色、标题与简介，四种语言都齐全；
  - 点击磁贴进入 `/tools/media/converter`，底部导航显示工具名；
  - 按 Esc 或点返回按钮回到工具列表；
  - 工具列表的总数计入这个工具。
- AC-WORKBENCH-01-2: 在 macOS 上（I4 之前）打开工具列表，看不到该分区和磁贴。直接访问该路由时，页面照常显示工具页头，正文只显示「暂不支持此平台」说明。Esc 与返回按钮照常可用。
- AC-WORKBENCH-01-3: 新增的 `media` 命名空间具备 zh、en、ja、zh-Hant 四种文案，`pnpm run i18n:check` 能通过。磁贴与底部导航用到的键已登记到 i18n 用法清单中。新增分区后，精选、经典、实验分区的布局不变；Agent 能力目录测试、e2e 工具目录断言和工具页导航测试的结果与 HEAD 基线相同。

#### 边界与异常

- 新分区不放进 `CLASSIC_TOOLS` 或 `FEATURED_TOOLS`，以免牵动 Agent 能力目录的约束。I5 接入 Agent 时再重新评估位置。

### R-WORKBENCH-02 添加文件与媒体信息

| 字段 | 值 |
| --- | --- |
| 来源 | BR-01, BR-03 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

添加文件后马上能看到媒体信息。处理不了的文件要说明原因，并给出下一步怎么做。

#### 验收标准

- AC-WORKBENCH-02-1: 添加文件的方式：
  - 拖到页面任意位置，或点上传区打开主进程的选择对话框；对话框可以按视频、音频或全部筛选。
  - 拖入文件夹时提示「暂不支持文件夹，请选择其中的文件」。
  - 一次超过 100 个文件时，只加入前 100 个，并说明有多少个没有加入。
- AC-WORKBENCH-02-2: 文件加入后立即出现在列表中，显示「分析中」。分析完成后显示：
  - 类型图标；
  - 文件名：过长时省略中间部分，悬停或聚焦时显示全名；
  - 时长与体积；
  - 视频：分辨率、帧率、编码、HDR 标记；
  - 音频：编码、声道、采样率、码率；
  - 音轨数与字幕数。
- AC-WORKBENCH-02-3: 无法处理的文件显示具体原因，不影响其他文件：
  - 不是音视频文件；
  - 文件格式不受支持（如播放列表）；
  - 微信语音格式暂不支持；
  - 文件已损坏或无法读取；
  - 拖入的是临时副本，无法找到原文件：提示「请先解压，或用选择文件添加」。

  文件与当前任务不匹配时（例如在「压缩视频」下加入纯音频文件），显示「当前任务不适用」和一键切换到合适任务的按钮；开始时跳过该文件。
- AC-WORKBENCH-02-4: 再次加入列表中已有的文件时，提示「已在列表中」，不新增条目。判断依据是文件身份，而不是文件名。

#### 边界与异常

- 一次加入大量文件时，列表逐个更新，界面保持可操作。

### R-WORKBENCH-03 任务类型与简单设置

| 字段 | 值 |
| --- | --- |
| 来源 | BR-01, BR-02, BR-03 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

左侧设置面板按任务类型显示对应字段。不改任何设置也能直接使用。开始之前，用户应该知道会损失什么。

#### 验收标准

- AC-WORKBENCH-03-1: 设置面板顶部用分段控件选择任务：压缩视频（默认）、转换格式、提取音频。切换后显示该任务的字段，未开始条目的处理计划同步更新。
- AC-WORKBENCH-03-2: 「压缩视频」的字段如下，括号内为默认值：
  - **压缩档位**：画质优先 / 均衡（默认）/ 体积优先。
  - **输出编码**：按用途命名，分为「最小体积（AV1）」「苹果与较新设备（HEVC）」「最大兼容（H.264）」。默认值取快照中的 `defaults.compressCodec`（AC-ENCODE-02-7）：本机有 HEVC 硬件编码器时为 HEVC，否则为 H.264。用户改选后，记住用户的选择。下方用一句话说明当前选项的兼容性：
    - AV1：「体积最小；iPhone 15 Pro 之前的 iPhone、M3 之前的 Mac 自带播放器无法播放」；
    - HEVC：「苹果设备都能播放；Windows 自带的「照片」需要安装 HEVC 扩展」；
    - H.264：「几乎所有设备和 App 都能播放，体积较大」。
  - **输出格式**：自动（默认）/ MP4 / MKV。
  - **分辨率上限**：保持原始（默认）/ 2160p / 1440p / 1080p / 720p / 480p。
  - **使用显卡加速**：只有选 AV1 且有可用的 AV1 硬件编码器时才能打开，说明为「更快，但体积约大一倍」。不能打开时，提示框说明原因，并告诉用户：HEVC 和 H.264 会自动使用显卡（如果有）。
  - **不比原文件小时丢弃**：默认开。
- AC-WORKBENCH-03-3: 「转换格式」的字段：
  - 目标格式：默认 MP4。按视频（MP4/MKV/WebM/MOV）和音频（MP3/M4A/Opus/FLAC/WAV/ALAC）分组。
  - 尽量只换封装：默认开。
  - 重新编码时使用的画质档位。

  「提取音频」的字段：
  - 输出格式：保持原音轨（无损，默认）/ MP3 / M4A / Opus / FLAC / WAV / ALAC。
  - 音质档位：只在选择有损格式时显示。
  - 「全部音轨」开关。
- AC-WORKBENCH-03-4: 面板下部的设置：
  - **输出位置**：源文件旁（默认）/ 指定文件夹。
  - **同名文件**：自动编号（默认）/ 覆盖。选「覆盖」时显示提醒：「会把同名旧文件移到回收站；源文件永远不会被覆盖」。开始时，用确认框列出将被替换的文件。「覆盖」不会保存到下次启动。
  - **低占用模式**：默认关，说明为「编码更慢，但尽量不影响游戏和其他程序」。这个选项由主进程保存。

  除「覆盖」外，所有设置重启后恢复。之前指定的文件夹失效时，回到「源文件旁」并提示。
- AC-WORKBENCH-03-5: 展开一个未开始的条目，可以看到它的处理计划：编码器的友好名称（如「SVT-AV1（CPU）」「NVIDIA NVENC HEVC」）、每条流的处理方式、会丢失的内容与原因、警告。显示内容与主进程的规划结果一致。
- AC-WORKBENCH-03-6: 会丢失内容的条目，不展开也能直接看到一行警告（如「2 条图形字幕将被丢弃」「HDR 将转为 SDR」「ASS 字幕样式将丢失」）。点「全部开始」时，如果有这类条目，先弹出确认框，列出受影响的文件；能通过改为 MKV 避免损失的条目，提供「改为 MKV」按钮。有损转无损的条目也在同一个确认框中确认。

#### 边界与异常

- 开始后修改设置，不影响已排队或运行中的条目。这些条目会注明「按开始时的设置处理」。

### R-WORKBENCH-04 队列、进度与结果

| 字段 | 值 |
| --- | --- |
| 来源 | BR-03 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

随时能看到每个文件的进度和结果，并能逐个控制。

#### 验收标准

- AC-WORKBENCH-04-1: 列表标题栏的操作：
  - 「全部开始」：引擎检测中或不可用时禁用，提示框说明原因；
  - 「全部取消」：有任务运行时出现，需要确认；
  - 「清除已完成」。

  每一行按状态显示开始、取消、重试、移除中可用的操作。
- AC-WORKBENCH-04-2: 运行中的行显示当前阶段（如「编码中」「收尾中」）、进度条（时长未知时为不确定状态）、倍速与 fps、已写大小、剩余时间。数值刷新时布局不抖动。
- AC-WORKBENCH-04-3: 结束后的行按结果显示：
  - **成功**：输出文件名、输出体积、相对源文件的变化（如 −62%，变大时为 +x%），以及「在文件夹中显示」。
  - **部分完成**（提取全部音轨时部分失败）：「部分完成 m/n」，已完成的输出可以打开。
  - **已跳过**：原因，加「仍然转换」。
  - **失败**：简短原因，加「查看详情」。详情包含错误码说明和脱敏后的 ffmpeg 日志末尾。
  - **已中断、已取消、输入已变化**：可以重试。

  完成与失败的变化通过 `aria-live="polite"` 播报。
- AC-WORKBENCH-04-4: 列表上方的汇总栏显示文件数、源文件总体积、已完成数、累计节省的体积。
  - 有任务运行时离开页面，提示一次「转换会在后台继续」。
  - 重载窗口或回到页面后，进度接着显示，不会中断。
  - 一批任务全部完成且窗口不在前台时，发出系统通知。

#### 边界与异常

- 列表有 100 个条目时，滚动与进度刷新保持流畅：只重渲染有变化的条目，进度每 250 ms 最多更新一次，不使用虚拟列表。

### R-WORKBENCH-05 引擎状态与硬件加速说明

| 字段 | 值 |
| --- | --- |
| 来源 | BR-02 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P1 |

#### 说明

让用户知道本机能用哪些硬件加速，以及某种格式为什么输出偏大。

#### 验收标准

- AC-WORKBENCH-05-1: 页头显示引擎状态：
  - 就绪：显示可用的硬件编码，如「NVIDIA NVENC」或「仅 CPU」；
  - 检测中：「正在检测编码能力」；
  - 不可用：原因与处理建议，此时上传区禁用并显示原因。

  页头提供「重新检测」；有硬件编码任务运行时不可用。
- AC-WORKBENCH-05-2: 所选输出编码在本机只能用较弱的 CPU 编码器（openh264、MF 软件、kvazaar）时，设置区显示提示，并提供「改用 AV1」快捷按钮。

#### 边界与异常

- NVENC 驱动过旧时，提示所需的最低驱动版本，并建议更新显卡驱动（不附外部链接）。

### R-WORKBENCH-06 目标大小、预估与预览对比界面

| 字段 | 值 |
| --- | --- |
| 来源 | BR-04, BR-05 |
| 状态 | deferred |
| 批次 | I2 |
| 优先级 | P0 |

#### 说明

- **压缩目标**：可在「按画质」与「按大小」之间切换。按大小时可选平台预设（微信、QQ、QQ 邮箱、邮件附件、Discord 等，精确字节数，标注核实日期），或自定义大小。体积统一按 1024 进制显示。
- **试算**：显示预估的体积范围、VMAF 与耗时。
- **预览对比弹窗**：
  - 同一时刻的原始帧与压缩帧，用滑动分隔线对比；
  - 可切换多个时刻，可在 100% 与适应窗口之间切换；
  - 显示 VMAF；
  - 「播放样片对比」：用系统播放器打开原始片段与压缩片段，H.264/AV1 也可在应用内播放。
- **完成后**：结果行显示 VMAF。

进入 I2 前细化。

## 约束

- 页面结构、间距和圆角遵循 `.agents/skills/fusionkit-ui-design/references/visual-contract.md`，复用 `src/pages/Tools/_shared/ui/` 中的组件。
- 布尔设置用 `ToolSwitchRow`，不用 Checkbox（见 `toolBooleanControlConsumers.test.ts`）。分段选择用 `ToolRadioButtonGroup`（见 `segmentedControlConsumers.test.ts`）。
- i18n 键用 `as const` 映射来解析。磁贴和底部导航的键必须登记到 `scripts/i18n-usage-manifest.mjs` 的对应选择器中。`t()` 中不写中文默认值（FK-PIT-0014）。
- 状态以主进程为准。渲染进程的控制器是模块单例，通过 `useSyncExternalStore` 使用。界面偏好保存在持久化的 zustand store 中，读取时用 zod 清洗。队列选项（并发数、低占用模式）只在主进程保存。
