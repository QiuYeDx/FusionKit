# 媒体转换与压缩 业务范围与路线图

本文是业务目标与范围的权威来源；具体 AC 写在各模块的 requirements.md。采用滚动规划：当前批次展开到任务，后续批次只写目标和验收要点。调研依据见 [discovery.md](discovery.md)。

## 背景、目标与成功条件

个人用户经常要处理这些事：

- 手机拍的视频太大，发不出去或占空间；
- 下载的视频格式播放不了；
- 想从视频里取出音频；
- 把无损音乐转成手机能放的格式。

现有工具各有问题：

- 在线压缩要上传隐私视频，还有大小上限；
- 格式工厂一类有广告；
- HandBrake 术语多，也不能按目标大小压缩；
- 技术最好的感知画质压缩工具（ab-av1、Av1an）只有命令行。

**目标：** 在 FusionKit 中提供一个本机运行的「音视频转换」工具。

- 默认用法：拖入文件、选一个档位、开始。结果画质好、体积小、不覆盖原文件。
- 视频压缩是核心。用 SVT-AV1 10-bit、硬件编码器调优参数、感知画质（VMAF）目标和真 2-pass 目标大小，在保留画质的前提下尽量减小体积。
- 高阶用户可以控制码率模式（恒定质量 / VBR / 2-pass / 带上限的恒定质量 / CBR）、编码器、preset、tune、GOP、位深、滤镜和音频处理。

**成功条件：**

1. Windows 上拖入一段手机拍的视频（iPhone HEVC/HDR 或 1080p H.264），选择「压缩视频 · 均衡」并开始。完成后：
   - 输出放在源文件旁，文件名带后缀；
   - 主观观看无明显画质损失（I1 以 AC-ENCODE-02-6 的校准阈值和人工评审为准；I2 起附带 VMAF 分数）；
   - 体积明显小于原文件；
   - 能在所选编码说明中承诺的设备上播放。

   整个过程中不覆盖原文件，未完成时不残留半成品。
2. MKV 转 MP4 时，若编码兼容，就只换封装，数秒内完成，画质无损。若有 MP4 不能容纳的流（图形字幕等），先说明再处理。
3. 音频能在 MP3、M4A（AAC）、Opus、FLAC、WAV、ALAC 之间转换，并保留标签与封面（目标格式支持的情况下）。能从视频中无损提取音轨。
4. 转换在后台进行：离开页面不中断，进度、速度、剩余时间可见，可以随时取消。编码进程默认以低于正常的优先级运行。开启「低占用模式」后，ffmpeg 的 CPU 占用不超过分配给它的约一半逻辑核（验收时实测），以减少对游戏或其他工作的影响。
5. （I2）可以指定「不超过 20 MB」。超过目标的文件不会被发布，结果尽量接近目标。开始前可以看到预估体积与画质，并通过滑动对比和播放样片预览画质。

## 范围外

- **编辑类**：剪辑时间线、拼接多个文件、烧录字幕、加水印、调色、AI 超分与插帧。
- **输入来源**：URL、直播流、HLS、DVD/蓝光目录、屏幕录制、麦克风录音。微信 SILK 语音只做识别和提示，不解码。
- **自动化**：监视文件夹、定时任务、分段并行编码（Av1an 式）。
- **特殊格式**：杜比视界 Profile 5 的重新编码，给出明确提示。
- **GPL 编码器**：v0.6.0 不随附 x264/x265 等 GPL 编码器（Q-03）。也不读取系统 PATH 中的 ffmpeg，或用户自带的 ffmpeg。
- **云端**：不上传任何文件，不调用付费 API。
- **发布动作**：不代用户提交、推送或发布版本。最终验收由用户完成。

### BR-01 本机完成常见音视频的格式转换与音频提取

| 字段 | 值 |
| --- | --- |
| 状态 | active |
| 批次 | I1 |

#### 说明

支持的输入：

- 常见视频容器：MP4、MOV、M4V、MKV、WebM、AVI、WMV、FLV、TS/M2TS/MTS、MPG、3GP 等。
- 常见音频格式：MP3、M4A/AAC、WAV、FLAC、OGG/Opus、WMA、AIFF、APE、AMR、AC3、M4B 等。

最终以 ffprobe 探测结果为准，不只看扩展名。

支持的输出：

- 视频：MP4、MKV、WebM、MOV。
- 音频：MP3、M4A（AAC）、Opus、FLAC、WAV、M4A（ALAC）。

规则：

- 能只换封装时，优先只换封装（无损、快）。
- 提取音频时，默认无损复制原音轨，也可以转成指定格式。
- 保留元数据、章节、多音轨与可容纳的字幕；不能保留的先说明。

#### 验收要点

- 常见组合能转换成功，输出可被 ffprobe 正确解析，时长一致。
- 只换封装的情况不重新编码。
- 音轨数量、语言标签、元数据和封面按规则保留。
- 不支持的组合有明确提示。

### BR-02 在尽量保持画质的前提下压缩视频体积

| 字段 | 值 |
| --- | --- |
| 状态 | active |
| 批次 | I1 |

#### 说明

简单模式只需做三个选择：

- **压缩档位**：画质优先 / 均衡 / 体积优先。
- **输出编码**：最小体积（AV1）/ 苹果与较新设备（HEVC）/ 最大兼容（H.264），每个选项都附有兼容性说明。默认值按 Q-01 的结论：本机有 HEVC 硬件编码器时用 HEVC，否则用 H.264；AV1 由用户主动选择。
- **分辨率上限**：默认保持原始，只缩小，不放大。

输出格式默认为「自动」：源文件含带样式的 ASS 字幕、图形字幕或附件时用 MKV，否则用 MP4。

工具按机器能力自动选择编码器。AV1 默认用 SVT-AV1 10-bit，也可以选择改用显卡。HEVC/H.264 优先用实测可用的硬件编码器，并使用调优过的恒定质量参数。

自动处理以下情况：

- 旋转；
- 色彩标记；
- HDR（保留或转为 SDR）；
- 可变帧率；
- 隔行扫描；
- 视频内音频（能直通就直通，否则重新编码）。

输出体积达到原文件的 98% 或以上时，默认不保存。

#### 验收要点

- 三档 × 三类编码目标都能产出可播放的文件。
- 硬件编码器只在实测可用时启用，没有时按降级链回退并提示。
- 竖屏视频的方向、HDR 视频的处理结果都正确。
- 默认设置下，真实样片在主观无明显损失的前提下明显变小（I1 用人工样片评审）。

### BR-03 可靠、安全、不打扰的批量处理

| 字段 | 值 |
| --- | --- |
| 状态 | active |
| 批次 | I1 |

#### 说明

**批量与后台：**

- 一次可加入多个文件。主进程持有队列，离开页面后继续，应用重启后保留历史。
- 默认一次只运行一个编码任务，进程优先级低于正常。提供低占用模式：最低优先级，并限制可用的 CPU 核。
- 可以单个或全部取消、重试、移除。
- 会丢失内容的条目（字幕、HDR 等）在开始前直接显示警告并请用户确认。

**输出安全：**

- 默认输出到源文件旁并加后缀。输出先写临时文件，成功后再原子发布。永不覆盖输入文件。
- 同名冲突时自动编号。用户可以显式选择覆盖：被替换的旧文件先移到回收站，并在开始前列出确认。
- 每个输出都有字节上限，开始前按卷检查磁盘空间，输出不会写满磁盘。
- 失败或取消时不残留临时文件；启动时清理上次异常退出留下的残留。

**通知与校验：**

- 批次完成且窗口不在前台时发出系统通知。
- 只用随附并通过完整性校验的 ffmpeg，不使用系统 PATH。

#### 验收要点

- 取消在数秒内生效，并清理临时文件。
- 离开页面后进度继续，回来能看到。
- 退出应用时运行中的任务被取消并清理，下次启动时标记为已中断。
- 目标文件已存在时不会被静默覆盖。
- 输入文件永远不被修改。

### BR-04 按目标大小压缩与压缩前预估

| 字段 | 值 |
| --- | --- |
| 状态 | deferred |
| 批次 | I2 |

#### 说明

用于发送分享场景。目标可以是：

- 平台预设：微信、QQ、QQ 邮箱、邮件附件、Discord 等。数值以精确字节数保存，并标注来源与核实日期，界面统一按 1024 进制显示；
- 自定义大小（MB）；
- 原大小的百分比。

码率按真实时长计算，扣除音频与封装开销。SVT-AV1 使用真 2-pass。每像素比特过低时，自动降低分辨率或帧率并说明原因。结果超标时自动修正后重编，尽量落在目标的 85%–100%；超过目标的文件不会被发布。开始前显示预估体积、画质与耗时。

#### 验收要点

- 不同时长与码率的样片在各目标下都不超过目标，多数落在目标的 85%–100%。
- 自动降分辨率时有说明。
- 预估值与实际值的误差在设计给出的范围内。

### BR-05 感知画质目标与可视化预览对比

| 字段 | 值 |
| --- | --- |
| 状态 | deferred |
| 批次 | I2 |

#### 说明

**画质目标：** 参照 ab-av1 / Av1an 的「目标画质」方法。

1. 从视频中均匀抽取若干片段（无损切片）。
2. 用与正式编码相同的设置做采样编码。
3. 用 VMAF（≤1440p 用 v0.6.1 模型，更高分辨率用 4K 模型）评分，加低分位保护。
4. 插值二分搜索出满足目标分数的最高压缩参数。

三档分别对应目标分数（初值：画质优先 96、均衡 94、体积优先 91）。同时预测体积与耗时。HDR 内容不适用 VMAF，回退到恒定质量档位并说明。

**预览对比：** 对代表片段编码，提取同一时刻的原始帧与压缩帧，用滑动分隔线对比并显示 VMAF。还可以播放原始片段与压缩片段，用来观察运动中的瑕疵。

**完成后报告：** 可选测量整个文件的 VMAF。

#### 验收要点

- 画质目标模式下，输出的 VMAF 达到目标（在给定容差内）。
- 预测体积误差在设计范围内。
- 预览对比的两帧时间对齐、方向和色彩正确。

### BR-06 高阶用户的完整编码配置与自定义预设

| 字段 | 值 |
| --- | --- |
| 状态 | deferred |
| 批次 | I3 |

#### 说明

「高级设置」折叠区包含以下内容。

**编码器参数：**

- 编码器选择（来自能力探测）、preset/速度、码控模式（CRF/CQ/ICQ/QVBR、VBR 1-pass/2-pass、带上限的恒定质量、CBR〔仅支持的编码器〕、平均码率）、码率与峰值、GOP、10-bit。
- SVT-AV1：tune、胶片颗粒合成、variance boost。另有带白名单校验的 SVT 参数文本框。
- NVENC/QSV/AMF：常用参数。

**视频滤镜：** 分辨率与帧率、去隔行（自动检测）、HDR 转 SDR、裁剪（手动或自动黑边检测）、轻度降噪。

**音频：** 编码、码率或 VBR 质量、采样率（soxr 高质量重采样加抖动）、声道与下混、响度标准化（EBU R128 两遍）、音轨与字幕选择、元数据与封面。

**预设与实用功能：**

- 只读的 ffmpeg 命令预览。
- 自定义预设：保存、导入、导出。
- 单个文件覆盖批量设置。
- GIF 与动态 WebP 输出、无损裁剪时长。

#### 验收要点

- 每个高级参数都能在命令预览和输出中观察到效果。
- 非法组合在开始前被拦截，并提示原因。
- 预设可以往返导入导出。

### BR-07 macOS 支持

| 字段 | 值 |
| --- | --- |
| 状态 | deferred |
| 批次 | I4 |

#### 说明

为 macOS arm64 提供能处理视频的 LGPL 媒体引擎（方案见 Q-02），包含 VideoToolbox（H.264/HEVC）、AudioToolbox（AAC，含 HE-AAC），以及 SVT-AV1、Opus、LAME、dav1d、libvpx、zimg、libvmaf 等。它作为独立运行时打包、签名和校验，不改动转写用的冻结运行时。macOS 上的能力矩阵靠能力探测得出。引擎就绪前，macOS 不显示该工具入口。

#### 验收要点

- macOS 上的主链路（I1–I3 已交付的能力）通过同样的验收场景。
- 打包契约、签名与完整性校验通过。
- 许可证与源码记录齐全。

### BR-08 Agent 可调用媒体转换

| 字段 | 值 |
| --- | --- |
| 状态 | deferred |
| 批次 | I5 |

#### 说明

- **内置 FusionKit Agent**：可以根据用户输入的文件路径准备转换或压缩任务卡片，用户确认后执行。
- **外部 Agent（MCP）**：新增读取媒体信息、开始转换、查询任务、取消任务四个工具，使用新的审批组。覆盖文件属于破坏性操作，任何档位都需要确认。

本功能不需要 API Key，符合外部 Agent 的开放范围（external-agent 决策 A-06）。

#### 验收要点

- 两类 Agent 都能完成「检查媒体 → 发起压缩 → 查询进度 → 拿到输出」。
- 未授权路径、只读档位、覆盖确认都有可观察的结果。
