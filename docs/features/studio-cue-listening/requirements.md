# 边听边校对 需求

## 目标与范围

在已有的“字幕片段原始音频试听”（`docs/features/studio-cue-audio/`）之上，让校对者**边听边改**：连续往下听并看到当前播放到哪一句、放慢或循环听难句、在听到的位置直接定下字幕的开始和结束时间、在时间编辑框里看到这一段的声音起伏。

对应 `docs/TODO.md`「字幕工作台：听原声校对的后续」的前三项：用播放位置打点改时间（含波形）、连续跟读、慢放与单句循环。

来源：2026-10-11 用户：“你上面说的这些建议都挺好的，可以记录到一个TODO文档，然后再逐一处理”；随后：“先提交这两项，然后开始做TODO中的吧”。

覆盖两个批次：

- **I1 边听边改**：播放引擎改为可无缝连续播放、可变速（不变调）、可循环；连续跟读；速度与循环设置；播放时用 `[` / `]` 打点设定开始 / 结束。
- **I2 波形**：编辑时间时在输入框下方显示这一段的波形，可拖动开始 / 结束标记。

## 范围外

- 视频画面、整段进度条拖动、音量调节。
- 自动按静音或语音检测对齐时间（波形只做显示与手动拖动）。
- TODO 中的单句重新识别、整篇时间偏移、播放组件预热、记住转写音轨（各自另行处理）。
- AI 修订与一致性检查中的试听仍为单段播放，不加入连续跟读与打点。

### R-LISTEN-01 播放引擎：无缝连续、变速、循环

| 字段 | 值 |
| --- | --- |
| 来源 | 2026-10-11 用户“开始做TODO中的吧”；TODO「连续跟读」「慢放与单句循环」 |
| 状态 | active |
| 批次 | I1 |

#### 说明

- 单段播放保持现有行为（按钮、P、菜单、修订与一致性检查），改由 Web Audio 播放。
- 连续播放按 20 秒一段向主进程请求，当前段开始播放时预取下一段，按精确时间首尾相接，段与段之间听不出停顿；预取来不及时短暂显示加载，就绪后从断点继续。
- 速度 0.5× / 0.75× / 1×：由主进程用 FFmpeg `atempo` 处理，变慢但音高不变；播放位置按速度换算回原媒体时间。
- 循环：单段播放时反复播放这一段（含前后余量），直到再次按 P、点停止或开始其它播放。

#### 验收标准

- AC-LISTEN-01-1: 连续播放跨越 3 段（60 秒以上）时，相邻段首尾相接，播放位置连续递增、没有回退或超过 30 毫秒的空档（以调度时间记录验证）。
- AC-LISTEN-01-2: 0.75× 时，一条 2 秒的字幕片段播放约 2.67 秒，解码出的音频频率与 1× 相同（音高不变）；播放位置换算回原媒体时间，与 1× 时一致。
- AC-LISTEN-01-3: 开启循环后单段播放结束时自动从头再播，进度重新开始；停止后不再继续。
- AC-LISTEN-01-4: 已有的单段播放行为不变：悬停按钮、P、菜单、AI 修订和一致性检查中的播放，以及切换文档、关闭对话框时停止。

#### 边界与异常

- 连续播放请求越过媒体结尾（转写文档按媒体时长判断，字幕文档按主进程返回“没有音频”判断）时播放到结尾后自然结束。
- 连续播放中出现解码失败等原因时停止并显示原因，与单段播放一致。
- 测试中静音（`mute-audio` 同样作用于 Web Audio），播放时间照常推进。

### R-LISTEN-02 连续跟读

| 字段 | 值 |
| --- | --- |
| 来源 | TODO「连续跟读：从选中行一直播放下去，列表自动高亮并滚动到正在播放的那一句」 |
| 状态 | active |
| 批次 | I1 |

#### 说明

- `Shift+P` 或菜单“从这里连续播放”：从当前行开始时间（减前余量）一直播放到文档结尾。
- 正在播放的那一句（开始时间不晚于播放位置的最后一条）高亮，并在它变化时滚动到可见位置。
- 播放到当前页最后一条之后自动翻到下一页继续高亮。
- 再按 P 或 `Shift+P`、点高亮行的停止按钮，或开始其它播放时停止。

#### 验收标准

- AC-LISTEN-02-1: 在第 2 行按 `Shift+P`，高亮依次移到第 3、4 行……，与播放位置所在的字幕一致；高亮行不可见时自动滚动到可见。
- AC-LISTEN-02-2: 文档超过一页时，播放越过本页最后一条后自动显示下一页并继续高亮。
- AC-LISTEN-02-3: 连续播放中按 P 停止；切换文档、离开工作台时停止。

#### 边界与异常

- 连续跟读不改变选择；用户可以在播放中选择其它行（用于打点）。
- 用户在播放中手动翻页时不强行拉回，播放位置进入当前显示的页面时恢复高亮。

#### 说明

- AC-LISTEN-03-2: 连续播放中把速度从 1× 改为 0.5×，播放从当前位置继续，位置不回退超过 0.5 秒。

#### 边界与异常

- 速度只影响试听，不影响导出与时间计算。

### R-LISTEN-04 播放时打点设定开始 / 结束

| 字段 | 值 |
| --- | --- |
| 来源 | TODO「用播放位置打点改时间：播放时按 [ / ] 把当前播放位置设为这条字幕的开始 / 结束」 |
| 状态 | active |
| 批次 | I1 |

#### 说明

播放中（单段或连续）：

- `[`：把**当前行**（键盘焦点行；没有时取所选的第一条）的开始时间设为播放位置。
- `]`：把当前行的结束时间设为播放位置，并把当前行移到下一条，方便连续跟读时一句接一句地定时间。
- 播放位置扣除音频输出延迟，取整到毫秒；与手动改时间相同的检查（结束不早于开始、不越过相邻字幕、不超过媒体时长），不通过时在列表状态区说明原因且不修改。
- 每次打点都是一次可撤销的“修改时间”。

#### 验收标准

- AC-LISTEN-04-1: 连续播放中依次在第 3 行按 `[`、`]`，第 3 行的开始、结束变为按键时的播放位置（与引擎报告的位置相差不超过 50 毫秒），当前行移到第 4 行；Ctrl+Z 依次撤销。
- AC-LISTEN-04-2: 打点会使结束早于开始或越过相邻字幕时不修改，并在状态区显示与时间编辑相同的原因。
- AC-LISTEN-04-3: 没有在播放时按 `[` / `]`，状态区提示“播放时按 [ / ] 设定开始 / 结束”；翻译进行中等不能编辑时提示原因。
- AC-LISTEN-04-4: 菜单与帮助列出 `Shift+P`、`[`、`]`。

#### 边界与异常

- 慢放时位置同样按原媒体时间计算。
- 打点不会停止播放；页面因修改重新载入时连续播放继续。

### R-LISTEN-05 时间编辑框中的波形

| 字段 | 值 |
| --- | --- |
| 来源 | TODO「时间编辑框旁显示该段的小波形」 |
| 状态 | active |
| 批次 | I2 |

#### 说明

编辑一条字幕的时间（双击时间或按 T）且文档有可用媒体时，输入框下方显示“开始前 1.5 秒到结束后 1.5 秒”的波形，标出开始与结束位置；拖动标记即改写对应输入框（仍需 Enter 或离开保存），点击波形旁的播放按钮试听输入框当前的时间段。

#### 验收标准

- AC-LISTEN-05-1: 打开时间编辑后 1.5 秒内显示波形（含本次会话首次读取时约 1 秒的播放组件校验；预热见 TODO），开始 / 结束标记位置与输入框一致；有声段与静音段在波形上可区分（以测试音频的有声 / 静音区间验证峰值）。
- AC-LISTEN-05-2: 拖动结束标记后结束输入框随之变化（10 毫秒精度），Enter 保存，可撤销；拖到开始之前时按现有规则提示不能保存。
- AC-LISTEN-05-3: 没有可用媒体时不显示波形区域，编辑器尺寸与现在一致；786 宽与深色主题下不溢出列。

#### 边界与异常

- 结束时间未知时，波形显示到开始后 5 秒，结束标记可拖出以设定结束。
- 波形用于显示的数据只保存在内存中。
