# agent 需求

需求行为只在这里定义；L 的业务目标来源于 brd.md。不要在 tasks/record 另写一套期望。

## 目标与范围

让 FusionKit Agent 在对话中可靠地检索翻译资料，并以「变更卡片 → 用户确认 → 原子保存」的方式新建/修改/归档资料，复现并解决背景对话中「只能检索、不能记录」的问题。

## 范围外

删除资料、修改方案/风格；替用户在工作台翻译配置中选用资料集。

## 需求

### R-AGENT-01 资料检索与目录

| 字段 | 值 |
| --- | --- |
| 来源 | BR-01 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

`search_translation_knowledge` 支持多词查询（空白分隔，每个词都须命中任一字段），匹配字段扩展到条目所属对象的名称/别名、所属资料集的名称/说明、术语别名与备注；可按对象、语言对、状态筛选；资料集/方案结果附带语言对与条目数。新增只读 `list_translation_knowledge_catalog`，分页返回未归档对象、资料集（条目数、语言对、关联对象名）与方案。

#### 验收标准

- AC-AGENT-01-1: 在库中有别名为「ZZZ」的作品对象及关联它的资料集时，用「ZZZ」检索，结果包含该对象与资料集，以及其中条目。
- AC-AGENT-01-2: 在有译文「泰姆菲尔德家的大小姐」的术语时，用「泰姆菲尔德 大小姐」检索能命中；用「泰姆菲尔德 不存在」检索不命中。
- AC-AGENT-01-3: 在调用目录工具时，返回未归档对象与资料集，每个资料集含条目数、语言对、关联对象名；结果分页有界且不含证据摘录。

#### 边界与异常

资料服务不可用或读取失败时返回稳定错误码（沿用 `translation_knowledge_unavailable` / 服务错误码）。默认不返回归档内容。

### R-AGENT-02 准备资料变更

| 字段 | 值 |
| --- | --- |
| 来源 | BR-01 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

新增 `prepare_knowledge_changes`：Agent 提交对象/资料集新建、条目新建/修改/归档及每条依据与证据摘录；工具用 R-KNOWLEDGE-02 构造提案，可保存时注册一张资料变更卡片并返回 prepared；不可保存时返回逐项原因。任何执行模式下都不在卡片确认前写入。

#### 验收标准

- AC-AGENT-02-1: 在提交合法提案时，返回 `executionStatus: "prepared"`、卡片 id 与逐项摘要，资料库 generation 不变。
- AC-AGENT-02-2: 在执行模式为自动执行时提交合法提案，仍返回 prepared 且资料库不变。
- AC-AGENT-02-3: 在提案含 invalid 项时，返回失败 `knowledge_proposal_invalid` 与逐项原因，不注册卡片。
- AC-AGENT-02-4: 在全部条目已存在时，返回成功 `executionStatus: "unchanged"`，不注册卡片。

#### 边界与异常

会话切换或取消后不注册卡片（沿用现有会话检查）。同一会话就绪卡片数受现有上限约束；新提案准备时撤下本会话中尚未确认的旧资料卡片，避免同时存在两份互相矛盾的提案。

### R-AGENT-03 资料变更卡片与保存回执

| 字段 | 值 |
| --- | --- |
| 来源 | BR-01 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

卡片在首页与悬浮面板中显示：一句话摘要（新建/修改/归档数量与目标资料集）、逐项变更（类型、原文 → 译文或要求文本、所属资料集、冲突/跳过说明）、「保存后直接启用」开关（默认值依据 basis）、确认保存 / 不保存。确认后调用 `saveRecords` 原子保存；结果回报 Agent；完成后可一键打开对应资料集。

#### 验收标准

- AC-AGENT-03-1: 在确认且开关开启时，所有项在一次保存中写入，条目为 ready 并有 human 批准；开关关闭时条目为 candidate，出现在资料页「待审核」。
- AC-AGENT-03-2: 在准备后库被其他操作改动、致使修改项 revision 过期时确认，卡片显示失败与原因，库中没有本提案的任何记录；Agent 收到 action_failed 事件。
- AC-AGENT-03-3: 在点击「不保存」时，库不变，卡片显示已取消，Agent 收到 action_dismissed 事件。
- AC-AGENT-03-4: 在保存成功后点击「在翻译资料中查看」，进入资料页并选中目标资料集。
- AC-AGENT-03-5: 在 1280×860 与 786×660 的首页及悬浮面板、浅/深色、中英文下，包含 12 项与长文本（>80 字原文）的卡片自然换行、超过 6 项时折叠其余项，按钮可键盘操作。

#### 边界与异常

准备后库有无关改动（generation 变化但涉及记录未变）时，按最新库重新预检后照常保存。保存期间按钮禁用防重复提交；不确定结果按记录 id 对账，已存在则视为成功，不重复写入。

### R-AGENT-04 Agent 记录资料的行为指引

| 字段 | 值 |
| --- | --- |
| 来源 | BR-01 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

系统提示与工作台页面说明告诉 Agent：用户要求记住/记录/统一某个译法时，先查目录与检索；作品对应资料集存在则用之，不存在则在同一提案中新建作品对象与资料集；术语原文取自字幕原文（必要时先读/查字幕）或用户给出，不臆造；语言对取自文档与资料集；用户明确说出的译法用 user_stated；准备后让用户在卡片上确认，收到确认事件前不说已保存；保存后提醒翻译时在资料中选用该资料集。

#### 验收标准

- AC-AGENT-04-1: 在系统提示中包含上述资料维护指引，且工具列表包含 `list_translation_knowledge_catalog` 与 `prepare_knowledge_changes`。
- AC-AGENT-04-2: 在 Electron 中以脚本化模型复现背景对话（工作台打开文档 → 用户要求把译法记入《绝区零》资料），对话中出现资料变更卡片；点击确认后资料页可见新资料集与已启用术语，Agent 收到完成事件并回复。

#### 边界与异常

真实模型对指引的遵循程度不由自动化证明，交付说明中如实标注。

### R-AGENT-05 修订应用回报与跟进

| 字段 | 值 |
| --- | --- |
| 来源 | BR-02 |
| 状态 | active |
| 批次 | I2 |
| 优先级 | P1 |

#### 说明

Agent 发起的 AI 修订（`studio_prepare_revision`）结果附带可沉淀的译法摘要；用户在预览中应用后，FusionKit 以界面事件 `revision_applied` 回报应用条数与这些译法。有译法时 Agent 跟进询问一次是否记入资料，用户同意后以 basis user_revision 准备资料变更卡片；没有译法时不打扰。

#### 验收标准

- AC-AGENT-05-1: 在 Agent 打开的修订预览中模型返回可沉淀译法时，工具结果含 `knowledgeHints`（原文、译文，最多 5 条）。
- AC-AGENT-05-2: 在用户应用该修订后，Agent 收到 `revision_applied` 事件，事件文本含应用条数与译法；有译法时触发跟进，无译法时不触发跟进。
- AC-AGENT-05-3: 在系统提示中说明：收到带译法的 `revision_applied` 后询问一次，不重复追问；用户同意后使用 user_revision 并引用这些原文/译文。

#### 边界与异常

用户关闭预览未应用时不发送事件（沿用现状）。事件不授予任何权限。

### R-AGENT-06 Agent 发起一致性检查

| 字段 | 值 |
| --- | --- |
| 来源 | BR-03 |
| 状态 | active |
| 批次 | I3 |
| 优先级 | P1 |

#### 说明

在字幕工作台，用户说「检查一下人名是否统一」时，Agent 用页面工具 `studio_check_consistency` 打开一致性检查并开始检查当前文档（可带重点），等待结果后返回问题组摘要；统一由用户在检查窗口中确认，Agent 不写入。

#### 验收标准

- AC-AGENT-06-1: 在当前文档检查完成后，工具返回 `awaiting_user_review`、问题组数量与前 10 组摘要（原文、各写法与出处数、推荐写法），文档未被修改。
- AC-AGENT-06-2: 在没有打开文档、检查窗口已打开或文档没有字幕时，工具返回稳定错误码且不打开窗口。

#### 边界与异常

用户取消检查时返回 `consistency_cancelled`。

### R-AGENT-07 Agent 联网查证与带来源的资料

| 字段 | 值 |
| --- | --- |
| 来源 | BR-04 |
| 状态 | active |
| 批次 | I4 |
| 优先级 | P0 |

#### 说明

新增工具 `web_search`（来源、检索词、语言、B 站 Wiki 代号、`site:` 限定）与 `web_read`（读取链接正文）。未开启联网时返回 `web_lookup_disabled`，Agent 告诉用户在 设置 → Agent 中开启。系统提示规定来源优先级：一般先查维基百科；动画、游戏等二次元内容优先萌娘百科与百度百科，游戏专有名词可查 B 站游戏 Wiki（已配置时），官方译名用必应加 `site:` 查官网；先检索再读取最相关页面，以页面内容为准，不凭搜索摘要下结论。`prepare_knowledge_changes` 接受 basis `web` 与链接、标题、访问时间；联网得到的条目默认待审核，证据为网页来源；卡片注明来源网站。

#### 验收标准

- AC-AGENT-07-1: 在未开启联网时调用 `web_search` / `web_read`，返回 `web_lookup_disabled`，不调用主进程接口。
- AC-AGENT-07-2: 在开启联网时，`web_search` 返回有界结果（标题、链接、摘要、来源名称），`web_read` 返回有界正文与访问时间；关闭的来源返回 `web_source_disabled`。
- AC-AGENT-07-3: 在提交 basis 为 web 的条目时，保存后的证据为 web 来源（含链接、访问时间、标题），条目默认待审核；卡片行标出来源网站名。
- AC-AGENT-07-4: 在系统提示中包含联网来源优先级与“以页面内容为准、注明来源、默认待审核”的指引。

#### 边界与异常

单轮最多读取 5 个页面（提示约束）；正文按 8000 字截断，工具结果再按上下文预算压缩。basis 为 web 的条目必须指向本次运行中用 `web_read` 读过的页面链接（资料库要求网页来源带访问时间，也保证以页面内容为准），否则该行为 invalid，原因 `missing_url` / `page_not_read`，不出现卡片。未开启联网时，提示中只有一句说明（不出现来源指引）；Agent 可用 `open_app_page` 的 `agent_settings` 打开 设置 → Agent。

## 约束

新增工具的行名、摘要、卡片与错误文案同步四语言，并在 `AgentToolCall` / `AgentToolResult` / `action-error` 中注册。能力目录保持 7 项，只在「翻译资料」能力下追加 operations。不新增依赖、不调用付费 API。
