# knowledge 需求

需求行为只在这里定义；L 的业务目标来源于 brd.md。不要在 tasks/record 另写一套期望。

## 目标与范围

为 Agent 及后续的修订提示、一致性检查提供共用的资料写入基础：主进程原子批量保存、渲染进程可复用的提案构造与预检，以及翻译资料页的 Agent 页面上下文与定位入口。

## 范围外

不改动现有逐条录入入口（条目编辑器、批量粘贴、快捷记录）的行为；不新增删除/清除能力；不改变翻译时的资料解析规则。

## 需求

### R-KNOWLEDGE-01 原子批量保存

| 字段 | 值 |
| --- | --- |
| 来源 | BR-01 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

资料服务提供 `saveRecords`：一次请求携带当前 generation 与最多 200 项 `{ group, record, source?, adopt? }`，按顺序以与 `saveRecord` 相同的规则保存，整体只校验一次、只产生一个新 generation；任一项不合法则整批不写。渲染进程通过 `window.translationKnowledge.saveRecords` 调用，权限与现有资料通道相同。

#### 验收标准

- AC-KNOWLEDGE-01-1: 在空库下，提交「对象 + 引用该对象的资料集 + 引用该资料集并附证据且 adopt 的术语」三项，返回的快照 generation 恰好加 1，三项及证据都存在，术语为 ready 且有 human 批准。
- AC-KNOWLEDGE-01-2: 在批次中任一项不合法（如引用不存在的资料集、新记录 revision 不为 1、中文语言标签缺少文字）时，请求失败并返回带项序号路径的诊断，库的 generation 与内容不变。
- AC-KNOWLEDGE-01-3: 在 generation 已过期时提交，返回 `revision_conflict`，库不变。
- AC-KNOWLEDGE-01-4: 在一批保存成功后用新 generation 原样重放同一批，返回成功且 generation 不变（幂等）。
- AC-KNOWLEDGE-01-5: 在 IPC 层，超过 200 项、重复 id 或未注册的调用方被拒绝；通过 preload 的合法调用到达服务。

#### 边界与异常

同一批内不允许出现重复记录 id。`adopt` 只对条目有效；adopt 的条目若依赖已归档资料集则整批失败（沿用 `REVIEW_DEPENDENCY_ARCHIVED`）。修改已有记录时按记录 revision 检查，与 `saveRecord` 相同。

### R-KNOWLEDGE-02 资料变更提案构造与预检

| 字段 | 值 |
| --- | --- |
| 来源 | BR-01 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

提供纯函数 `buildKnowledgeProposal(input, snapshot)`：输入对象/资料集的新建、条目的新建/修改/归档（引用已有 id 或同一提案内的临时引用），以及每条的依据 basis 与证据摘录；输出逐项状态（new / update / archive / exists / invalid）、可读摘要、冲突警告，以及可直接提交 `saveRecords` 的请求（按「启用」与否两种形态）。依据与证据映射遵循 [总体设计·依据与可信度](../../architecture.md)。

#### 验收标准

- AC-KNOWLEDGE-02-1: 在库中没有《绝区零》对象时，提案「新建作品对象 + 新建资料集(引用该对象) + 术语(引用该资料集, basis=user_stated)」得到三项 new，术语证据为 user_note/direct，启用形态中术语 adopt=true、待审核形态中为 candidate。
- AC-KNOWLEDGE-02-2: 在资料集中已有同语言对、同原文、同译文且未归档的术语时，同样的术语项状态为 exists 且不进入保存请求；全部为 exists 时提案标记为无需保存。
- AC-KNOWLEDGE-02-3: 在库中其他资料集有同原文不同译文的术语时，新术语项附带冲突警告，指出对方资料集名与译文。
- AC-KNOWLEDGE-02-4: 在引用不存在的 id、临时引用未定义、`zh` 未写明 Hans/Hant、term 缺原文或译文时，对应项为 invalid 并给出稳定原因码，提案不可保存。
- AC-KNOWLEDGE-02-5: 在修改或归档条目时，修改项保留原 id 并以当前 revision 作为基准；basis 为 agent_inferred/document 的条目使用 ai_proposal/inferred 证据，且提案默认启用开关为关闭。
- AC-KNOWLEDGE-02-6: 在库中已有未归档的同类同名对象或同名资料集时，提案中对应的新对象/资料集复用已有记录（状态 exists），条目存入已有资料集，不产生重复记录。

#### 边界与异常

单个提案最多 5 个对象、5 个资料集、50 个条目。语言标签 `zh` / `zh-CN` / `zh-TW` 等常见写法规范化为 `zh-Hans` / `zh-Hant`，其他不合法标签为 invalid。证据摘录截断到 300 字。用同一组 id 重建提案时，库中已存在的这些 id 视为已保存（exists），用于对账结果不确定的保存。名称比较忽略首尾空白与大小写（NFC）。

### R-KNOWLEDGE-03 翻译资料页的 Agent 上下文与定位

| 字段 | 值 |
| --- | --- |
| 来源 | BR-01 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P1 |

#### 说明

用户在翻译资料页打开悬浮 Agent 时，Agent 能知道当前视图、所选资料集及可见条目，从而理解「把这几条改成……」。其他界面（变更卡片回执）可带着资料集/条目定位打开资料页。

#### 验收标准

- AC-KNOWLEDGE-03-1: 在资料页选中某资料集时，Agent 每轮获得的页面快照包含视图、资料集 id/名称/语言对/条目数，以及最多 20 条可见条目的 id、revision、类型、摘要与状态；批量选择时包含所选条目 id。
- AC-KNOWLEDGE-03-2: 在通过导航状态 `{ collectionId }` 打开资料页时，页面进入资料视图并选中该资料集；资料集不存在或已归档时停留在全部资料且不报错。

#### 边界与异常

快照受 6000 字符上限约束；不包含证据摘录与来源 URL。

### R-KNOWLEDGE-04 批量记入对话框

| 字段 | 值 |
| --- | --- |
| 来源 | BR-02, BR-03 |
| 状态 | active |
| 批次 | I2 |
| 优先级 | P0 |

#### 说明

可从工作台打开的对话框，一次记入多条译法：每行可勾选并编辑原文与译文，显示「已存在」或「与某资料集译法不同」；选择已有资料集或新建资料集，设置语言对；「保存后直接启用」默认开启（内容来自用户亲自应用的修订）；保存走提案构造与 `saveRecords` 原子保存，成功后提示并广播资料变更。

#### 验收标准

- AC-KNOWLEDGE-04-1: 在预填 2 条译法并选择已有资料集时，点击保存，两条术语一次写入该资料集，状态为启用（human 批准），证据为「已应用的修订」用户约定。
- AC-KNOWLEDGE-04-2: 在某行与资料集中已有同译法条目相同时，该行标为已存在且默认不勾选；在其他资料集有不同译法时显示冲突说明。
- AC-KNOWLEDGE-04-3: 在选择「新建资料集」并输入名称时，保存同时创建资料集与条目；名称为空、没有勾选行、原文或译文为空、语言未选时保存按钮不可用。
- AC-KNOWLEDGE-04-4: 在保存失败（如资料已被改动）时，对话框保留输入并显示错误，库中没有本次的任何记录。

#### 边界与异常

最多 50 行。关闭开关时条目存为待审核。保存期间禁用表单与按钮，防重复提交。

## 约束

界面文案同步 zh / en / ja / zh-Hant 并运行 `pnpm run i18n:check`。不新增依赖。主进程契约以 `src/translation-knowledge/ipc-contract.ts` 为准。
