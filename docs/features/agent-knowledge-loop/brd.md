# Agent 与翻译资料闭环：业务范围与路线图

## 背景

2026-10-10 用户测试 FusionKit Agent 时的一段对话（节选）：

> 用户：有些翻译不太合适，应该是泰姆菲尔德家的大小姐
> Agent：查找字幕 → 准备 AI 修订（检查 6 条，建议修改 4 条），请在预览中确认。
> 用户：能否把这个词汇记录到一个属于绝区零的翻译资料中
> Agent：搜索翻译资料（本页资料：0 条条目 · 0 个资料集 · 0 个方案）→ 打开「翻译资料」页。「我这边的翻译资料工具只有检索权限，不能直接写入条目……需要你新建一个。」

暴露的问题（均已在代码中核实，见 [总体设计](architecture.md) 的现状盘点）：

1. **Agent 只能检索、不能维护资料。** 唯一的资料工具 `search_translation_knowledge` 只读；前一轮 HomeAgent 升级刻意把写入排除在范围外（`docs/features/home-agent-upgrade/architecture.md`「不自动采纳/删除」）。用户只能离开对话、自己去资料页手工录入。
2. **检索太弱，找不到「属于绝区零」的资料。** 只对条目标题/摘要和资料集名称做单个子串匹配；对象（作品）名称与别名、资料集说明、术语别名都不参与，多词查询必然落空。
3. **修订与资料是两条断开的线。** AI 修订不读取翻译资料，也从不提示「这条译法值得记下来」；用户修正了一次的专有名词，下次翻译还会错。
4. **缺少整体视角的检查。** 同一人名/术语在一个或多个文档里出现几种写法（例：「泰姆菲尔德」「时间菲尔德」），目前只能靠用户逐条发现、逐条修订。
5. **没有联网查证。** 应用内无任何网页检索能力；为作品补充人名、地名等资料只能借助外部工具制作 `.fktk.json` 包再导入。

## 目标

让翻译资料「越用越丰富、越用越准」，并且这件事可以完全在对话和字幕工作台内完成：

- 用户用一句话就能让 Agent 记录、修改、整理资料；Agent 提出变更，用户在卡片上核对后保存。
- 用户每次修订字幕时，应用能识别出值得沉淀的译法，主动、克制地询问是否记入资料。
- 用户可以一键检查文档中的写法不统一，确认后批量修正，并把统一后的写法沉淀为资料。
- 需要时 Agent 可以联网查证，资料附带来源，默认待审核。

## 原则（跨批次不变）

| 原则 | 含义 |
| --- | --- |
| 提议—确认—保存 | Agent 与 AI 只提出变更；写入资料库前必须由用户在可信界面（卡片/对话框）核对确认。任何执行模式（含自动执行）都不自动写入。 |
| 区分「用户说的」和「AI 猜的」 | 用户明确给出的译法记为 `user_note` 证据，可直接启用；AI 推断或联网得到的内容记为 `ai_proposal` / `web` 证据，默认存为待审核。不把 AI 建议伪装成已采纳。 |
| 原子、可解释 | 一次确认的多条变更要么全部保存、要么全部不保存；冲突、重复、需审核的原因在确认前可见。 |
| 克制的主动性 | 只在有把握时提示（专有名词、反复出现的术语、用户明确表达的约定）；一次修订最多提示一次，可忽略，不打断主流程。 |
| 不扩权 | 不删除/清除资料（只允许可恢复的归档），不全量发送私有资料库给模型，联网需用户开启且只发送查询词。 |

## 范围外

- 永久删除（purge）资料、修改资料导入历史、跨设备同步。
- 自动学习：没有用户确认的后台积累（协议里的 `learningSuggestion` 仍不执行）。
- 经典字幕翻译器接入翻译资料（现状：仅字幕工作台使用资料）。
- 表达（expression）与参考译文（memory）的执行；Agent 写入只覆盖会参与翻译的 term / rule / context。

## 路线图

| 批次 | 交付 | 依赖 |
| --- | --- | --- |
| I1 | Agent 检索与维护资料：更强的检索与目录、资料变更提案卡片、原子批量保存、资料页上下文 | 无 |
| I2 | 修订 ↔ 资料：AI 修订参考已选资料；修订后识别可沉淀译法，在工作台与对话中询问并批量记入 | I1 的批量保存与提案构造 |
| I3 | 术语一致性检查：单/多文档写法不统一检查，确认后批量统一并可记入资料 | I1、I2 的记入对话框 |
| I4 | 联网查证：可配置的资料站/搜索来源，读取网页摘要，资料附来源并默认待审核 | I1；Q-01 来源选型 |

每批都交付一条可演示的用户链路；后续批次在进入实施前细化模块需求与任务。

### BR-01 在对话中检索与维护翻译资料

| 字段 | 值 |
| --- | --- |
| 状态 | active |
| 批次 | I1 |

#### 说明

用户在任意页面对 Agent 说「把这个词记到绝区零的资料里」「把选中的几条改成必须使用」「建一个《绝区零》的资料集」，Agent 能找到合适的对象与资料集（找不到时提议新建），从字幕/对话中取得原文与译法，生成一张资料变更卡片；用户确认后原子保存，Agent 收到结果并简短回报。检索覆盖作品名、别名、资料集说明与术语别名。

#### 验收要点

复现背景对话：在字幕工作台修订后要求记录术语，一轮对话内出现变更卡片（新建《绝区零》对象/资料集 + 术语），确认后资料库中可见并可在翻译时选用；拒绝或失败时不写入任何内容。

### BR-02 修订后沉淀译法

| 字段 | 值 |
| --- | --- |
| 状态 | active |
| 批次 | I2 |

#### 说明

AI 修订使用当前文档已选的翻译资料作为约束；修订模型同时识别「可复用的译法约定」（专有名词、称谓、反复出现的术语）。用户应用修订后，工作台提示「发现 N 条可记入翻译资料的译法」，打开批量记入对话框选择资料集保存；若修订由 Agent 发起，Agent 在对话中跟进询问并给出变更卡片。

#### 验收要点

修订统一了人名后出现一次提示；已存在的同译法不重复提示；忽略后不再追问；保存走与 I1 相同的原子保存与证据规则。

### BR-03 术语一致性检查

| 字段 | 值 |
| --- | --- |
| 状态 | active |
| 批次 | I3 |

#### 说明

在字幕工作台对当前文档或多个文档发起「一致性检查」：找出同一原文对应多种译法、疑似同一名称的不同写法（含听写错误），以及未按已启用资料翻译的位置。结果按问题分组，用户为每组选定标准写法后批量修正（可撤销），并可把标准写法记入资料。Agent 也可发起检查并汇报。

#### 验收要点

含「泰姆菲尔德/时间菲尔德」两种写法的文档检查后出现一组问题、给出推荐写法与出处；确认后所有出处统一且可撤销；选择记入时生成资料。

### BR-04 联网查证资料

| 字段 | 值 |
| --- | --- |
| 状态 | active |
| 批次 | I4 |

#### 说明

用户开启联网后，Agent 可查询资料站或搜索服务、读取网页正文摘要，用于确认作品中的人名、地名、术语译法，并把来源（标题、链接、访问时间）作为证据写入提案；联网得到的条目默认待审核。

#### 验收要点

关闭联网时 Agent 说明需要开启而不发请求；开启后查询结果附来源，生成的条目为待审核且证据为 web；不发送资料库或字幕全文。
