# revision 需求

需求行为只在这里定义；L 的业务目标来源于 brd.md。

## 目标与范围

应用检测相邻重复并提出合并；AI 修订可提出合并与删除；Agent 能准备合并、删除、改时间或请 AI 修订找重复。全部在修订预览中确认。

## 范围外

模型给出的时间；拆分。

## 需求

### R-REVISION-01 相邻重复检测

| 字段 | 值 |
| --- | --- |
| 来源 | BR-03 |
| 状态 | active |
| 批次 | I3 |
| 优先级 | P0 |

#### 说明

不调用模型，在所选字幕或整篇中找出相邻重复：相邻两条原文规范化（NFKC、去空白与标点、小写）后相同，或一条包含另一条且较短者不少于较长者的 50%；连续多条重复合为一组。AI 修订对话框提供「检查相邻重复」，结果作为合并建议显示在修订预览中（合并后的原文、译文、时间范围），可逐条取消；应用为一次编辑。

#### 验收标准

- AC-REVISION-01-1: 在双语识别后的用户样本中检查整篇，结果包含一处合并建议：00:00:26.780 起的两条，合并后原文「先輩みたいに朝から眠そうにしてる方、」、译文「像前辈这样一大早就犯困的，」。
- AC-REVISION-01-2: 在取消某条建议后应用，只合并仍勾选的组；撤销一次恢复全部。
- AC-REVISION-01-3: 在没有相邻重复时，预览说明“没有发现相邻重复”，不做任何修改。

#### 边界与异常

只在同一页（≤100 条）或一次检查的字幕范围内比较；间隔 >10 秒的相邻字幕不视为重复识别。

### R-REVISION-02 AI 修订提出合并与删除

| 字段 | 值 |
| --- | --- |
| 来源 | BR-03 |
| 状态 | active |
| 批次 | I3 |
| 优先级 | P0 |

#### 说明

AI 修订的模型在用户请求涉及时，除改字外还可返回：合并（同一请求内相邻的条目，附合并后的原文与可改的译文）与删除（无意义的识别结果，如纯噪声、重复的片尾语）。应用校验：合并条目必须相邻且在同一块；删除不得清空文档；时间由应用按合并规则计算。预览中合并与删除各成一行，与改字同样可勾选；应用为一次编辑。

#### 验收标准

- AC-REVISION-02-1: 在请求「合并重复识别的句子」且模型返回合并 c3、c4 时，预览显示一行合并（两条原文、合并结果与时间范围），应用后为一条。
- AC-REVISION-02-2: 在模型返回不相邻的合并、不存在的条目、或会删除全部条目的删除时，这些建议被丢弃并计入“未采用”。
- AC-REVISION-02-3: 在请求只改文字时，提示词不鼓励合并/删除，结果与现状相同。

#### 边界与异常

跨块（每块 40 条）的相邻条目不能合并；单次修订最多 200 处合并、200 处删除。

### R-REVISION-03 Agent 准备结构修复

| 字段 | 值 |
| --- | --- |
| 来源 | BR-03 |
| 状态 | active |
| 批次 | I3 |
| 优先级 | P0 |

#### 说明

Agent 的字幕工作台工具可：(a) `studio_prepare_cue_edits` 按用户的明确说法准备结构修改（合并第 N–M 条、删除第 N 条、把第 N 条的开始/结束改为某时间），不调用模型，直接在修订预览中显示；(b) `studio_find_duplicates` 检查相邻重复；(c) 照旧用 `studio_prepare_revision`（其提示已允许合并与删除）。用户在预览中应用后，Agent 收到结果事件（含合并、删除、改时间的数量）：没有需要回应的内容时不自动发言，事件记入对话，Agent 在下一轮看到。

#### 验收标准

- AC-REVISION-03-1: 在用户说“把第 19、20 条合并”时，Agent 调用工具后修订预览显示该合并，应用后为一条；Agent 不声称已修改，直到收到应用事件。
- AC-REVISION-03-2: 在用户说“找出所有重复识别的片段并合并”时，Agent 调用相邻重复检查，预览显示建议；没有时返回无结果。
- AC-REVISION-03-3: 在 Agent 给出不连续的合并、越界序号或非法时间时，工具返回稳定错误码，不打开预览。

#### 边界与异常

序号按文档中的字幕编号（从 1 起）；一次最多 200 处修改。

## 约束

不新增依赖；文案四语言；AI 修订真实模型的遵循度需用户试用验证。
