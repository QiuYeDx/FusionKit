# import 需求

需求行为只在这里定义；L 的业务目标来源于 brd.md。不要在 tasks/record 另写一套期望。

## 目标与范围

导入文本字幕时，若现有双语识别判定为推荐，直接以原文 + 导入译文的形式建立文档，适用于所有导入入口；并提供恢复原样导入。

## 范围外

已编辑文档的事后识别；新的识别算法（沿用 `bilingual.ts` 的配对、语言判断与推荐阈值）。

## 需求

### R-IMPORT-01 导入时自动识别双语

| 字段 | 值 |
| --- | --- |
| 来源 | BR-01 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

主进程在创建文档前分析导入结果：`isBilingualRecommended` 为真时按「原文一侧」规则应用现有的双语拆分（`applyBilingual`，不拆同行文本），文档创建时即带导入译文轨道（`origin: imported`，未审阅）。原文一侧：两种语言中恰有一种是中文时，中文一侧作为译文；否则第一行一侧为原文。导入结果与文档标题区显示已识别的语言方向与配对数，以及需核对的配对数。

#### 验收标准

- AC-IMPORT-01-1: 在导入与用户样本同结构的双语 LRC（151 个时间戳，每个下一行日文、一行中文）时，文档为 151 条字幕，原文为日文，译文轨道为中文且来自导入；文档标题区显示「已识别为双语：日语 → 中文」，不弹出对话框。
- AC-IMPORT-01-2: 在一次导入多个文件、或由 Agent 按路径导入时，双语文件同样被识别，单语文件不受影响。
- AC-IMPORT-01-3: 在导入中文在前、日文在后的双语文件时，原文为日文、译文为中文。
- AC-IMPORT-01-4: 在导入不满足推荐条件的文件（配对少于 3 对或不足 80%、单语文件）时，文档与现状相同（全部为原文），「双语整理」按钮按现有规则可用。

#### 边界与异常

识别失败（异常）时按原样导入，不影响导入结果。转写文档、带不可翻译内容的文档（`capabilities.translate = false`）不识别。

### R-IMPORT-02 恢复原样导入

| 字段 | 值 |
| --- | --- |
| 来源 | BR-01 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

已识别为双语、且识别后没有编辑过的文档，提供「按原样导入」：用原始文件内容重新建立为单语文档（全部为原文），作为一次文档变更（版本递增）。适用于自动识别与手动「双语整理」的结果。

#### 验收标准

- AC-IMPORT-02-1: 在自动识别后点击「按原样导入」，文档恢复为 302 条原文、无译文轨道；「双语整理」按钮重新可用。
- AC-IMPORT-02-2: 在识别后已编辑原文、译文、时间、删除字幕或运行过翻译任务时，「按原样导入」不可用并说明原因；主进程也拒绝该请求（`revision_conflict`）。

#### 边界与异常

不改动来源文件；文档 id 不变；工作台撤销历史在文档被重建后清空（沿用版本跳变时的现有行为）。
