# 翻译资料 v2：概念收敛与彻底重构

2026-10-12，基线 `473d58e`（分支 v0.4.0）。

起因：用户评审翻译资料模块，认为「方案与风格（翻译方案 / 翻译风格 / 偏好模板）、内容对象、全部资料、资料页里的固定译法 / 背景说明 / 翻译要求，加上各自复杂的表单」层次多、乱、难理解，使用与维护成本都高。对照代码核实后确认：页面几乎把 FK-TK/1 存储协议（7 类实体、5 种条目、6 种状态）原样暴露给用户，其中风格、偏好模板、方案的一半字段、表达习惯 / 参考译文并不参与翻译，内容对象的说话人范围在整篇翻译里基本不生效。

用户决定（2026-10-12）：

1. 审核流程不保留；
2. 翻译方案「并入资料集」与「工作台预设」两者都做；
3. 内容对象（含说话人 / 适用范围）删除；

随后补充：历史数据（非正式版）直接作废，不引入任何兼容旧数据的逻辑，旧资料移入待处理归档文件夹，日后用 AI Agent 按新规范重建。

并要求「治根，不要只治表面」：数据结构一起重构，所有受影响的地方逐一梳理改造，不能漏改；先写文档，再开发。
