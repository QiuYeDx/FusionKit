# 长文本翻译（重写）需求

设计见 [design.md](design.md)，任务见 [tasks.md](tasks.md)。

## 目标与范围

旧的长文本翻译工具实现质量差（项目模式与语义记忆让状态复杂、黑盒运行、无法逐段核对），整体删除，**不作参考**。重新设计并实现一个新的长文本翻译工具：

- 拖入 TXT / Markdown 或粘贴文本后，文档立即以“原文 | 译文”逐段对齐打开。
- 先试译一小段，再一键翻译全文；可暂停、可在应用重启后继续；API 密钥不落盘。
- 边读边改：行内编辑、带要求的单段重译、锁定、撤销、需关注跳转与查找。
- 译名一致：模型自动记录的译名表（可确认、可编辑、可保存到翻译资料）与翻译资料注入。
- Markdown 保真；导出仅译文或双语，绝不覆盖已有文件。
- 界面与字幕工作台（Studio）是同级页面，遵守 FusionKit 视觉契约，四种界面语言齐全，中文为主。

来源：2026-10-22 用户：“把现有的长文本翻译工具完全删除（实现得很差，不要参考），清理代码，然后重新设计并实现一个全新的：功能要好用，交互自然友好，界面布局美观并与 FusionKit 风格一致，由你来设计。”

**固定约束**（来自工作流，不再讨论）：保留路由 `/tools/text/translator`、ToolKey `textTranslator`、菜单键 `menu.text.translator`、Agent 页面键 `text_translator` 与 i18n 命名空间 `text`；本轮工具仍在实验区，不改 `AGENT_CAPABILITIES`；新代码放在 `src/long-text/`、`electron/main/long-text/`、`electron/preload/long-text-*.ts`、`src/pages/Tools/Text/LongTextTranslator/`、`src/store/tools/text/useLongTextStore.ts`；用户数据根 `<userData>/long-text/`；模型调用经 `sendModelRuntimeText`；不新增 npm 依赖；不改 Studio 目录、`electron/main/ai/*`、`electron/main/local-subtitle/*`、`studio.json`；`electron/main/index.ts` 与 `electron/preload/index.ts` 只做最小修改。

## 范围外

- DOCX、EPUB、PDF、HTML、RTF 输入；字幕文件只做拒绝与引导。
- 流式输出；跨文件“书籍项目”；运行摘要 / 语义记忆；翻译 → 反思 → 改进；多候选与多引擎对比；替换功能。
- 应用内 Agent 的准备动作与外部 MCP 工具（可选的只读页面上下文除外，见 R-LT-21）。
- 按原编码导出、自动保留期清理、磁盘空间预检、自定义目标语言。
- 修改 `package.json` / `pnpm-lock.yaml`。

## 后续（明确推迟）

- 多选与选区栏（批量重译、锁定、复制）。
- 交替排列、字号选项、快捷键对话框。
- 从其他文档导入译名表；`QuickTermDialog` 快捷术语入口。
- 运行摘要记忆、全文一致性检查、资料术语冲突提示。
- Agent 准备动作与外部 MCP 读工具（需移入 `AGENT_CAPABILITIES`，另起规格）。

### R-LT-02 导入文件

| 字段 | 值 |
| --- | --- |
| 来源 | 设计 §1.2-1、§2 F2 |
| 状态 | active |
| 批次 | I1 |

#### 说明

- 支持 `.txt`、`.md`、`.markdown`，拖放到页面任意位置或主进程原生选择框；可多选，每个文件一篇文档。
- 解析、分段、存储都在主进程；渲染端按页拉取。

#### 验收标准

- AC-LT-02-1: 在选择框中选中 2 个文件后，文档列表新增 2 行，第一篇新文档成为当前文档，列表按最近更新排序，读屏区播报“已导入 2 篇文档”。
- AC-LT-02-2: 拖入文件时出现整页覆盖层“松开以导入到长文本翻译”；页面上可见的 `[data-tool-file-drop-target]` 恰好 1 个；`test/tool-file-drop.electron.test.ts` 的 `text/translator` 用例通过（与 HEAD 基线比较）。
- AC-LT-02-3: 同批导入 `a.docx`、`ep01.srt`、11 MiB 的 `big.txt`、空的 `empty.txt`、含 NUL 的 `data.txt` 与一个合法 `ok.md` 时，只有 `ok.md` 成为文档；提示条列出前 3 个被拒文件及原因（“等 n 个”），其中字幕文件附“打开字幕工作台”按钮并导航到 `/tools/subtitle/studio`。
- AC-LT-02-4: 再次导入同一路径且内容 sha256 未变的文件时不新建文档，激活已有文档并提示“已在列表中”。
- AC-LT-02-5: 合成的 5 MB UTF-8 中文 TXT 与 5 MB Markdown 在主进程各自导入完成 < 5 s，期间 `monitorEventLoopDelay` 最大值 < 250 ms；任何一次 `readPage` 返回的行数 ≤ 60。

#### 边界与异常

- 单次最多 50 个路径；文档库最多 200 篇（超出 `limit_exceeded`）；单篇最多 200,000 段（超出 `too_many_segments`）；超过 5 MiB 提示“较大，打开可能需要几秒”。
- 拖放路径在拖放事件中同步捕获；路径必须是绝对路径、普通文件、非符号链接。

### R-LT-04 编码识别与更换

| 字段 | 值 |
| --- | --- |
| 来源 | 设计 §6.2 |
| 状态 | active |
| 批次 | I1 |

#### 说明

- 只用 iconv-lite：BOM → 无 BOM UTF-16 → 严格 UTF-8 → 候选打分（有效性门槛、Big5/GBK 尾字节启发、假名 / 谚文加分、常用字分）。
- 把握低时拦截试译与翻译，直到用户点一次“编码正确”或换编码；换编码有前 8 行预览，原始字节保留在 `original.bin`。

#### 验收标准

- AC-LT-04-1: 用 `iconv.encode` 生成的 ≥ 2 KB 自然文本样本中，gb18030、big5、shift_jis、euc-jp、euc-kr、windows-1252 都被识别为对应编码且置信度 high；三种 BOM 与无 BOM 的 UTF-16 LE / BE 识别正确；Big5 繁体样本不被识别为 GB18030。
- AC-LT-04-2: 置信度 low 的文档显示编码提示条；此时点“试译”或主按钮不发出任何模型请求（假服务请求数不变），并返回 `encoding_unconfirmed`；点“编码正确”一次后提示条消失，重启应用后不再出现。
- AC-LT-04-3: 编码对话框选择另一种编码时显示该编码解码的前 8 个非空行（源文件已删除时仍能预览）；有译文时按钮为“清除译文并重新打开”，确认后段落重新生成、译文清空、编码标为已确认。
- AC-LT-04-4: 元信息行显示编码名（如“GB18030”）。

#### 边界与异常

- 没有候选通过有效性门槛时仍导入（low），由编码门槛拦截翻译；含 NUL 或控制字符超过 1% → `binary_file`；UTF-32 BOM → `binary_file`。

### R-LT-05 分段与分页

| 字段 | 值 |
| --- | --- |
| 来源 | 设计 §6.3–6.5 |
| 状态 | active |
| 批次 | I1 |

#### 说明

- TXT：自动判定“每行一段”或“合并折行”，可在高级设置手动覆盖；章节标题与分隔行识别；超长段按句末拆分。
- Markdown：自写逐行块扫描；代码、front matter、HTML、数学、分隔线为原样块；标题、段落、列表项、引用、表格行、脚注为可翻译段。
- 分页：每页最多 60 段或约 8,000 Token，优先在章节标题处断开。

#### 验收标准

- AC-LT-05-1: 每行以全角空格缩进的中文小说 TXT 中，每个非空行是一段，缩进留在段区间外，导出仅译文时每行缩进保持不变。
- AC-LT-05-2: 古腾堡式硬折行英文（行宽约 70、段间空行）自动识别为“合并折行”，一个空行分隔的段落是一段；分节的诗歌不被合并。
- AC-LT-05-3: “第十二章　夜”“Chapter IV”“序章”被识别为章节标题；`***` 与 `◇◇◇` 为原样块。
- AC-LT-05-4: Markdown 夹具中围栏代码（含列表内与引用内）、front matter、HTML 块、数学块、链接引用定义不产生可翻译段；表格的表头行与每个表体行各为一段；任务项显示 ☐ / ☑。
- AC-LT-05-5: 所有分段夹具满足：(a) 没有译文时重建结果与原文逐字节相同（含混合 CRLF 与单独 CR）；(b) 段区间有序、不重叠、与原样块不相交；(c) 每段显示文本经投影再还原后与自身相同。
- AC-LT-05-6: 页最多 60 段、可翻译段 Token 估算和 ≤ 8,000；遇章节标题且当前页已有 ≥ 8 个可翻译段时换页；页标题为页内第一个标题。
- AC-LT-05-7: 估算超过 1,200 Token 的段被拆成每块 ≤ 900 Token 的段并共享组号；双语导出时整组原文之后跟整组译文。
- AC-LT-05-8: 高级设置把段落识别改为“每行一段”时，若已有译文，先显示“需要清除全部译文”的警告，确认后重新分段。

#### 边界与异常

- 行内记号超过 200 个的段、只有无 alt 图片的段改为原样块；拿不准的结构归为原样块。

### R-LT-09 全文翻译、节奏与进度

| 字段 | 值 |
| --- | --- |
| 来源 | 设计 §2 F5、F6，§6.8，§6.9.3 |
| 状态 | active |
| 批次 | I1 |

#### 说明

- 主按钮随状态变化：翻译全文 / 继续翻译 / 重试失败的 n 段 / 导出… / 暂停 / 正在暂停…。
- 以页为单位分路：每路一次一页、页内按顺序并携带前文；节奏 1 / 2 / 4 路；全局最多 6 个模型请求在途。

- AC-LT-09-6: 离开页面后翻译继续；返回时进度为最新；离开时出现提示“长文本翻译仍在后台进行”。
- AC-LT-09-7: 收到 429 时有效路数减 1，状态行显示“服务限流，已降至 n 路”；连续 20 次成功后恢复 1 路，不超过设定节奏。

#### 边界与异常

### R-LT-11 失败处理

- AC-LT-11-5: 翻译资料不可读、已归档或语言方向不符时，开始被拒并提示，提供“打开设置”。
- AC-LT-11-6: 写盘失败（模拟 ENOSPC）时运行停止并提示“无法保存译文：磁盘空间不足或没有写入权限”。
