# 列表内查找替换 需求

## 目标与范围

人工校对时需要在整篇字幕中找一个词（人名、误写、术语），逐个查看并改正。目前只有 Agent 能按文字查找字幕，字幕预览没有搜索框。本次在字幕预览中加入**查找与替换**：Ctrl+F 打开查找栏，在整篇（所有页）的原文、译文中查找，逐条跳转并高亮，可逐条替换或全部替换，替换可撤销。

对应 `docs/TODO.md`「字幕工作台：编辑与校对 → 列表内查找替换（Ctrl+F）」。

来源：2026-10-11 用户：“你上面说的这些建议都挺好的，可以记录到一个TODO文档，然后再逐一处理”；随后“跑完后提交并推送，然后继续下一项”。

## I2：正则表达式与整词匹配（2026-10-14）

字面查找无法处理“所有以‘先生’结尾的称呼”“把 `(\d+)年` 改成 `$1 年`”或“只找单词 cat、不找 category”这类校对需求。I2 在查找栏加入**正则表达式**与**全词匹配**两个开关，查找、高亮、逐条替换与全部替换都遵循它们，替换支持引用捕获组；整篇查找不会因恶意或低效的表达式卡住应用。

来源：2026-10-14 用户在 v0.5.0 回顾后选定“查找替换支持正则和整词匹配：现在只能按字面查找”，要求先写文档再开发（`docs/TODO.md`「v0.5.0 后续」）。

I2 范围外：模糊匹配；跨字幕（跨行）的匹配；Agent 工具使用正则（内置 Agent 的近似查找不变）。

## 范围外

- 正则表达式、整词匹配（I1 范围外；I2 加入，见 R-FIND-04、R-FIND-05）与模糊匹配（Agent 的近似查找仍在 AI 修订中）。
- 跨文档查找。

| 批次 | I1 |

#### 说明

- 编辑操作“替换”：在指定字幕（或全部匹配字幕）的原文和 / 或当前译文轨译文中，把查找词的每一处替换为替换词（可为空）。原文替换与编辑原文相同（对应译文标为原文已变更）；译文替换与编辑译文相同（成为人工译文）。
- 格式：匹配处在同一格式片段内时保留格式；跨越格式片段时按整行替换（与行内编辑相同，局部格式会移除）。
- 替换后为空、或替换词含 `<` `>` 等不能保存的字符时拒绝，文档不变。一次最多替换 1000 条字幕。
- 撤销恢复替换前的原文与译文（一次撤销）。

#### 验收标准

- AC-FIND-02-1: “全部替换”把 3 条中的 4 处“法尔童”替换为“法厄同”，含不在当前页的字幕；撤销后全部恢复。
- AC-FIND-02-2: “替换”只替换当前一条中的所有匹配处，并跳到下一条匹配。
- AC-FIND-02-3: 替换后为空或替换词含 `<` 时拒绝且文档不变；斜体整行的字幕替换后仍为斜体。

#### 边界与异常

- 翻译进行中拒绝（与其他编辑相同）。

### R-FIND-03 查找栏

| 字段 | 值 |
| --- | --- |
| 来源 | TODO「列表内查找替换（Ctrl+F）」 |
| 状态 | active |
| 批次 | I1 |

#### 说明

- 在字幕列表中按 Ctrl+F（或点列表上方的查找按钮）打开查找栏，焦点进入查找框；已选中的单条字幕中选中的文字作为初始查找词（如有）。
- 查找栏：查找框、匹配计数（“第 3 / 17 条 · 共 21 处”，无匹配时“无匹配”）、上一条 / 下一条（Shift+Enter / Enter）、范围（原文 / 译文 / 全部，有译文轨时）、区分大小写开关、展开替换（替换框、“替换”“全部替换”）、关闭（Esc）。
- 跳转：转到匹配字幕所在页，选中并滚动到该行；当前页中所有匹配处高亮，当前条更醒目。
- 文档改变（编辑、撤销、替换）后自动重新查找；关闭查找栏后清除高亮并回到列表。

#### 验收标准

- AC-FIND-03-1: Ctrl+F 输入“法尔童”，显示“第 1 / 3 条 · 共 4 处”，第 3 条被选中并高亮；Enter 跳到第 120 条（翻到第 2 页），Shift+Enter 回到第 3 条。
- AC-FIND-03-2: 展开替换输入“法厄同”点“全部替换”，计数变为“无匹配”，撤销后又找到 3 条。
- AC-FIND-03-3: Esc 关闭查找栏，高亮消失，焦点回到列表。
- AC-FIND-03-4: 1280×860 浅色与 786×660 深色下查找栏不溢出，按钮可用。

#### 边界与异常

- 翻译进行中替换按钮禁用并说明；查找仍可用。

### R-FIND-04 正则表达式与全词匹配

| 字段 | 值 |
| --- | --- |
| 来源 | 2026-10-14 用户：“查找替换支持正则和整词匹配” |
| 状态 | active |
| 批次 | I2 |

#### 说明

- 查找与替换各增加两个选项（可组合，也可与区分大小写组合）：
  - **正则表达式**：查找词按 JavaScript 正则表达式（Unicode 模式）解释；`^` `$` 匹配每一行的开头与结尾；只在一条字幕的一个字段内匹配，不跨字幕。空匹配（如 `a*` 在没有 a 处）不计入、不高亮、不替换。替换词中 `$1`…`$99`、`$<名称>` 引用捕获组，`$&` 为整个匹配，`$$` 为字面 `$`；未开启正则时替换词中的 `$` 一律按字面处理（与 I1 相同）。
  - **全词匹配**：匹配处两端不能紧挨着字母、数字或下划线（任何文字的字母都算，如 café、Привет）；但匹配处一端的字符是汉字、平假名、片假名或泰文时，该端不受此限制（这些文字不用空格分词，避免“全词”让中日文查找失效）。
- 正则无效时不查找，在查找栏说明“正则表达式无效”；替换操作同样拒绝（`invalid_pattern`），文档不变。
- 替换后的文字（展开捕获组之后）仍按 I1 的规则检查：为空或含 `<` `>` 等不能保存的字符时拒绝，文档不变。
- 查找与全部替换在整篇上执行正则的总时间超过 3 秒时停止并说明“表达式过于复杂”（`pattern_too_slow`），应用不卡顿、文档不变。

#### 验收标准

- AC-FIND-04-1: 正则 `\d+年` 在“1999年”“二〇〇〇年”“2001 年”中只匹配第一处；替换为 `$&份` 得到“1999年份”；`(\d+)年` 替换为 `$1 年` 得到“1999 年”；未开启正则时替换词 `$1` 原样写入。
- AC-FIND-04-2: 全词匹配查找 “cat” 匹配 “a cat.”、不匹配 “category”“bobcat”；查找 “café” 匹配 “un café”；查找“法尔童”在“法尔童说”中仍匹配。
- AC-FIND-04-3: 无效正则 `(abc` 显示“正则表达式无效”且计数为空，全部替换被拒绝且文档不变；`a*` 只计非空匹配。
- AC-FIND-04-4: 对 2000 条长文字执行 `(a+)+$` 一类回溯严重的表达式时，3 秒内返回“表达式过于复杂”，期间其他窗口与列表仍可操作；文档不变。
- AC-FIND-04-5: 开启正则或全词后，高亮、计数、上一条 / 下一条、逐条替换、全部替换与撤销都与开关一致。

#### 边界与异常

- 查找词长度仍为 1–200 个字符；替换词仍不超过 200 个字符（展开后受字幕长度上限约束）。
- 翻译进行中替换禁用（与 I1 相同）；查找可用。

### R-FIND-05 查找栏的正则与全词开关

| 字段 | 值 |
| --- | --- |
| 来源 | 2026-10-14 用户：“查找替换支持正则和整词匹配” |
| 状态 | active |

#### 说明

- 查找栏在“区分大小写”旁增加“全词匹配”“使用正则表达式”两个切换按钮（按下状态与区分大小写一致，有提示文字；全词匹配的提示说明中日文按字查找不受影响），快捷键 Alt+W（全词）、Alt+R（正则），焦点在查找栏内时有效。
- 正则无效或过于复杂时，原计数位置显示错误说明（不同于“无匹配”），替换按钮禁用。
- 开关状态在本次会话内保留（关闭再打开查找栏不丢失）。

#### 验收标准

- AC-FIND-05-1: 点“使用正则表达式”后输入 `\d+年`，计数与高亮按正则；Alt+R 关闭后按字面查找（无匹配）。
- AC-FIND-05-2: 输入 `(abc` 时计数处显示“正则表达式无效”，替换与全部替换禁用；修正后恢复。
- AC-FIND-05-3: 1280×860 浅色与 786×660 深色下查找栏不溢出，三个开关对齐、可用键盘操作。


#### 边界与异常

- 查找词为空时三个开关可切换但不查找；切换开关后立即按新选项重新查找。
