# agent-multi-session 需求

需求行为只在这里定义；实现方案见 [design.md](design.md)，任务见 [tasks.md](tasks.md)。

## 目标与范围

2026-10-12，基线 `5cf4dba`（分支 v0.4.0）。用户原话：「目前的FusionKit Agent不支持多会话 需要支持一下多会话与会话管理和相关逻辑 可以先好好想一下设计清楚 然后写文档再开发」。

现状：`useAgentStore` 只有一个 `session`；「新对话」直接销毁它；除执行模式外什么都不落盘，重启即丢失。工具围栏、准备好的操作、转写流水线回报和经典工具的输出目录缓存都把「当前会话变了」当作「作废」。

本次要做到：

1. 同时保有多个 Agent 会话，随时新建、切换，各自保留消息、计划、用量、日志和输入草稿；
2. 切走的会话在后台继续回复，多个会话可同时运行，互不打断；
3. 授权、卡片和事件始终归属发起它的会话，删除会话即作废其授权；
4. 会话保存到本机应用数据目录，重启后可查看并接着聊；
5. 会话管理：重命名、置顶、删除、搜索、按时间分组、导出与导入、清空全部；
6. 标题先取首条消息，首轮回复后由 Agent 模型生成短标题，手动重命名优先；
7. 主页左侧可折叠的会话侧栏，悬浮面板头部的会话切换器。

产品取舍已由用户在 2026-10-12 的问答中确定：后台继续且可多会话同时运行；主页侧栏 + 面板切换器；保存到应用数据目录；标题先截取、首轮后模型生成、支持手动重命名。

## 范围外

- 会话正文全文搜索（只搜标题与摘要）；会话分支、回退到某条消息重答、编辑已发送消息。
- 跨设备同步、云端存储、会话加密。
- 重启后恢复进行中的回复、待确认卡片、准备好的操作和执行确认：授权不跨重启，这些卡片显示为已失效（与现有 prepared-actions「不持久化」的原则一致）。
- 按会话分别设置执行模式或 Agent 模型：二者仍为全局设置。
- 会话归档、文件夹/标签、批量多选删除。

## 需求

### R-SESSION-01 多会话与切换

| 字段 | 值 |
| --- | --- |
| 来源 | 用户请求：「支持一下多会话与会话管理和相关逻辑」 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

应用同时持有多个会话，界面显示其中一个（当前会话）。每个会话独立保存：消息、工作计划、Token 用量、会话日志、待确认的执行确认与重命名计划、输入草稿、是否有未读回复。「新对话」新建一个空会话并切换过去，不再销毁原会话。

#### 验收标准

- AC-SESSION-01-1: 在会话 A 有若干消息时，点击「新对话」，界面切到空白的新会话，A 仍出现在会话列表中且内容完整。
- AC-SESSION-01-2: 在会话 A、B 各有不同的消息、计划与用量时，在两者间切换，消息流、计划状态栏、用量条与会话日志始终显示所选会话自己的内容。
- AC-SESSION-01-3: 在会话 A 输入框写了未发送的文字后切换到 B 再切回 A，A 的草稿仍在，B 的输入框不出现 A 的草稿。
- AC-SESSION-01-4: 当前会话为空（没有任何消息）时再点「新对话」，不再创建第二个空会话，焦点回到输入框。

#### 边界与异常

空会话不进入列表、不落盘；切走后自动丢弃。列表里的会话首次被选中时需要从磁盘读取，读取期间显示加载态，失败时提示且不切换。

### R-SESSION-02 后台运行与并发

| 字段 | 值 |
| --- | --- |
| 来源 | 用户 2026-10-12 选择「后台继续，可多会话同时运行」 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

每个会话同一时间最多一个进行中的回复；不同会话的回复互不影响。切换会话、离开主页、打开或收起悬浮面板都不中断回复。停止按钮只停止当前所显示会话的回复。

#### 验收标准

- AC-SESSION-02-1: 在会话 A 正在回复时切换到会话 B，A 的回复继续完成并写入 A；切回 A 时看到完整回复，B 的消息流中不出现 A 的任何内容。
- AC-SESSION-02-2: 在会话 A 正在回复时，在会话 B 发送消息，两者同时进行，各自完成后结果各归其会话。
- AC-SESSION-02-3: 在 A、B 同时回复时，在 B 中点击停止，只有 B 停止，A 继续完成。
- AC-SESSION-02-4: 后台会话正在回复时，会话列表中该会话显示运行中标识；它在后台完成回复后显示未读标识，选中该会话后未读标识消失。
- AC-SESSION-02-5: 正在回复的会话 A 中，在其输入框不能再次发送（与现有行为一致：按钮变为停止），而其他会话照常可发送。

#### 边界与异常

后台回复中如果工具需要原生选择器，选择器照常弹出，标题沿用工具原有标题；用户取消即为该工具的取消结果。回复出错只影响该会话的状态与提示。

### R-SESSION-03 会话范围的授权、卡片与事件

| 字段 | 值 |
| --- | --- |
| 来源 | 多会话后保持现有安全模型（tool fence、prepared action、用户意图授权）不被跨会话借用 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

工具执行时读取的用户原话（输入路径、覆盖意图、重命名确认等）、写入的计划、执行确认与重命名计划、准备好的操作、转写流水线完成回报、卡片操作产生的界面事件，都只属于发起它的会话。切换会话不再作废其他会话的待确认卡片；删除会话会停止其回复并作废它的全部授权。

#### 验收标准

- AC-SESSION-03-1: 在会话 B 中用户亲手输入了路径 P，会话 A 的模型以 P 调用需要「用户输入过的路径」的工具时，A 的工具判定未授权（与 B 无关）。
- AC-SESSION-03-2: 会话 A 有一张待确认的准备好的操作卡片，切到 B 再切回 A，卡片仍可确认并执行，确认后的界面事件写入 A 并由 A 跟进。
- AC-SESSION-03-3: 会话 A 提交了带自动翻译/导出的转写批次后用户切到 B，批次完成时完成回报写入 A（A 在后台跟进），B 不受影响。
- AC-SESSION-03-4: 删除一个有进行中回复和待确认卡片的会话后，回复停止，其卡片无法再执行，后续不再有任何内容写入或回报给它。
- AC-SESSION-03-5: 后台会话的工具写入工作计划、执行确认或重命名计划时，写入该会话自身，当前显示的会话不变。

#### 边界与异常

页面工具（Studio 等当前页面能力）仍按回合开始时的页面确定，离开页面后返回 page_unavailable，与现状一致。页面上报的事件（如 Studio 应用修订）写入当前显示的会话。

### R-SESSION-04 本地持久化

| 字段 | 值 |
| --- | --- |
| 来源 | 用户 2026-10-12 选择「保存到应用数据目录」 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

有消息的会话自动保存到应用数据目录（每个会话一个 JSON 文件，格式与导出文件兼容，另有索引）。重启后会话列表完整，选中即可查看并继续对话。待确认卡片、准备好的操作、执行确认、重命名计划不跨重启。

#### 验收标准

- AC-SESSION-04-1: 有两个含消息的会话时重启应用，列表中两个会话的标题、置顶状态与顺序不变；打开任一会话，消息、计划、用量与日志与重启前一致，并可继续发送消息。
- AC-SESSION-04-2: 重启前留有待确认卡片的会话，重启后卡片显示为已失效、不可执行；计划中进行中的步骤不再显示为进行中。
- AC-SESSION-04-3: 会话发生变化后最多约 1 秒内写盘，每次回复结束时立即写盘；写盘采用临时文件替换，写一半中断不会损坏已有文件。
- AC-SESSION-04-4: 某个会话文件损坏或不合法时，其余会话照常列出与打开；损坏的会话在列表中显示为无法读取，可删除。
- AC-SESSION-04-5: 写盘失败（磁盘满、权限、超出 8 MiB 上限）时，会话仍留在内存中可继续使用，界面给出不打断操作的提示。
- AC-SESSION-04-6: 启动应用后主页显示空白新会话（欢迎界面），历史会话在侧栏中，不自动打开上一次的会话。

#### 边界与异常

单个会话文件上限 8 MiB（与导出一致）。超限时先丢弃最旧的会话日志明细再写，仍超限则报告失败。会话 ID 只接受安全字符，主进程拒绝任何可构成路径穿越的 ID。索引丢失或损坏时从会话文件重建。

### R-SESSION-05 会话管理

| 字段 | 值 |
| --- | --- |
| 来源 | 用户请求：「会话管理和相关逻辑」 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

列表按「置顶 / 今天 / 昨天 / 近 7 天 / 更早」分组，组内按最近更新排序；可按标题和摘要搜索。每个会话可重命名、置顶/取消置顶、导出、删除。导入的会话作为新会话加入列表并切换过去，不覆盖当前会话。设置 → Agent 可清空全部会话记录。

#### 验收标准

- AC-SESSION-05-1: 在会话行上重命名并确认后，列表、面板标题即时更新，重启后保持；输入空标题或按 Esc 则取消，标题不变。
- AC-SESSION-05-2: 置顶一个会话后它出现在「置顶」组顶部，取消置顶后回到按时间的分组；状态重启后保持。
- AC-SESSION-05-3: 删除会话需二次确认；确认后会话从列表和磁盘移除。删除当前会话后界面切到空白新会话。
- AC-SESSION-05-4: 在搜索框输入关键字，列表只显示标题或摘要包含它的会话（不区分大小写）；无匹配时显示空结果说明；清空关键字恢复完整列表。
- AC-SESSION-05-5: 导入一个合法的会话文件后，列表新增该会话（保留文件中的标题，没有时按首条消息生成）并切换到它，原当前会话保留不变；导入的执行模式不生效（与现有导入一致）。
- AC-SESSION-05-6: 在设置 → Agent 中清空全部会话，确认后停止所有进行中的回复，列表为空，磁盘上的会话文件被删除，界面为空白新会话。
- AC-SESSION-05-7: 从会话行导出任一会话（不必先切换过去），得到的文件可被导入，导入后内容一致。

#### 边界与异常

删除或清空是永久的，确认文案需说明不可恢复。正在回复的会话被删除时先停止回复。

### R-SESSION-06 会话标题

| 字段 | 值 |
| --- | --- |
| 来源 | 用户 2026-10-12：「先取首条消息自动截取，然后再在首轮回复后用Agent模型生成短标题……要支持手动重命名」 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P1 |

#### 说明

用户发出会话的第一条消息时，立即以该消息截取出标题；首轮回复正常结束后，用当前 Agent 模型基于首条消息与首轮回复生成一个简短标题（用户语言），替换截取标题。用户手动重命名过的标题永远不被自动覆盖。生成请求的 token 用量计入该会话的用量统计。

#### 验收标准

- AC-SESSION-06-1: 在新会话发送「把工作台里还没翻译的日语字幕翻成中文」，列表中立刻出现以该句开头的标题（过长时省略）。
- AC-SESSION-06-2: 首轮回复正常结束后，标题被替换为模型生成的短标题（不超过约 20 个字符、无引号与句末标点）；生成请求不带任何工具，用量计入该会话。
- AC-SESSION-06-3: 在标题生成完成前用户手动重命名，生成结果不覆盖手动标题；手动重命名后的会话之后也不再自动改标题。
- AC-SESSION-06-4: 标题生成失败、超时或首轮回复出错/被停止时，保留截取标题，不弹错误，会话日志记录原因；首轮失败的会话在之后第一次成功回复后再尝试生成一次。

#### 边界与异常

只对用户亲手输入的首条消息截取（界面事件消息不算）。截取按字素处理，不切坏代理对；去掉换行与多余空白。生成结果为空或全是标点时视为失败。

### R-SESSION-07 会话入口与布局

| 字段 | 值 |
| --- | --- |
| 来源 | 用户 2026-10-12 选择「主页左侧可折叠侧栏 + 面板头部切换器」 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

主页左侧为会话侧栏：窗口足够宽时常驻（可手动收起，偏好记住）；窗口较窄时收起为左上角按钮，点开以浮层显示，选择会话或点外部即关闭。悬浮面板头部标题区变为会话切换器，点开弹出带搜索的会话列表和「新对话」；原头部「新对话（重置）」按钮改为新建会话。主页工具栏「新对话」不再需要二次确认（不会丢失内容）。

#### 验收标准

- AC-SESSION-07-1: 窗口宽度不小于 1000px 时，主页左侧常驻会话侧栏，且对话栏、输入框与侧栏不重叠；点击收起后侧栏隐藏，重启后保持收起。
- AC-SESSION-07-2: 窗口宽度小于 1000px（含最小 786px）时，侧栏默认不占位，点击左上角会话按钮后以浮层打开，选中会话后浮层关闭并切换到该会话；Esc 或点击外部关闭。
- AC-SESSION-07-3: 在工具页打开悬浮面板，点击头部会话切换器，弹出列表中可搜索、选择会话或新建；选择后面板显示所选会话，页面不跳转。
- AC-SESSION-07-4: 侧栏与切换器在浅色、深色主题下，长标题（中英混合、无空格长串）单行省略且悬停/聚焦可见完整标题；运行中与未读标识、当前会话高亮、悬停同时出现时互不遮挡。
- AC-SESSION-07-5: 侧栏、切换器、行内菜单与删除确认均可用键盘操作（Tab/方向键/Enter/Esc），图标按钮具有可读名称，中文与英文界面文案齐全。

#### 边界与异常

从主页离开时的「对话栏飞入悬浮面板」交接动画不受侧栏影响。

变更（2026-10-12，用户确认）：常驻阈值 1216px → 1000px（AC-07-1、AC-07-2）。原因：侧栏常驻时主页对话内容改为居中于侧栏右侧的空间（用户反馈），672px 的对话栏在 1000px 宽时两侧仍各留 32px，不再需要按整窗居中推出的 1216px。没有任何历史会话时侧栏显示简短空状态。

## 约束

- 安全模型不降级：工具对「用户亲手输入」「覆盖意图」「重命名确认」的判断只读本会话的用户消息；界面事件消息永远不是用户授权；授权与准备好的操作不跨重启（`src/agent/prepared-actions.ts` 的既有原则）。
- 存储只在 `app.getPath("userData")/agent-sessions/` 下；只有应用自身窗口主框架可调用（同 `electron/main/web-lookup/index.ts` 的 trusted 规则）；预加载 API 通过 `scripts/check-preload-bundle.mjs` 检查。
- 会话文件即导出格式（`src/agent/session-schema.ts` 的 `sessionExportSchema`，`version: 1`），新增字段均为可选，旧版本应用导入时会忽略。
- UI 测试默认静默窗口（不抢焦点、不弹到前台），见 `vitest.config.ts` 与 `electron/main/test-window-mode.ts`。
- i18n：新增文案同时提供 zh 与 en，通过 `pnpm i18n:check`。
- 不调用付费 API 做验证：端到端测试使用本地模拟的 Responses 接口。
