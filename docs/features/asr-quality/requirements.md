# 转写质量与复杂音频支持 需求

需求行为只在这里定义。调研与方案评估见 [discovery.md](discovery.md)。

## 目标与范围

提升 Subtitle Studio 本地转写在低音量/耳语（日语 ASMR）与嘈杂（环境声、音效、BGM）音频上的可用性：提供可选的音频类型模式、让需要听校的句子可见可跳转、让失败任务可重试、增强单句重新识别，并加入有证据支持的新模型。默认“标准”模式保持现有行为不变，新行为全部可选；质量结论以真实音频对照与用户听审为准。

## 范围外

- 不改变默认参数、默认模型与默认音频类型。
- 不引入新的推理运行时（onnxruntime、sherpa-onnx、CrispASR）与人声分离/降噪模型（第三期评估）。
- 不上传音频到任何云端服务。
- 不自动删除或改写任何字幕；质量复核只标记，修改需用户操作。
- 不做开放式调参：每个预设只用设计中固定的参数跑一次真实音频对照。
- 不升级 whisper.cpp，不改 VAD 模型。

## 需求

### R-ASRQ-01 音频类型预设

| 字段 | 值 |
| --- | --- |
| 来源 | 用户 2026-10-22：“对于不同原始音频的支持程度更好…原始人声较小的音频、杂音/环境音/音效较多的复杂音频”；discovery A1 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

转写设置新增“音频类型”：标准（默认，等同现状）、低音量·耳语、嘈杂·音乐音效。预设决定附加发送给 whisper-server 的 VAD/解码字段与低音量调理方式，不改变用户选择的模型、语言、束宽等其他设置。选择保存在转写偏好中；任务提交时冻结。

#### 验收标准

- AC-ASRQ-01-1: 在默认偏好下提交转写，发送给 whisper-server 的每个请求字段名与值都与改动前一致，现有执行器回放与转写测试保持通过。
- AC-ASRQ-01-2: 选择“低音量·耳语”提交，每个开启 VAD 的识别请求额外带上设计规定的 VAD 阈值、最短语音时长、语音填充、no_speech 阈值与 suppress_nst 字段，窗口低音量调理改用 R-ASRQ-02 的门控动态增益；重开 Studio 后该选择仍在。
- AC-ASRQ-01-3: 选择“嘈杂·音乐音效”提交，每个开启 VAD 的识别请求带上设计规定的该预设字段，低音量调理保持标准方式。
- AC-ASRQ-01-4: 选择非标准预设时语音检测被开启；用户关闭语音检测时音频类型回到标准并显示原因说明。
- AC-ASRQ-01-5: 转写任务列表能看出每个任务使用的音频类型。

#### 边界与异常

- DTW 分句等 VAD 关闭的辅助请求不带预设的 VAD 字段，保持已验证的路径。
- 历史任务快照没有该字段时按标准处理。
- 主进程拒绝预设名称未知或字段越界的请求。

### R-ASRQ-02 低音量门控动态增益

| 字段 | 值 |
| --- | --- |
| 来源 | 用户原始描述“原始人声较小的音频”；discovery B1；历史 phase10 中 C 类局部低音量问题 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

“低音量·耳语”模式下，每个识别窗口用门控、平滑的增益提升安静人声：按帧估计噪底与活动电平，只对活动部分提升，用平滑的逐帧增益处理瞬态而不是整窗放弃。

#### 验收标准

- AC-ASRQ-02-1: 对合成信号应用增益后采样数与时间位置不变，峰值不超过 -1 dBFS，纯噪底帧的提升不超过 6 dB。
- AC-ASRQ-02-2: 活动电平低于 -60 dBFS 的安静语音窗口、以及含少量强瞬态的安静窗口都会被提升；旧策略对这两类窗口不做处理。
- AC-ASRQ-02-3: 门控增益的识别结果无效、出现过长段或重复时，仍按现有安全网回退原音重识别一次。
- AC-ASRQ-02-4: 标准预设下窗口音频字节与改动前一致。

#### 边界与异常

全静音窗口、全满幅窗口与极短窗口不报错，原样返回。

### R-ASRQ-03 逐句置信度与质量复核

| 字段 | 值 |
| --- | --- |
| 来源 | 用户原始描述“结果的可用性”；discovery C1 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

新转写的每条字幕带 0–1 的置信度。Studio 字幕列表能筛出需要听校的句子并说明原因：低置信度、疑似幻觉短语、句内重复循环、只有符号或音效标注、语速异常、与相邻句重复。提供计数、上一个/下一个跳转与针对单句的快速操作。只标记，不自动删改。

#### 验收标准

- AC-ASRQ-03-1: 新转写完成后，文档中转写稿的每段都有 0–1 的置信度；没有置信度的旧文档正常打开，只按文本规则标记。
- AC-ASRQ-03-2: 对“ご視聴ありがとうございました”（低置信度）、“♪～♪”、“あああああああああああ”、语速明显过快的句子与正常句子，复核规则分别给出疑似幻觉、纯符号、重复循环、语速异常与不标记。
- AC-ASRQ-03-3: 在 Studio 打开含标记的文档，开启“待复核”筛选后只列出被标记的句子并显示各类计数与原因，可用上一个/下一个跳转并播放该句音频；无标记与大量标记时界面状态正确。
- AC-ASRQ-03-4: 用户修改某句文本后，该句不再因置信度被标记；用户对某条标记选择“忽略”后，在本机重新打开文档时不再显示该标记。
- AC-ASRQ-03-5: 复核不会自动删除或改写字幕；“折叠重复”等修正只在用户点击后执行，并能用撤销恢复。

#### 边界与异常

置信度只是提示，界面不宣称其为准确率；短语表不包含常见真实台词（如おやすみなさい）。

#### 验收标准

- AC-ASRQ-04-1: 资源面板与模型选择列出三款新模型，显示中文名称、大小、适用场景与许可提示；模型目录、迁移与下载源相关测试通过。
- AC-ASRQ-04-2: 选中 turbo 或语言专用模型时“翻译成英文”不可选；中文/日语专用模型把识别语言锁定为 zh/ja；不允许提示词的模型禁用上下文提示并说明原因；主进程拒绝与模型配置不一致的提交。
- AC-ASRQ-04-3: 只适合短句的模型（anime-whisper）不出现在整段转写的模型选择中，可在重新识别中选择，并说明推荐用法。
- AC-ASRQ-04-4: 下载地址位于 huggingface.co 其他仓库的模型，官方源失败时会尝试 hf-mirror.com 的同一路径，下载结果仍按 SHA-256 校验。
- AC-ASRQ-04-5: 获得下载许可（Q-01）后，三款模型各在真实样本上完成一次加载与识别，记录时间戳与输出是否可用；未获许可时该项保持待验证。

#### 边界与异常

模型配置表对未知模型使用保守默认（允许全部语言、允许提示词、允许整段转写、不支持翻译以外无限制）。

### R-ASRQ-05 重新识别增强

| 字段 | 值 |
| --- | --- |
| 来源 | discovery C3；历史 phase5/phase10 结论（局部重识别需要上下文与低音量增益） |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P1 |

#### 说明

重新识别可选择已安装的识别模型；剪辑带前后上下文，只把与字幕时间重叠的识别段作为结果；低音量剪辑先增益并开启 VAD 填充；结果附置信度，疑似幻觉时提示；可以直接针对“待复核”筛选出的句子发起。

#### 验收标准

- AC-ASRQ-05-1: 选择另一个已安装模型重新识别时请求使用所选模型；未安装的模型不可选。
- AC-ASRQ-05-2: 返回文本只包含与字幕时间范围重叠的识别段，上下文中相邻句的文字不会混入。
- AC-ASRQ-05-3: 剪辑电平处于低音量区间时识别的是增益后的音频；结果低置信度或命中复核规则时界面给出提示且不自动应用。
- AC-ASRQ-05-4: 可以一次对当前“待复核”筛选出的句子发起重新识别，并遵守单次数量上限。

#### 边界与异常

上下文与剪辑总长不超过 30 s；模型切换导致服务重新加载时显示忙碌状态而不是失败。

### R-ASRQ-06 失败任务的重试与建议

| 字段 | 值 |
| --- | --- |
| 来源 | 用户原始描述“成功率”；discovery C2 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P1 |

#### 说明

失败或无内容的任务可以直接用同一文件重试，并根据结果给出可一键执行的建议；错误说明区分程序问题与识别质量问题。

#### 验收标准

- AC-ASRQ-06-1: 失败或无内容的任务显示“重试”，不需要重新选择文件即可用同一文件重新提交；源文件已被移动或修改时提示重新添加。
- AC-ASRQ-06-2: 无内容结果提供“改用低音量·耳语重试”；GPU 相关失败提供“改用 CPU 重试”；两者都一键提交。
- AC-ASRQ-06-3: 窗口级识别或质量失败显示为识别质量问题并建议切换分段方式、音频类型或模型，不再提示重新安装；每种失败都能复制不含文件路径的诊断信息。

#### 边界与异常

重试生成新任务，原失败任务保留到用户移除；批量重试遵守单批文件上限。

### R-ASRQ-14 窗口接缝重复字幕

| 字段 | 值 |
| --- | --- |
| 来源 | 用户 2026-10-23 听审 T-09 #10：“不知道为什么 低音量·耳语 和 嘈杂·音乐音效 都重复输出了 转写出了两遍”；随后指示“先修窗口接缝处的重复字幕（后处理去重 + 复核规则识别近似重复），修完给我听对比” |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

重叠窗口在接缝处会把同一句话输出两次：其中一份来自另一个窗口、被裁到接缝时刻，时间常被压缩到 1 秒以内。后处理在接缝处去掉这类重复，只去掉与接缝另一侧已识别内容高度重合的那一份，不丢字（带有另一侧没有的字的那一份保留）；保留的那一份文字不变，它被裁到接缝的一端在另一份去掉后可移回原始时间（不越过相邻字幕，2026-10-24 按重跑结果补充）；真实的重复说话保留。复核规则把与上一句文字近似（包含上一句，或只差一两个字）的相邻句也标为“与上一句重复”。

#### 验收标准

- AC-ASRQ-14-1: 用修复后的版本按 run-2512BY 的配置重跑，records/listening-results-2026-10-23-partial.md 核对出的接缝重复（如 pv-zh 152.50 s 处被转写两遍的那句）不再出现，对应内容在接缝另一侧保留一份。
- AC-ASRQ-14-2: 去重只作用于接缝处被裁剪、且文字与接缝另一侧重合的句子；「うん」「うん」这类合法重复、不在接缝处的相同句子保持不变。
- AC-ASRQ-14-3: 9 段样本 × 3 种音频类型重跑后，与修复前相比，除被去掉的重复句与保留句移回的一端外，其余字幕的文字与时间不变；有其他差异时逐条列出并说明原因。
- AC-ASRQ-14-4: 复核规则把“包含上一句”或“与上一句只差一两个字”的相邻句标为“与上一句重复”（如 pv-zh 嘈杂·音乐音效 52.50 s 处人名带间隔号、又换了两个同音字的那一对）；「うん」「はい」这类短语气词不误标。
- AC-ASRQ-14-5: 用户在听审页面逐处对比修复前后被去掉的句子，确认去得对或指出不该去的（由用户听审，Agent 不代签）。

#### 边界与异常
