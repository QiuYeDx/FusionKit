## Rendered review: state/position -> problem -> cause -> change -> re-check
Earlier run folders named below (run-du1izf, run-DXlYoA, run-RVWHfn) were since pruned by createTestRun; run-dNL4mU, run-F87pf6,
run-pAON6Z and the final run-Edg5GR remain.
1. 1280x800 light, model list open (run-du1izf/01-models-1280-light.png): the usage line of 中文普通话 and 日语动画·ASMR was cut off at the
   list's right edge ("…再对需"). Cause: the list reused the settings' .studio-transcription-model-options (max-width 22rem = 352 px) while
   Radix gives the viewport min-width = trigger width (416 px), so the items were wider than the visible list. Change: own class
   .studio-cue-recognize-models. First try (max-width only, run-DXlYoA/01) let the list grow to its longest line (521 px) and centre past the
   trigger's left edge, so the width is now pinned to the trigger as the audio-type list is. Re-check run-RVWHfn/01 and the final
   run-F87pf6: list 416 px = trigger 416 px, usage lines wrap to two lines inside it, nothing cut.
2. 1280x800 light results (run-du1izf/02): the model hint read "…替换文本。 所选模型只识别日语。 所选模型…" with spaces between Chinese
   sentences. Cause: the parts were joined with ' '. Change: no separator for zh/ja, a space for other languages. Re-check run-DXlYoA/02
   (zh, no spaces) and 03-results-1024-light-en (English keeps spaces).
3. Same state: the 低置信度 / 疑似幻觉 tags of unchosen flagged rows were faded to 0.5 with the text, so the warning was the faintest thing in
   the row. Cause: the dialog dims the whole texts column of unaccepted rows. Change: for flagged rows only the text is dimmed. Re-check:
   measurements flaggedText opacity 0.5, flaggedTexts 1, flag 1 with rgb(217,119,6); visible in all 03-results screenshots.
4. 1280x800 light, hovering line 5's flag (run-DXlYoA/02): the tooltip arrow pointed at the middle of the row, far right of the tag. Cause:
   the tag is a grid item of .studio-cue-revision-texts and stretched to the column width (533 px), so the trigger box was the whole row.
   Change: justify-self: start for tags in this dialog. Re-check run-RVWHfn/02 (cropped): the arrow sits under the tag; measured flag
   width 57 px.
5. 1280x800 light, hovering line 5's flag after change 4 (run-dNL4mU/02): the tooltip opened above the tag and covered most of line 5's own
   text. Cause: side="top" on a tag that sits under the text it explains. Change: side="right", as the list's row marks open. Re-check
   run-F87pf6/02: the tooltip sits to the right of the tag, line 5's text stays readable except the tail of its deletion mark (superseded by 7).
