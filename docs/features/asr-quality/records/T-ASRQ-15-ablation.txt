1. 源码核对（V-ASRQ-15-2）
本项目窗口时间换算（只读）：
- 段秒 → 毫秒：Math.round(*1000)（server-contract.ts:526-527, 705-706）；绝对时间 = window.startMs + 段时间
  （subtitle-post-processor.ts:1412-1413），再裁到窗口核心（1418-1435）；跨窗合并只把 ≤ 100 ms 的重叠移到中点
  （1520-1545）；cue-boundary-planner.ts:41 不做内部切分。没有固定时长或均分。
- 窗口 PCM 是逐帧切片（pcm-window.ts:278, 289），调理就地进行（293）；门控增益逐样本乘增益、长度不变、无重采样
  或滤波延迟（quiet-audio.ts:68-70, 112-114）。增益只在 > 0 dB 时记录，且执行器此时把 vad_speech_pad_ms 改为 1000
  （transcript-executor.ts:1585-1586）；pv-zh 的 10 个 Q 请求都发 300、没有 quietAudioGainDb。
- 预设字段只加在开语音检测的请求上（server-contract.ts:62-74, 316-352；transcript-executor.ts:1581-1584, 1600-1608）；
  token_timestamps=false，服务端 max_len 换行不生效。日语 CUDA 修复与分句候选不涉及 pv-zh。
服务端 whisper.cpp v1.9.1（源码下载到会话草稿区阅读；带 * 的行本次综合时再次核对过）：
- * server.cpp:832 每个请求从 default_params 复制参数，字段不会串到下一个请求；* 962-967 把六个 vad_* 字段传给
  wparams；* 109 no_context 默认 true，* whisper.cpp:6921-6923 每次解码清空上文；* 7163 每次解码清空 KV 缓存。
- * whisper.cpp:5973 max_initial_ts 默认 1.0 s，* 6319-6327 第一个时间戳不能超过它；服务端没有对应的请求字段。
- 语音检测：neg_threshold = threshold − 0.15（5252）；连续低于它 min_silence 才结束一段（5327）；短于 min_speech 的段丢弃
  （5369）；两段间隔 < 2×pad 时各取一半并接上，否则两侧各加 pad（5395-5420）。
- 拼接与映射：每段（最后一段除外）后接 0.1 s 原音与 0.1 s 零（6714, 6739, 6780）；映射点为 (vad_start, orig_start)、
  (vad_end, orig_end)、(silence_start, orig_end)、(silence_end, 下一段 orig_start)（6755-6756, 6776-6777），线性插值、两端
  夹紧（7941-7979）；只要有一个语音段就映射（6685, 7985, 7999）。片段内部 1:1；#3683 的 vad_end 比例错误已在
  PR #3711（2026-03-17 合入）修复，v1.9.1（2026-06-19）不受影响。
- no_speech_thold 在 v1.9.1 不起作用：no_speech_prob 读的是没有写入的 logits 行（511-523, 2949-2955, 7179-7181；
  PR #3945、#4068 未合入），值恒约 1/n_vocab = 1.93e-05。suppress_nst 只屏蔽非语音文字 token（6279-6295），不改时间戳规则。
- 结论：映射只在语音段之间改正时间；段内的误差原样通过。窗口内的时间完全取决于解码器给出的时间戳。

8. 修法原型 C：按标准请求的锚点修正时间（推荐）
做法：先按 app 顺序发完一个样本的全部预设窗口（与现在相同），再对每个窗口用同一份 PCM 发一次标准请求（去掉
vad_threshold、vad_min_speech_duration_ms、vad_speech_pad_ms（有增益时保留 1000）、no_speech_thold、suppress_nst，
与 standard 变体对该窗口发的字段相同）。两边段文字去标点空白后逐字 LCS 对齐：预设段开头（结尾）前两个字与锚点段
开头（结尾）前两个字在同一位置对上，这一端取锚点时间；其余端按前后最近两个已锚定端的位移线性插值，两端之外取最近
一个的位移；窗口没有锚点时不动；按顺序保证起点 ≥ 上一段终点、终点 ≥ 起点 + 0.2 s，裁在窗口内。文字不变。

9. 判断
- 原因：解码器时间戳。片段起点钉在处理后 0.00；解码器跳过开头内容（上一窗口延续的半句、BGM）或中途一句时，后面的
  时间戳顺延提前，30 s 窗口里没有外部锚点，映射还会把跨过的停顿加进误差；下个请求重新对齐。
- 触发：vad_threshold 0.35 让 100–130 s 的第一个片段把上一窗口延续的半句包进来，3/3 严重；175–205 s 各配置都从 0.00
  起，是否偏早取决于解码的数值差异，0.35 时更常见（S+thr0.35 2/3、Q-pad 1/2，标准 0/3）。pad 300 让片段多带 0.3 s
  BGM，起点贴片段时额外偏早约 0.3 s（100–130 s 第 0 段偏移随 pad 30/100/200/300/500 为 -1.01/-1.08/-1.18/-1.28/-1.48 s）。
  min speech 150、no_speech_thold 0.7、suppress_nst、门控增益（pv-zh 0 dB）无可测影响。
- 修法 A（只调阈值）仍偏早约 1 s 且丢掉一半召回收益；修法 B（标准语音检测）等于标准、失去全部召回收益；
  修法 C（锚点修时间）文字不变，偏早或偏晚 > 1 s 的句子在 7 个样本×变体上合计 54 → 15。
