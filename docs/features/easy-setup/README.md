# 新手友好的安装与上手（easy-setup）

目标：不太懂电脑的用户，从官网下载到完成第一次字幕翻译和本地转写，**不打开终端、不手动装任何运行库、不需要理解 Base URL、Token 或代理端口**，15 分钟内能用起来；遇到问题时，应用告诉他原因和下一步该点什么。

- 现状盘点（依赖清单、新手路径走查、网络与文案问题，含代码位置）：[audit.md](audit.md)
- 结论：**目前未达到目标**。运行时依赖基础不错（不需要 Node、Python、FFmpeg、CUDA Toolkit，下载有续传和校验），但“打不开、配不好模型、下不动资源、Windows 缺 VC++ 运行库、出错看不懂”五处会让新手卡住。
- 实施任务与进度：[tasks.md](tasks.md)

## 已定决策（2026-10-17）

| # | 决定 | 对方案的影响 |
| --- | --- | --- |
| D1 | 暂不购买证书做签名与公证 | “打不开”只能靠清楚的图文指引解决（README、官网、DMG 内说明、应用内帮助）。macOS 继续不做自动更新 |
| D2 | 可以使用第三方镜像 | 模型、VAD、CUDA 包、更新清单与安装包都接入多下载源，自动选择、失败换源；完整性由已固定的大小和 SHA-256 保证 |

| D4 | 只预设 DeepSeek，并作为最推荐的服务商 | 向导默认 DeepSeek，给出获取 Key 与充值链接；OpenAI 与“其他”保留为现有选项，不新增其他服务商 |

## 验收标准

在以下环境各走一遍完整路径：全新 Windows 10 / 11 x64 虚拟机（未装 VC++ 运行库、无 `HTTP_PROXY` 环境变量）、全新 macOS 用户账户（Apple Silicon）；中国大陆网络下分别测试“开着 Clash 类系统代理”和“完全不开代理”。

| # | 标准 |
| --- | --- |
| A1 | 从官网、README 或 DMG 里就能找到“打不开怎么办”，按步骤操作即可打开；macOS 唯一需要的命令可以一键复制 |
| A2 | 第一次打开有向导；选 DeepSeek、粘贴 Key、点“测试”通过后，Agent 和翻译直接可用，不需要再去别处“分配模型” |
| A3 | Key 错、余额不足、模型名错、网络不通，各自给出看得懂的原因和下一步按钮 |
| A4 | 点一次“一键准备”就装好推荐模型和语音检测；不开代理时在大陆网络下也能下完 |
| A5 | 全新 Windows 上不额外装任何东西就能完成一次本地转写 |
| A6 | 开着系统代理时，AI 调用、资源下载、检查更新都自动走代理，用户不用填端口 |
| A7 | Windows 上发现新版本可在应用内下载并安装；GitHub 不可达时自动用镜像 |
| A8 | 新手会看到的界面中不出现未解释的英文术语（Base URL、max_tokens、GGML、VAD 等改写或收进“高级”） |

## 设计

### 1. 装得上、打得开

**VC++ 运行库（D3）**

转写程序 `whisper-server.exe` 启动时的 `PATH` 被冻结代码收紧为“程序目录 + System32”（`server-process-contract.ts` 中的 `buildLocalSubtitleServerEnvironment`），程序目录又受冻结清单的精确文件树校验，所以把 DLL 放在应用目录里行不通；而且 System32 中若有旧版运行库会优先加载，用新工具链编译的程序在旧版 `msvcp140.dll` 上也可能崩溃。因此采用“安装官方运行库”：

- 构建时由 `beforePack` 准备 `build/vc-redist/vc_redist.x64.exe`：从微软官方地址下载（或使用本地已有文件），校验 Authenticode 签名为 Microsoft Corporation，记录版本与 SHA-256。只在 Windows 构建中通过 `win.extraResources` 放到 `resources/vc-redist/`。
- NSIS 安装脚本（`nsis.include`）在安装完成后读取注册表 `HKLM\SOFTWARE\Microsoft\VisualStudio\14.0\VC\Runtimes\x64`，未安装或版本低于转写程序能用的最低版本（14.51.36247：转写程序由 MSVC 14.51 工具集编译，微软要求运行库不旧于编译工具集；以随包版本为界会让运行库可用的用户每次更新都看到确认框）时运行 `vc_redist.x64.exe /install /quiet /norestart`。这一步需要管理员权限，会弹一次系统确认框；用户拒绝不影响安装完成，并会被记住，之后的更新不再询问。
- 应用内检测：主进程读取同一注册表项，得出“已安装 / 缺失 / 过旧”。在下载模型之前、打开转写页与资源管理时、以及转写或加载检查以运行类错误失败时检查（实施时确认：冻结的转写代码不把 `0xC0000135` / `0xC0000139` 等退出码交给界面，只给出 `runtime_crashed`、`model_incompatible` 等错误码，所以改为遇到这类错误就重新检查注册表）；不满足就提示“需要安装微软运行库”，按钮“一键修复”运行随包的安装程序（系统确认框），完成后自动重新检查。这样可以避免下载完 1 GB 模型后才失败。

**打不开时的指引（D1）**

- README（中英）、官网下载区增加“打不开怎么办”：macOS“无法验证开发者”→ 系统设置 → 隐私与安全性 → 仍要打开；“已损坏”→ 一行可复制的命令；Windows SmartScreen → 更多信息 → 仍要运行。
- macOS DMG 中附带一份“打不开请看这里”说明文件（实施时：`build/dmg/打不开请看这里.html`，中英双语、不引用任何外部资源，命令可一键复制；经 `dmg.contents` 放进 DMG，应用、“应用程序”链接和说明文件各有固定位置，由打包合同固定：不设背景，沿用 dmg-builder 自带的 540×380 背景图，窗口同样大小；应用和“应用程序”留在 electron-builder 默认的位置（箭头两端），说明文件放在它们上方的空白处；收尾修正后它在 DMG 里的名字是中英双语的“打不开请看这里 Can't open.html”（`dmg.contents` 的 `name`，仓库里的文件名不变）。macOS 上的实际显示未验证）。
- 写清系统要求：Windows 10 / 11 x64；macOS 12 及以上、仅 Apple Silicon；磁盘空间（Windows 安装后约 850 MB（收尾修正时实测 `win-unpacked` 878,668,270 字节；瘦身前约 1.1 GB），推荐模型另需约 1 GB）。
- 应用内帮助页也有同样内容；要转发给朋友时用 README 或官网下载区（帮助页的说明里写了官网地址）。

### 2. 首次启动向导与模型配置（D4）

**欢迎向导**：没有任何可用的模型配置、且没看过向导时自动出现；可跳过，帮助页和设置中可重新打开。

1. “你想怎么用 FusionKit？”三选一：**用 DeepSeek 等 AI 服务**（推荐）/ **我用 Claude Code、Codex 或 Cursor**（不需要 Key；收尾修正后先经过第 3 步本地转写，因为外部 Agent 通过 FusionKit 转写时也要用到这些资源，完成页再打开“外部 Agent”设置）/ **先只用本地功能**。
2. DeepSeek 卡片：说明“国内可直接访问、价格低”，“获取 Key”“充值”按钮打开 DeepSeek 开放平台；粘贴 Key → “测试并保存”。测试通过后保存配置，**同时设为 Agent 模型和任务执行模型**。也可选“使用其他服务”，进入简化后的配置表单。
3. “要用本地转写吗？”显示推荐模型大小与剩余磁盘空间 → “一键准备”（可在后台进行）。
4. 完成页：给出三个可以直接点的示例任务。

**模型配置页修正**

- “前往设置”统一跳到 `?tab=model`。
- 新建配置时，空着的角色自动分配给它；“Agent 模型”和“任务执行模型”加一句说明。
- OpenAI 预设保留 Responses API（实施时确认 Agent 已支持 Responses 与 Chat Completions 两种格式，原定改为 Chat Completions 的理由不成立；OpenAI 的 Pro 型号只开放 Responses），在“高级设置”中仍可切换。
- Key 输入框默认遮挡，可切换显示。
- “API 格式”“输出 Token 参数”“价格”收进“高级设置”，选了预设就不用动。
- 配置对话框加“测试连接”。主进程发一个最小请求（走代理），错误归为：Key 不对（401/403）、余额不足（402 或余额类错误）、模型不存在（404 或 model not found）、请求过多（429）、网络不通（超时、DNS、连接被拒绝，附“去代理设置”）、服务异常（5xx）。Agent、字幕工作台与经典工具的运行时错误复用同一分类与文案。

### 3. 网络：系统代理与下载源（D2）

**统一代理层**（新增 `electron/main/network/`）

- 三种模式真正生效：**无**（直连）、**系统**（用 Electron `session.resolveProxy(url)` 读取操作系统代理与 PAC，按目标地址解析；操作系统没有设代理时沿用 `HTTPS_PROXY` 等环境变量）、**自定义**（HTTP 代理地址，也可写 `socks5://`）。
- 提供代理 Agent：https 目标走 HTTP `CONNECT` / SOCKS 隧道；http 目标经 HTTP 代理时按浏览器的做法用完整地址转发（只放行 443 端口 CONNECT 的代理也能用）。供主进程所有 Node 请求使用：AI 调用（替换现在只读环境变量的 axios 配置）、资源下载、安装包下载、联网查证。
- 同步设置默认会话和 electron-updater 自己的会话（`electron-updater` 分区）的 `setProxy`，让检查更新与渲染进程请求也遵循同一模式；设置生效后关闭旧连接。
- 代理设置同时保存在主进程（用户数据目录），启动时立即生效，不等渲染进程同步。
- 代理测试改为测试实际要用的地址：已配置的模型服务地址、当前下载源与 GitHub。

**多下载源**

在下载传输层（不是清单）把官方地址映射为候选地址，按顺序或测速结果尝试，失败自动换下一个。设置中提供“下载源：自动（推荐）/ 官方 / 国内镜像优先”。

| 资源 | 官方 | 已核实的镜像（2026-10-17，大小与 SHA-256 一致） |
| --- | --- | --- |
| Whisper 模型 | `huggingface.co/ggerganov/whisper.cpp/resolve/<rev>/<file>` | ModelScope：`cjc1887415157/whisper.cpp`、`viggocx/whisper.cpp`、`iceCream2025/whisper.cpp`（`/resolve/master/<file>`）；`hf-mirror.com`（同路径） |
| VAD | `raw.githubusercontent.com/ggml-org/whisper.cpp/<commit>/models/<file>` | `cdn.jsdelivr.net/gh/ggml-org/whisper.cpp@<commit>/models/<file>`、`fastly.jsdelivr.net`、`ghfast.top/<官方地址>` |
| CUDA 包 | `github.com/ggml-org/whisper.cpp/releases/download/...` | `ghfast.top/<官方地址>`、`ghproxy.net/<官方地址>`（均支持断点续传；`gh-proxy.com` 不支持 Range，不用于大文件） |
| 更新清单与安装包 | GitHub Releases | 同上的 GitHub 加速前缀（实施时改为 electron-updater 的自定义 provider 按顺序换源，见第 5 节） |
| 更新日志 | `raw.githubusercontent.com` | jsDelivr、`ghfast.top` |

- 镜像地址不进入冻结的资源清单；清单里的官方地址、大小、SHA-256 不变，下载完成后照常校验，镜像给出错误文件只会导致校验失败并换源重下。
- 同一资源一次下载过程中固定使用同一个源，保证断点续传有效；换源时从头下载该文件。
- 下载失败提示区分：网络不通或被拦截（建议换下载源或开代理）、磁盘空间不足、文件校验失败（下载时已自动换源重试，仍失败时建议换下载源）；导入模型失败另有说明（文件对不上、文件读不了）。

### 4. 本地转写一键准备

- “管理资源”顶部“一键准备（推荐）”：一次装好推荐模型和语音检测（先模型后语音检测：语音检测的加载检查要用推荐模型），显示总大小与剩余空间，完成后通知；向导第 3 步复用。
- 友好名称（界面层映射，不改冻结清单）：`large-v3-q5_0` →“标准（推荐，约 1.0 GB）”，`large-v3` →“最高精度（约 2.9 GB，较慢）”；VAD →“语音检测（自动跳过静音）”；CUDA →“NVIDIA 显卡加速”。原名放在详情里。
- 检测 NVIDIA 显卡与驱动版本（`nvidia-smi`，退回 WMI）。有显卡才推荐加速包，驱动低于 551.61（CUDA 12.4 对应版本）时提示更新驱动；没有显卡则标“此电脑不适用”。
- 导入文案如实说明“须与列表中的文件一致”。
- 设备选“自动”而实际用了 CPU 时，说明原因。
- 缺少本地资源时 Agent 也有出路（收尾修正）：准备转写因模型、语音检测、显卡加速包或转写程序没准备好而失败时，工具结果告诉 Agent 可以提议打开“管理资源”用一键准备；`open_app_page` 新增 `subtitle_studio` + `studioView: resources`（打开资源管理）、`network_settings`、`help` 三个去处。

### 5. 更新与安装包

- Windows：应用内“下载并安装”，显示进度、速度与下载来源，可取消；下载完成后“立即重启安装”静默安装并重新打开（实施时没有沿用旧的 `start-download` / `quit-and-install` 通道，改为只服务应用主框架的 `window.appUpdate`，旧通道与没有调用方的 `download-installer` 删除）。“立即重启安装”会先停下本地转写等功能，所以安装没能开始时只提示“重启 FusionKit”，重启后再次提示新版本。
- 换源：electron-updater 用自定义 provider 读取 GitHub Releases 的 `latest.yml`，按“下载源”设置的顺序试 github.com 与 `ghfast.top`、`ghproxy.net` 前缀（官方源只试 github.com，国内镜像优先时先试镜像），每个源单独限时；下载从回答检查的源开始，连接失败、文件缺失、SHA-512 不符或 60 秒没有数据时依次换到后面的源，最后再试排在它前面的源。全部失败时，明确回答“文件不存在”或“校验不符”的源（GitHub 优先）比连不上的源更能说明原因。安装包按版本标签路径下载，旧版本的 blockmap 也能经镜像找到，可以只下载变化的部分。
- 完整性：electron-updater 按 `latest.yml` 中的 SHA-512 核对安装包，所以这份清单本身必须可信（B5 / T5.4 起）。检查由 github.com 回答时直接采用；先回答的是镜像时，同时向还没问过的源（另一个镜像、镜像优先模式下的 github.com）要清单，各自限时，第一个足够的回答结束检查：github.com 的清单最优先（与镜像不一致时以它为准），否则另一个镜像主机给出的版本与每个文件的名称、SHA-512、大小完全相同才算印证（发布日期、说明、字段顺序不计）。都印证不了时仍显示新版本，但不能在应用内下载安装，只给“打开下载页面”和“国内镜像下载安装包”，并说明“为了安全，镜像来源无法互相印证时不会自动安装”，以及镜像下载的安装包同样没有经过核对、能打开 GitHub 时请从 GitHub 下载（镜像链接仍然保留：这时多半连不上 GitHub，去掉它就只剩“稍后重新检查”；换成另一个镜像也不更安全，两个镜像说法不一致时不知道哪个是对的）；主进程的下载入口同样拒绝。镜像的清单格式不对（如文件列表不是文件）时整份不认，不算印证。macOS 本来就手动下载，不做额外请求。清单中要求管理员权限的字段一律忽略（安装包按用户安装，不需要）。另有只用于印证、从不用于下载的 `gh-proxy.com`（它不支持断点续传，不适合下载安装包，但能返回清单；“仅官方源”模式不问它），这样两个下载镜像中有一个不可用时仍能印证。代价：GitHub 连不上、且 ghproxy.net 与 gh-proxy.com 都没有给出一致的清单时，Windows 版只能手动更新。更强的办法见“后续事项”。
- macOS：未签名不能自动更新，给出 DMG 直链（GitHub 与国内镜像各一个，文件名以 `latest-mac.yml` 为准）和替换步骤：先从程序坞退出 FusionKit，拖进“应用程序”选“替换”，被拦下时在“隐私与安全性”中允许，提示“已损坏”时可一键复制 `xattr` 命令。
- 更新错误改为看得懂的说明（网络、找不到文件、完整性检查不通过、磁盘、其他）和下一步按钮，技术信息折叠在下方可复制；Windows 下载或安装失败时还给出经国内镜像下载安装包的链接。启动时的自动检查失败不打扰用户；应用自己弹出的更新对话框在欢迎向导关闭后才出现。关于页按检查结果显示“最新”“有新版本”“正在下载”“已下载”。
- 安装包瘦身：渲染进程依赖已由 Vite 打包进 `dist`，却仍被 electron-builder 作为生产依赖整包打入 `app.asar`（约 286 MB、2.8 万个文件）。把只在渲染进程使用的依赖移到 `devDependencies`，并用打包后的应用实际启动验证（实施时把主进程用到的 `gpt-tokenizer` 也移过去，由 Vite 打进主进程包，只带它用到的一种编码）。两份相同的转写资源（各约 225 MB）受冻结来源审计约束，本次不动，记录为后续事项。

### 6. 文案与帮助

- 术语改写（新手可见处）：API Key →“密钥（API Key）”，Base URL →“接口地址”，Model Key →“模型名”，温度 / 搜索宽度 / 上下文提示等收进“高级”。实施时：工作台的这些参数本来就在“高级设置”里，改为在折叠内容顶部加一句说明；“上下文窗口”“每批输出上限”改为“模型一次能读的长度”“每批回答的最大长度”；Token 作为用量与费用的单位保留，在第一次出现的地方（工作台高级设置、经典字幕翻译的用量提示、Agent 用量面板）说明它是什么，并链接帮助页。经典转写页的“服务合同”“Whisper 运行器”“后端探测”“托管资源”“VAD”等全部改写，写给开发者的“源码运行请重新组装……”只在开发版显示。

## 实现约束

- **冻结来源审计**：本地转写相关代码受 `scripts/subtitle-studio-provenance/` 约束。`electron/main/speech-resources/engine/` 与 `resources/speech-resources/manifests/` 的字节由 `resources/speech-resources/provenance/resource-engine-extraction.v1.json` 固定，修改后必须重新登记该输出的编辑记录与摘要；`electron/main/index.ts`、`electron/preload/index.ts` 等组合文件要在两份组合审计中重新登记；冻结源文件（如经典转写页）走 `current-source-audits.json`；Studio 复制文件走 `current-copy-audits.json`。每批改动后运行 `node node_modules/vitest/vitest.mjs run test/subtitle-studio-provenance`。
- 本方案尽量不改冻结代码：下载源与代理通过资源管理器已有的 `downloadResource` 注入接入（`electron/main/index.ts` 组合 `SpeechResourceService` 时传入，模型、语音检测、CUDA 包共用），冻结的下载引擎 `resource-download.ts` 不改，提取审计无需重新登记；友好名称在界面层映射。
- 打包配置变更须同步 `scripts/packaging/subtitle-studio-contract.mjs`，并运行 `node --test scripts/packaging/*.test.mjs`（不在 `pnpm test` 中）。
- 新增界面文案同步四种语言（zh、zh-Hant、en、ja），运行 `pnpm i18n:check`。
- Electron 界面测试保持静默模式（`FUSIONKIT_TEST_WINDOW=quiet`），不抢焦点。
- 官网（`website/`）在 `main` 更新时由 Vercel 自动上线，而下载按钮给的是 GitHub 上最新的正式版。新的三步上手、一键准备、自动换镜像和应用内更新只有 0.5.1 才有，所以 `main` 要在发布 0.5.1 时一起更新（和以往一样，发布时把 `main` 快进到发布提交），不能提前合并。
