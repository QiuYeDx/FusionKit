## 设计：转写 → 翻译 → 导出流水线（V9、V10、V13）

### 现状
- 字幕工作台已有“转写完成后自动翻译”：主进程为每个转写任务保存一份持久的自动翻译意图（`automaticTranslation`），**每个文件转写完成后立即开始翻译**，不必等整批转写结束。Agent 的转写准备工具目前强制关闭了它。
- 没有自动导出，Agent 也没有导出工具。
- 转写生成的文档在创建时就绑定了源文件位置（`source-location`），主进程可以在不弹选择器的情况下导出到原媒体旁边。

### 方案：整条流水线交给主进程，Agent 只在开始前和结束后出场
1. **开始前**：Agent 一次问清缺少的决定——目标语言与双语顺序、翻译资料、导出格式（默认按来源）、保存位置（原文件旁）、同名文件是覆盖还是自动编号。
2. **提交**：`prepare_studio_transcription` 新增 `translation`（目标语言、要求、资料选择）与 `export`（格式 `auto`/具体格式、内容 `bilingual`/`target`/`source`、双语顺序、冲突策略）。只有用户要求时才启用，确认卡片写明全部配置。
3. **执行（无需 Agent）**：每个文件转写完成 → 主进程立即翻译 → 翻译完成 → 主进程导出到源文件旁。只转写不翻译时，转写完成后直接导出原文。
4. **结束后**：渲染进程跟踪这批任务，全部到达终态（导出成功/失败、翻译失败等）后上报界面事件，Agent 自动汇总：成功导出了哪些文件、哪些失败及原因。

### 持久化
- 文档快照新增可选的 `automaticExport`：`{ spec, state: 'pending' | 'exported' | 'failed', fileName?, error? }`，与 `automaticTranslation` 并列，在文档创建时写入。
- 有自动翻译时，在该意图对应的翻译任务完成后导出；没有时在转写提交后导出。翻译失败则导出保持 `pending`，由 Agent 汇报。
- 文档摘要带出导出状态，供工作台列表、`list_studio_documents` 与流水线跟踪读取。

### 导出默认格式（V12）
- 共享函数按显示名的扩展名判断：音频（wav、mp3、m4a、aac、flac、ogg、opus、wma）→ LRC；视频与未知 → SRT。主进程的自动导出（`format: 'auto'`）与工作台导出对话框共用。

### 取舍
- 不用定时轮询让 Agent 推进：每一步都要消耗模型调用，且 Agent 不在时就停摆。主进程已经持有意图与源位置授权，流水线放在主进程最稳。
- 需要确认的导出问题（如有损转换）在自动导出中按“跳过/原文回退”处理：`incomplete: 'source-fallback'`，阻断性问题记为失败并汇报，不静默丢内容。

- 渲染进程：`controller.enqueue({ autoExport })` 只作用于本批；`prepare_studio_transcription` 新增 `translation`（目标语言、要求、资料集/方案）与 `export`（格式、内容、顺序、冲突策略）。本批启用的自动翻译在提交或取消后恢复为用户原来的工作台设置。确认卡片写明整条流水线（“每个文件转写完立即翻译为中文，再导出到原文件旁 · 音频 LRC / 视频 SRT · 双语 · 同名时自动编号”）。
