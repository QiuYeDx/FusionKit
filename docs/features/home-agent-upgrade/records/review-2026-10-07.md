## 记录

### R1 / R2（完成）
- 新增 `src/agent/runtime/optional-parameters.ts`：按 endpoint+model 记忆被 400 明确拒绝的可选参数（`temperature`、`include`），只在首个请求、尚无输出与工具执行时重试，避免重复副作用。
- Responses：请求带 `include:["reasoning.encrypted_content"]`；无 `encrypted_content` 的 reasoning 不回放，同步骤 function_call 去掉 `id`、assistant message 以文本回放；历史轮次的 function_call 不再带 `id`。HTTP 错误读取 `error.param` 并保持密钥脱敏。
- Chat Completions：`streamWithTemperatureFallback` 在首个事件为“temperature 不支持”的 400 时去掉该参数重启一次。未改为按模型名猜测，避免误伤支持 temperature 的同名网关模型。
- 环境：`node_modules/.pnpm/@ai-sdk+provider@3.0.8` 包目录为空导致相关测试无法加载，按 lockfile 重装该包后恢复。
- 验证：`vitest run src/agent/runtime` 34 项通过；`tsc --noEmit` 通过。官方接口实测未做。

### R3（完成）
- 根因：main 的 `registerRecoveredTaskBatch` 每批都消费目录 draft，renderer 无法复用，只能每批重新弹选择器。
- main：`RegisterRecoveredSubtitleTranslationTaskBatchRequest.retainDirectory`；`prepareRecoveredTasks` 在按批次（非 candidateIds）且本批后仍有候选时保留 draft，最后一批照常消费；draft 仍受 30 分钟 TTL 与 owner 约束。
- renderer：`recoveryOutputDirectories` 按 `recoveryScanId` 记住本会话的目录令牌，后续批次直接复用；最后一批、prepare 失败、本轮取消、会话切换时撤销。工具描述与系统提示同步改为“每次扫描只选一次目录”。
- 验证：新增 main 多批次测试与 renderer 复用/会话切换撤销测试；`vitest run test/translation src/agent` 637 项通过、13 项跳过。

### R4（完成）
- 经典执行器、重命名 store 与 `services/name-translation/agentPlan.ts` 的中文/自由文本错误改为稳定错误码（如 `translation_input_selection_cancelled`、`rename_plan_expired`、`scan_failed`），原始细节放入 `data.reason` 等有界字段；IPC 原样返回的英文错误信息保持不变。
- `actionErrorMessage` 新增映射与四语言 `home:action_error_*` 文案；工具调用详情、经典结果卡片（失败时不再输出 JSON）、重命名预览卡片统一本地化显示。
- 顺带修正：重命名在提交后若因“计划过期/为空/预览后已变化/未配置模型”失败，属于确定未执行，不再标记为“结果未知、禁止重试”；结果未知时原始细节写入新增的 `errorDetail`。
- 失败结果跨轮回放时保留结构化 `data`（`toolFailurePayload`，Chat 用 `error-json`），否则模型下一轮只能看到错误码。
- 验证：相关 vitest 669 项通过、13 项跳过；`pnpm i18n:check` 通过；`tsc --noEmit` 通过。

### R5（完成）
- `orchestrator.ts` 正常结束不再调用 `interruptPlan()`；步数上限（循环内已处理）、响应不完整与取消/出错仍标 blocked。
- `AgentPlanPanel`：非流式时 `in_progress` 步骤显示 `CircleDot` + `home:plan_waiting`（四语言），流式中显示真正旋转的 `Loader2`（尊重 reduced motion）。原先 `Loader2` 并未旋转。
- 系统提示补充“等待用户时保留 in_progress 并写明等待什么”，放在 R8 一并修改。
- 验证：orchestrator 与 HomeAgent 测试 42 项通过（新增正常结束保留与中断标 blocked 两组用例）。

### R6（完成）
- `modern-tools.ts` `run()`：`ToolFailure` 原样返回；取消归为 `agent_cancelled`；其他异常仍返回 `tool_request_failed`，但附带 `data.reason`（脱敏 Agent/任务模型密钥、截断 600 字），并在会话未切换时写入 sessionLog（`source: modern_tool`）。
- 验证：modern-tools 38 项通过（原“密钥不得外泄”用例改为断言脱敏后的 reason 与日志）。

### R8（完成）
- `buildSystemPrompt()`：执行模式说明、计划、prepared-action 回执、经典执行确认与重命名计划合并为末尾的 “Current Application State” 段；其前的静态规则在不同执行模式与状态下逐字节一致，可被前缀缓存复用。同时补充 R5 所需规则（等待用户时保留 in_progress 并写明等待内容）。
- 未采用“把动态状态作为尾部 system/developer 消息插入历史”的更激进方案：部分 OpenAI 兼容网关/聊天模板要求 system 只能位于开头，兼容性风险高于收益。
- 验证：新增“不同模式与计划下静态前缀一致”用例，orchestrator 17 项通过。

### R7（完成）
- `HomeAgent/index.tsx`：整页改为 `useShallow` 选择所需字段（sessionLog 只取是否非空）；思考指示、流式回复与进行中工具调用抽为 `StreamingAssistant`，单独订阅 `streamingText`/`activeToolCalls`；流式 widget context 用 memo 固定引用；滚动跟随依赖去掉 `streamingText.length`（根节点 ResizeObserver 已覆盖内容增长）。
- 根因补充：每个 text-delta 都调用 `setStatus("streaming")` 并生成新 session 对象，单靠 selector 无法避免整页重渲；`setStatus` 在状态不变时返回原 state。
- `orchestrator.ts`：文本增量按帧（rAF，无 DOM 时 16ms 定时）合并写入 store；`flush()` 与结束清理前先排空缓冲，保证落盘文本完整。
- 验证：新增增量合并用例；agent/store/HomeAgent 测试通过，`tsc --noEmit` 通过。

### R9（完成）
- 新增 `src/agent/user-intent-authority.ts`：`userRequestedOverwrite`（含否定识别，中/日/英）与 `userMentionedDirectory`（只认用户消息中完整出现的路径，分隔符/大小写归一，允许与中日文直接相邻，拒绝前缀/父目录/根目录）。
- 转换/提取：`outputMode=custom` 时，`outputDir` 只有在用户亲自写过该目录时才采用，否则通过既有 `select-output-directory` 原生对话框选择（同一 scanId 的后续批次复用，会话切换清空）；取消则不创建任务（`output_selection_cancelled`）。
- 冲突策略：翻译、转换、提取、恢复翻译统一经 `resolveConflictPolicy`，`overwrite` 需最新用户消息明确要求，否则降级为 `index` 并在结果中返回 `conflictPolicyAdjusted`。工具 schema 描述与系统提示同步。
- 未改：转换/提取的 `filePaths` 仍可由模型给出（只读取并在源目录旁新建文件，默认不覆盖），保持既有大批量扫描工作流。
- 验证：新增 user-intent-authority 与执行器授权用例共 25 项通过。
