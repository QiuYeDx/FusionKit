# HomeAgent 运行可靠性需求

## 目标与范围

让 HomeAgent 的一次用户请求成为有明确归属、可取消、可解释终止的运行单元。保留 Chat Completions 与 Responses 两条兼容路径，为规划工具和扩展工具目录提供相同的执行边界。

## 范围外

不引入实验性模型能力、后台自主调度、多 Agent 产品功能或新的远程服务；不自动重试有副作用的工具，不因取消撤销已受理任务。工具任务精确确认、会话导入及界面由其他模块负责。

## 需求

### R-RUNTIME-01 隔离会话运行并可靠保存工具执行事实

| 字段 | 值 |
| --- | --- |
| 来源 | BR-01 |
| 状态 | active |
| 批次 | I1 |
| 优先级 | P0 |

#### 说明

当前实现依赖单个全局 AbortController，流事件直接写当前会话，工具调用仅在步骤结束时落入历史，且两种 adapter 的异常/步数终止行为不一致。本增量将 turn 身份、工具串行接纳、成对历史和上下文预算作为运行时约束，并使上限与异常具有明确结果。

#### 验收标准

- AC-RUNTIME-01-1: 在重复发送、用户取消、重置或导入会话与旧流事件交错时，同一会话只有一个活动 turn；旧 turn 的文本、工具结果、用量及 finally 不污染新会话或解除新 turn 状态；取消后不再接纳后续工具调用。
- AC-RUNTIME-01-2: 在工具已返回后流中断及长会话包含大工具结果时，已完成工具事实仍以完整 call/result 配对保留；未完成调用有明确中断结果；发送模型的上下文按完整消息组控制预算，并保留最新用户请求及当前执行约束，不制造孤立工具结果。
- AC-RUNTIME-01-3: 在 Responses 流提前结束、incomplete、无效参数、工具失败、取消或达到步数上限时，不把不完整响应当作可执行调用；两种 adapter 产生可观察的错误或终止原因，参数错误可通过工具失败结果反馈，且不会在上限后继续调用工具。

#### 边界与异常

已受理工具副作用不随聊天取消回滚；工具自身应在异步选择/授权后和副作用接纳前检查传入的 abortSignal。中断产生的未知结果不得描述为已成功或自动重试。过大最新用户输入不可静默裁掉其含义，应明确报上下文限制。重置与导入依赖 store session 身份变化，运行时不扩展其持久化语义。

## I2 复审需求

### R-RUNTIME-02 停止、确认上下文与可恢复归档

| 字段 | 值 |
| --- | --- |
| 来源 | BR-04 |
| 状态 | active |
| 批次 | I2 |
| 优先级 | P1 |

#### 说明
修复复审中有证据的实际运行缺口，契约及证据见 ../../records/review-i2-plan.md。

#### 验收标准
- AC-RUNTIME-02-1: 名称规划的停止信号贯穿 executor、批次、SDK 与 Responses fetch；取消不触发 fallback、retry 或后续批次，运行结束后输入恢复。
- AC-RUNTIME-02-2: 系统提示准确区分经典任务已入队与现代动作待确认；裁剪长历史后仍保留当前 pending ID/范围/状态的有界数据投影，且不因此绕过二次确认。
- AC-RUNTIME-02-3: 导出写文件前通过同一导入 schema 与 8MiB UTF-8 上限；成功文件可重导入，超限/非法不写入，保存取消和失败返回不同可读结果。
- AC-RUNTIME-02-4: Responses 完整输出中的 reasoning、message、function_call 在当前 turn 内按原序回传，再追加工具结果；不完整流不执行，密文受预算限制且不进入 UI、日志或持久化。

#### 边界与异常
不撤销已经受理的副作用，不自动截断归档，不恢复导入后的执行权限；单 turn 密文回传兼容性用合成协议测试验证，真实供应商验证另记限制。

## 约束
兼容现有工具输入 schema 与会话消息形状；不向模型传入 API key 或引入新的路径授权方式。上下文预算采用显式字符近似上限，属于产品保守边界而非 tokenizer 精确计量；使用配置常量与测试证明上限，不能声称模型精确 token 占用。共享 src/agent/types.ts、store、工具注册沿用集成负责人单写，I2 executor 由 runtime 单写。
