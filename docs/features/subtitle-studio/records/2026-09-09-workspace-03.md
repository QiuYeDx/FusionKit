## DeepSeek 默认配置跟进

用户随后用本地 `pnpm dev` 导入明确指定的 52 条日文 LRC，报告 DeepSeek 翻译失败并要求排查根治；这是本次修复及该文件同供应商复验的来源。只读检查失败文档快照：模型 deepseek-v4-flash、Chat Completions、thinking 字段缺失、每批最多 32 条、每批输出 4096、2 批计划、1 次尝试、0 批完成；实际输入 767、输出 4096，错误被归入 translation_protocol_invalid。

根因链：UI 从通用 ModelProfile 投影不带 thinking 设置，planner 原样使用；通用 adapter 只在明确指定布尔值时发 DeepSeek thinking，省略时由供应商默认决定。DeepSeek V4 默认启用思考，思考与正文共享输出上限。此前真实测试手工写入 thinkingEnabled:false，而 UI 测试使用非 DeepSeek fixture，导致通过证据没有覆盖生产默认。原快照不保存原始响应或 reasoning 内容，不能从总 output usage 推算思考的精确占比；输出达到上限、单次失败及修复后同文件结果共同支持该诊断。旧字幕工具的历史修复记录也说明其专门默认关闭该选项，但新版没有导入任何 v1 代码。

修复在新版 main 的规划入口统一默认值，在计算预算前为 DeepSeek Chat 缺省 thinking 冻结 false；保留显式 true/false，其他模型和 Responses 不变。预算、持久任务及执行使用同一配置。输出截断单独映射 translation_output_limit，明确提示调整批次大小或输出上限，不保存半批、不重复相同预算请求，已保存批次和真实 usage 保留；收到明确截断响应不再误记为未知执行。UI 沿用现有紧凑状态栏，仅修改错误映射和四语言文案。
