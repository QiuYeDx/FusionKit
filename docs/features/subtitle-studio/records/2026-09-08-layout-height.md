# 字幕工作台纵向空间修复

## 请求与基线

用户要求先提交推送已有代码，再优化截图中字幕工作台上下多余空白。T02 已提交为 `b8eac4c6df24e0dca2241bbc8e7d546edd14a158` 并推送 `origin/v0.3.1`，本次布局修复基于该版本，尚未提交。不推进 T03，也不据此声明 I1 完成。

## 实现

- 仅字幕工作台路由移除应用内容容器重复的 40px 顶部 padding；其他工具页保留原有规则。
- 工作台按视口扣除标题栏和底部导航空间，预览面板通过 flex/grid 分配剩余高度，替代阅读区多套猜测式 max-height。
- 文档库和阅读区分别内部滚动；预览头部、分页栏保持可见。窄窗口展开诊断时，正文区域允许滚动，保留至少 120px 阅读轨道。
- 文件名增加局部定位上下文，避免列表中读屏文本的绝对定位越过滚动容器裁剪范围。

## 实测

单位为 CSS px；顶部间距指标题栏底部到标题，底部间距指面板底部到导航容器。

| 实际窗口 | 顶部间距 | 底部间距 | 阅读区高度 | 外层溢出 |
| --- | --- | --- | --- | --- |
| 1280 x 860，修复前 | 64 | 92 | 310 | 0 |
| 1280 x 860，修复后 | 24 | 6 | 436 | 0 |
| 1106 x 756 | 24 | 6 | 320 | 0 |
| 786 x 540 | 24 | 6 | 148 | 0 |
| 786 x 861 | 24 | 6 | 469 | 0 |
| 1440 x 861 | 24 | 6 | 437 | 0 |

1280 x 860 下阅读区增加 126px，约 41%。导航内部另有 8px 顶部 margin，面板与可见导航胶囊约相距 14px。macOS 将请求的 900/1100px 窗口高度限制到当前屏幕范围，未宣称实际验证 1100px 高原生窗口。

## 可复用避坑记录

绝对定位的 `sr-only` 文本仍可能影响祖先 scrollHeight。当文件名没有局部定位上下文时，13 个文档可使外层页面多出 536px 滚动范围，即使文档库可见边界完全位于导航上方。让隐藏文本定位于对应文件名内部后，外层溢出恢复为 0。

排查时同时测量可见边界和真实 Radix viewport 的 `scrollHeight - clientHeight`，并检查隐藏绝对定位子元素的包含块。避免用全局 overflow-hidden 掩盖问题，避免只凭截图或容器边界断言滚动已受控。对应回归为 `vertical-layout.test.ts` 的长文档库断言。本轮 `.agents` 目录为只读，经验先保留在此记录中。
