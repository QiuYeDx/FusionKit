## 必要修复与失败处置

- 新版 export-service 测试只用 `/` 匹配临时文件，Windows 的 11 个故障注入未生效。匹配两种分隔符后原始失败/回滚/删除并发断言通过，没有修改导出生产逻辑。
- 旧授权测试创建 64 GiB 超限文件时，NTFS 实际分配导致 ENOSPC。先将测试文件设置为 sparse，再保留真实超限大小及拒绝断言。
- POSIX chmod 不可执行验证只在支持该权限语义的平台运行；Windows 明确跳过，不改为通过。其他运行时验证保留。
- 旧模型 move 有真实 Windows 实现问题：unlink 后最后一个句柄关闭时 NTFS 再次更新 ctime，原逻辑误报 model_corrupt 并恢复源文件。仅在该关闭时点检查相同文件对象/内容属性，重新验证固定模型 header/size/SHA-256，再固定完整身份并删除隔离链接。未全局忽略 ctime。既有 4 项移动/回滚失败修复；新增复核拒绝反例证明源文件保留、删除钩子不被调用、受管副本回滚。代价是 Windows 的显式 move 在删除源文件前增加一次流式完整校验，copy 与转写流程不增加该开销。
- 新版崩溃恢复测试原先只杀 Electron 主 PID，Windows 子进程可能继续持有 profile 单实例锁。测试改为杀死该测试拥有的完整进程树并等待 close；生产进程退出策略未改动。
- 移除演练脚本原写死 `/private/tmp` 和 POSIX 命令 shim。改用 OS 临时目录、显式 UTF-8、Windows junction 和 Node 脚本入口；遍历清单排除依赖 junction，并移除新增旧工具验收测试。共享控件扫描统一相对路径分隔符；保留工具的真实消费者清单不变。
- 最终临时构建曾因 8.3 路径与长路径混用失败：Node `realpathSync` 保留 ADMINI~1，`realpathSync.native` 才得到长路径。修正验收准备脚本的 cwd 后完整重建通过。一次依赖验证被过早派发到失败构建，三个 UI 失败只作为无效中间运行记录；不计入验收。最终通过记录必须来自 build exit 0 后的运行。
