# 字幕工作台：独立新版工具

日期：2026-09-08。工作名称：字幕工作台 / Subtitle Studio。工具身份 `subtitleStudio`，建议路由 `/tools/subtitle/studio`；这是新增入口，不改变现有入口的含义。

## 本轮结论

用户已认可统一字幕文档的方向，并授权实施独立新版 I1；现有工具作为 v1 保持可用，未来删除 v1 不影响新版。当前已完成文档链路、持久化/权限、文本翻译、双语导入解释/清轨、任务恢复/取消和多模式导出；独立移除构建的实际 Electron 链路通过。既有 TypeScript、i18n 与五项路径断言失败已修复；I1 整体验收仍待补齐旧工具真实转写/历史恢复等证据，不实际归档或删除旧工具，不开始原生转写移植。

新版采用独立的领域模型、持久化、IPC、前端状态、执行队列、原生运行时与资源归属。字幕文件和本地转写都是文档的生产者；翻译写入译文轨；导出读取指定文档版本，不消费一次性的翻译结果字符串。

转写采用有来源记录的代码副本：先冻结现有生产实现及其依赖、默认值、原生资源和回归证据，复制后验证等价，再通过适配器输出新文档。不能只复制 Whisper HTTP 调用，也不允许新版运行时回调 v1。

## 换机器接续

本轮设计推送到 `v0.3.1` 分支。另一台机器先保护其未提交改动，拉取该分支的最新提交，在仓库根打开 Codex，按上方阅读顺序恢复上下文，不依赖本次聊天自动出现。

- 仓库文档、源码和已经跟踪的 `.agents/skills/fusionkit-pitfall-guard/` 随 Git 同步。
- 本机用户级 `spec-driven-ai-coding` 技能和它的 checker 不在本仓库，需要另一台机器已有或另行安装同版本。没有该辅助脚本时，可依本仓库明确的 R/AC/T/V、依赖、写集、授权及证据规则人工核验并记录“checker 未运行”；不要将工具缺失写成业务需求缺失，也不要冒充脚本通过。
- Codex 模型/推理设置、个人配置、连接器权限、API key 和应用偏好不由这次 Git 提交迁移。为减少行为差异，尽量使用相同模型和推理设置；不要把密钥提交到 Git。
- `node_modules`、构建输出、`test-results` 和本机受管原生资源不由 Git 同步。按 lockfile 安装依赖，按目标平台准备环境；I1 不要求先复制所有原生模型，I2 的真实转写对照需要另行准备模型和限定样本。
- 文档中的 Windows 绝对路径是历史环境记录，源码落点按仓库相对路径解析。新平台重新运行适用验证，不复用旧机器的通过结论。
