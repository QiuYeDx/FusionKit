#### 说明

从实际已集成的 Git 提交冻结完整来源，覆盖主进程转写与生命周期、领域/IPC 类型、有效用户配置、原生资源 manifest/许可/构建脚本、相关测试及其 fixture。明确生产入口的传递依赖、应用组合层、需要替换的旧导出/交接边界和不采用的实验代码，记录拟议目的路径及理由。

#### 验收标准

- AC-TRANSCRIPTION-01-1: 对固定提交生成清单，两次结果逐字节相同；每项包含来源路径、Git 对象身份、内容 SHA-256、用途及拟议处置；缺文件、未解析的相对依赖和重复目的路径不能静默通过。
- AC-TRANSCRIPTION-01-2: 清单覆盖实际生产代码的相对/别名/type import 依赖和测试/脚本所需 fixture；应用组合层仅作为来源证据，不复制整个旧前端；动态加载、原生字符串和非代码资源边界有显式核对记录。
- AC-TRANSCRIPTION-01-3: 有效默认值、引擎/模型/VAD/CUDA 与平台 manifest 身份可追溯到冻结源码或资源；未存在的新副本 hash、原生推理结果、发布许可及平台通过结论不得伪造。
- AC-TRANSCRIPTION-01-4: 检查器可以发现已登记文件内容变化、遗漏和清单篡改；冻结历史提交后仍可重新校验；运行过程不执行旧业务模块、不读取真实 userData/模型/音频、不启动服务、不改源文件或依赖锁。

#### 边界与异常

Git blob 是跨 Windows/macOS 的字节身份；工作树状态核对遵循 Git 的换行规范，单独说明与历史提交验证的区别。大模型及未跟踪二进制仅记录可信 manifest 中的预期身份，不声称本机已验证实物。原生 C++、脚本和运行时字符串必须人工审计，AST import 图不能证明全部运行依赖。

#### 验收标准

- AC-TRANSCRIPTION-02-1: 从T01固定Git来源生成副本与实际provenance，每项记录源/目标内容hash及精确变换；只调整依赖路径、独立命名空间和必要测试定位，不调推理、句界、重试、增益、窗口或默认参数。重复检查可发现手改/缺失/目标冲突，默认不覆盖不同内容的目标。
- AC-TRANSCRIPTION-02-2: 新版生产源码及正常回归不import/type-import/调用旧业务或读取旧资源/测试helper；默认资源解析只指向新版根，IPC与权限实例独立。尚未复制的原生构建、真实资源及组合入口在provenance中明确递延，不用历史hash冒充新版运行或签名通过。
- AC-TRANSCRIPTION-02-3: 隔离迁移harness用同一固定响应、窗口、配置和增强响应运行冻结旧实现与新版副本，严格比较完整transcript、时间/词级证据、请求计划、窗口和回退/重试。覆盖fixed与acoustic、低音量原音回退/反例、合法重复与未知句界、跨窗重叠、CUDA f16 DTW资格及不合格路由；每类同时断言预期路径，不能只证明两边同样输出。
- AC-TRANSCRIPTION-02-4: 双方用真实构造/验证流程签发代表性的backend、accelerator、batch runtime及PCM/window凭据，本侧正例成功，对侧凭据被拒绝；不能用关闭brand验证的fake harness证明独立性。
- AC-TRANSCRIPTION-02-5: 新版确定性回归、实际依赖边界、TypeScript与既有I1回归通过；旧来源工作树对照无漂移。迁移对照可在独立维护测试中读取冻结Git到临时副本，但业务/正常测试不得依赖迁移工具或旧Git副本。副本尚不注册到产品入口，不声明用户已可转写。

#### 边界与异常

模型/VAD/CUDA上游内容身份保留，许可证及来源回执保留原字节与历史事实。只复制声明和预期身份，不生成伪造ready资源或使用v1安装目录。native addon命名空间与签名改动必须在后续重建后获取新hash，T02不加载旧实物作为新版证明。旧model-manager的move能力仅可暂留在未注册机械副本供继承验证，后续新版模型导入只允许copy，不能删掉用户选中的旧模型。

#### 验收标准

- AC-TRANSCRIPTION-03-5: 在当前macOS arm64主机真实编译新版addon、先最终嵌套ad-hoc签名再冻结hash，并在独立Electron进程加载/验证原生事务与恢复。Windows源码/契约静态覆盖但未实跑的平台明确待验；新普通回归、T02回放、真实依赖边界、两套TypeScript、i18n及旧来源无漂移通过。所有任务启动进程清理；不把ad-hoc测试当作发布签名、真实ASR或完整应用打包验收。

#### 边界与异常

本阶段只对隔离测试文件执行原生事务；不触碰真实用户文件、模型或安装。允许在本机测试目录生成新版原生实物和回执；跨平台实机、完整共存/删除后应用包和真实模型推理后续统一验收。T02精确副本保持可重建，外围新增组合层不要求删除历史证据或允许任意副本漂移。

#### 验收标准

- AC-TRANSCRIPTION-04-1: 新媒体文档采用明确版本和媒体来源、转录时间证据及结构化preservation；旧schema1字幕文档继续读写。完整canonical transcript与cue按原顺序一一对应，精确保留文本/起止和所有已存在word/probability/speaker/confidence/estimatedTiming、语言及model证据；不制造未知字段、媒体内容hash或SRT往返。
- AC-TRANSCRIPTION-04-2: 文档承接上限保持100000 cues及128MiB快照；100001条、字节/词数越界、非法时间或重复id明确拒绝并无文档发布；不截断、自动拆分、合并或重算时间。媒体transcript摘要明确为转录内容摘要，未复制媒体则无原媒体导出能力。
- AC-TRANSCRIPTION-04-3: 独立派生executor保留T02推理/窗口/后处理及brand逻辑，最终清理成功后返回完整transcript，文档生产者再释放batch pin并提交；输出目录/文件exporter不参与。来源变换可重建，T01/T02机械副本不改。回放证明最终transcript一致；失败/取消/清理失败不能调用sink或伪造artifact成功。
- AC-TRANSCRIPTION-04-4: main-only sink绑定逻辑operation及owner/generation、单次文档身份，提交前校验取消/有效性，同一操作并发收敛且内容漂移拒绝；失败可安全重试、已发布文档不因迟到取消伪报未提交，已删除文档不可重放复活。持久层发布后故障明确区分提交状态/持久性，不吞错误冒充完全持久化。
- AC-TRANSCRIPTION-04-5: 媒体文档可持久化重开、分页/翻译并投影为SRT/LRC，完整转录证据不随翻译改变；原字幕文件专用导出/双语拆分明确拒绝媒体，投影损失可观察。既有I1和T02回归、实际边界、两套TS/i18n、规格检查及进程清理通过。内部生产者验证不代表真实ASR或转写UI已经上线。

#### 边界与异常

当前不扩容已有文档和翻译检查点、不自动拆分长文档。发布前取消应无可读文档，提交边界之后取消只能阻止迟到事件交付，不回滚已提交结果；持久性未知须保留同一文档身份供重试核对。重启任务自动恢复、用户媒体授权和完整runtime任务调度后续接入，不声明跨重启网络/推理exactly-once。
