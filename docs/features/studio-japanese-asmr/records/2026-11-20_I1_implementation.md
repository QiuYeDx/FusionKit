# 日语 / ASMR 转写实现与实机试用

2026-11-20。用户确认本轮交付完整功能，素材质量对照和盲听延后，随后在 Windows 11 CUDA 设备上试用。

## 实现

- 「字幕工作台 → 转写」提供标准转写和日语 / ASMR 模式，分别保存模式与设备选择。日语 / ASMR 显示两项资源状态和固定日语输出，保留选轨、自动翻译及导出设置。
- 共享资源管理通过现有下载安装事务验证并安装固定版本的 ONNX 模型。CPU 打轴运行在独立 Electron 进程中，完成或取消后回收。逐句识别复用 Anime Whisper 模型和 Whisper 服务租约，设备可选 CPU 或受支持的 GPU。
- 当前试用参数为 30 秒速窗、5 秒重叠，交界采用离窗口边缘更远的预测。起止概率阈值分别为 0.50 和 0.35，最短语音 100 ms，闭合停顿 180 ms。短间隙合并以 8 秒为目标，解码边距最多各 120 ms 且不跨邻句，解码总长度上限 20 秒。过长且没有可靠停顿的区间保留为待听校。
- 打轴生成原媒体时间，识别仅返回正文。待听校区间支持分页。部分结果生成可编辑文档。默认不阻断自动翻译和导出，设置里的「待听校时暂停自动步骤」开启后才跳过。待听校列表可跳转到文档对应行。整条任务完成后可以打开文档、听校、编辑或手动导出。

## 验证

- macOS arm64 / Electron 41.10.6 通过实际构建的应用验证两个固定模型。34 秒双音轨文件选择第 2 轨，CPU 打轴与 Metal 逐句识别生成日语字幕 `00:00:26.320 → 00:00:32.740`。读取文档确认音轨、时间与日语正文，并通过工作台导出 SRT。
- 500 秒合成静音在「正在打轴」时通过界面取消，任务返回取消状态且无文档和待清理标记。
- 在实际 Electron 检查了 1280×800 浅色缺资源状态、资源对话框、1024×700 深色窄窗和转写结果。模式选择可以通过键盘打开，切回标准后原参数恢复。待听校和部分结果自动化由任务服务测试覆盖。
- TypeScript、Vite 构建、预加载隔离、四种语言的翻译检查、共享资源来源以及工作台依赖边界通过。13 个打包契约测试通过。真实 Windows 安装和 CUDA 使用待目标机验证。
- 最终专项测试通过 1,138 项，包含 23 个标准转写对照回放。扩展测试中单句音频与加速包管理的失败已在改动前基线复现。
- 功能测试证据保存在本地忽略目录 `test-results/studio-japanese-asmr/`，其中 `full-app-result.json`、`full-app-cancel.json` 和 `asmr-check.srt` 对应上述两条任务。

## Windows 11 试用

1. 使用包含本次提交的应用。源码构建沿用仓库现有的 Windows x64 原生资源准备流程和 pnpm 8.7.0。打包钩子要求 Windows x64 宿主。
2. 打开「字幕工作台 → 转写」，将「转写模式」设为「日语 / ASMR」。在「管理资源」下载 **Whisper VAD EncDec ASMR**、**Anime Whisper** 和 **CUDA 加速包**。打轴模型约 119 MB，逐句识别模型约 818 MB。
3. 「处理设备」选 **NVIDIA GPU（CUDA）**。任务行的设备标签应显示 CUDA。打轴固定在 CPU 上运行。
4. 选择媒体和日语音轨，开始转写后打开生成的字幕文档。若任务显示「待听校」，可查看区间并对照原音轨复核。
