# 导入资料的批量审核

## 问题与行为

用户导入 ASMR 知识包后，数十至上百条候选只能逐条打开详情采纳。主进程已经提供多 ID 原子审核，但列表未暴露批量入口；导入页的 `adoptReady` 也不能处理候选。

本次补齐现有资料与新导入资料的审核流程：

- 导入成功后进入待确认列表，显示明确的导入结果。
- 待确认页按资料集、条目类型和文本筛选；普通资料列表也有批量审核入口。
- 可勾选单条、选择本页、选择全部筛选结果（跨页）、清空选择。筛选变化会解除选择，不把隐藏条目混入操作。
- 批量采纳／拒绝先展示冻结的所选内容，术语双列对照，来源和适用范围折叠；可在预览取消个别条目。
- 强制术语、强制要求、核心背景沿用逐条采纳要求；已归档依赖等不可用条目显示原因，不阻止其他可处理条目。
- 审核一次提交到现有事务接口，保留 revision／digest／本机人工采纳记录和使用范围。重复同状态操作不再无意义地增加修订号。
- 版本冲突时保留原选择，通过明确刷新重新核对；只重新读取原有 ID，不自动添加后来出现的资料。写入失败保留选择，整个事务可重试。

没有将外部候选自动视为已审核，没有改写资料文件协议，也没有修改用户现有资料库。

## 实现与审查

`review-policy.ts` 统一主进程与界面使用的逐条确认和归档依赖判定；后端仍独立校验，界面筛选不构成授权。列表选择绑定筛选范围和资料库 generation，审核弹窗冻结 snapshot 和 IDs。

复用 `KnowledgeRecordDialog`、Checkbox、Choice、Pagination、KnowledgeDisclosure。初版截图发现预览重复标题占用较多纵向空间，改为术语双列与紧凑元信息，并使用现有弹窗的固定操作栏、错误自动定位与焦点处理。中、英、日、繁体文案同时维护。

## 验证

- 单元和服务测试覆盖百条候选原子采纳、拒绝保留数据、同状态重试、失效 ID、过期 generation、写入失败重试、强制条目排除与刷新后的身份范围。
- 新增 `bulk-review-electron.test.ts`，使用隔离临时资料库导入 101 条候选。覆盖按集／类型筛选、本页和跨页全选、取消个别条目、审核时新增资料造成冲突、刷新重查、99 条批量采纳、1 条拒绝及保留未处理内容。
- 原生截图：`test-results/knowledge-bulk-review`，中文浅色 1280×860、英文深色 820×700；等待加载层退出并检查弹窗与工具栏的边界。
- 运行默认 TypeScript、四语言 i18n 完整性及使用检查、Vite renderer/main/preload 构建和 preload 外部模块检查。

Windows 沙箱的构建器上级目录访问限制通过正常权限的本地构建／测试解决；不改依赖、不安装包。Electron 测试只使用本轮临时 profile 并在结束时关闭，保留用户既有应用实例。

最终结果：111 项单元／服务回归与 1 项原生 Electron 流程通过，类型、四语言检查、构建及 preload 检查通过。原生流程实际采纳 99 条、拒绝 1 条、保留 2 条待确认，后来新增的条目未被混入采纳，页面运行错误为零。已检查宽屏浅色、窄窗深色、来源展开与冲突提示截图；冲突文案统一为在当前弹窗刷新核对，避免旧的“关闭重开”提示与恢复按钮矛盾。
