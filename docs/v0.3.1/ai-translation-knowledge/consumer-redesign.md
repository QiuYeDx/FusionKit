# 翻译资料与字幕工作台：面向日常使用的重构

日期：2026-09-18。实现基线：`d1cc07e`。

## 目标与授权

用户要求参考 `../refference/产品设计优化讨论记录.md`，先形成设计，再实际重构翻译资料模块及工作台使用流程。本文记录本轮设计、取舍和验收，实施进度见 [consumer-redesign-tasks.md](consumer-redesign-tasks.md)。已有 V3/FK-TK/1 协议、来源与冻结执行约束继续适用；本轮交互以本文为准。

核心用户任务是「写下一条固定译法 → 在字幕里选用 → 知道是否纳入 → 发现缺少的译法时就地补充」。不要求用户先学会对象、采纳、风格、方案和执行计划。本轮连续设计与实现已由上述用户请求授权，内部可逆设计决定由实现者完成。

## 现状与建议取舍

讨论记录基于较早提交，其中右侧常驻说明已经在 `8512e20` 改为 Tour，但教程没有改变核心操作成本。源码确认以下问题仍存在：

1. `model.newEntry()` 将资料集关联对象/浏览对象复制为 `requiredSubjects`；仅选资料集不足以使用该条目。
2. `EntryEditor` 默认不采纳，编辑已可用内容后直接保存会回到候选。
3. 页面首先呈现分类与筛选，正文内容被对象、管理视图和多种状态分散。
4. 工作台使用资料需开关后进入另一层翻译弹窗；本地检查变成强制的独立步骤。
5. 同维度自由文本要求被误判冲突；两条互补要求也可能被排除。

采纳资料集为中心、显式保存并应用、简洁录入、批量粘贴、工作台同面板选用、检查融入启动、同文档复用和就地记住译法。现有数据模型与执行服务有价值，不重建数据库，不批量清空旧条件，不把已有导入候选自动采纳。

本轮不增加 AI 自动提取、表达/参考译文执行、自动学习或云同步。它们需要独立的执行与可信来源设计；现有表达/参考译文仍能查看、整理、导出，但不占主要新增入口。自由文本没有可靠的互斥结构，不做未经验证的语义冲突检测。

## 一、资料页：维护资料集里的内容

```text
翻译资料                                 帮助   新建资料集

我的资料集            游戏 B                         编辑资料集
全部资料              日语 → 简体中文
主播 A
游戏 B [选中]         固定译法  背景说明  翻译要求
通用规范              搜索                    批量粘贴  添加译法

待确认（有内容时）     原词             译法              操作
归档                  checkpoint       存档点            编辑
                      save slot        存档槽            编辑
更多管理
导入 / 导出
前往字幕工作台
```

- 资料集直接显示名称与数量，点击即切换正文。全部资料、待确认和归档是可辨识视图。对象、方案/风格、来源/历史和维护放入次级管理区域，保留可达性。
- 选中资料集显示名称、翻译方向及编辑入口。默认内容分为固定译法、背景说明、翻译要求，展示实际内容；版本、来源、条件、采纳细节进入详情。已有其他类型在次级入口查看。
- 新建资料集默认只问名称和翻译方向；描述、关联对象为可选设置。创建完成选择新资料集；从添加内容发起时继续录入。全部资料下新增必须明确目标集，不能静默写入第一个资料集。
- 高频录入只要求原词/译法，或一段背景/要求。条目名称可由内容生成。术语匹配模式、别名、强度、来源和真实使用条件收在高级设置；存在限制时明确标示，不能因折叠而隐藏实际生效条件。
- 手工维护主操作为「保存并应用」，通过现有 `saveRecord({ adopt: true })` 原子保存并确认新修订；次操作「保存草稿」。提示仅影响之后选用该资料的新翻译，不修改已生成译文。归档条目不因普通编辑自动恢复。
- 新条目可保留分类关联，但 `requiredSubjects` 默认为空；用户明确设置的旧条件和新高级条件原样保留。
- 批量粘贴接受 TSV/CSV 与表格复制数据，先展示可编辑预览，阻止缺列、空值、超限和歧义格式；确认后逐条保存并应用。现有 IPC 没有批量事务，必须保留每条保存结果与最新 generation，部分失败不重发成功条目，显示剩余内容并允许重试，不能伪装整批原子成功。
- Tour 保留为可跳过的操作定位，按新主流程更新锚点与文案，不承担替代可理解界面的职责。

## 二、工作台：资料是翻译配置的一部分

```text
翻译字幕 / 批量翻译
模型                目标语言
原文语言（选用资料时确认）
本次资料     未使用资料 / 已选资料集名称       选择 / 清空
本次翻译要求

资料范围与检查结果（有资料时）
可用内容、未使用原因、需要处理的冲突          查看详情
更多设置：预算、资料限制、片段范围

保存本次设置 / 沿用上次设置          试译几句   开始翻译
```

- 去除「使用翻译资料」前置开关及嵌套的第二个翻译弹窗。未选择即不用资料，已选择名称始终可见，可清空。资料选择器是轻量配置区域，不拥有另一套翻译流程。
- 单文件全文、片段试译和批量保持各自真实执行 API，共享选择、目标语言与本次要求语义。父面板是模型、目标和预算唯一来源；不因临时无效输入卸载资料草稿。
- 点击开始/试译时在本地生成并校验新计划；成功才用该计划执行。检查失败留在当前面板展示原因，不回退普通翻译。单独查看检查仍不请求模型；任何模型请求必须来自明确启动动作。配置或资料变化使旧计划失效，异步结果需校验当前身份，不能启动过期结果。
- 普通资料集选中后按语言、确认状态和命中规则使用，不要求再声明其分类。确有限定条件的旧资料展示限制与范围入口；多人资料不自动将某人物授权为所有字幕说话者。片段范围设置在当前面板内可达。
- 检查区区分实际纳入、正常未命中/未使用和阻塞问题；保留每条原因及冲突处理。不得用「已应用正确」代替「已纳入请求」。全文公开预览若只有计数，应诚实展示已有信息，并通过现有片段/执行记录提供具体内容，不能捏造逐句命中结果。
- 同一应用会话中，同一文档保留资料与要求；新文档默认无资料，可显式沿用一般选择和要求。跨文档复用清空说话者、逐句绑定和条件确认。最近草稿仅在内存保留，最多 50 份文档；需要跨应用重启复用时，通过「保存本次设置」保存为现有 recipe，优先从真实设置产生方案。
- 转写后自动翻译沿用同一种选择表达；仍在入队前冻结资料。旧持久化偏好 `enabled:false` 即使有残留 ID 也按未使用处理，不能升级后悄悄启用。无字幕时不声称已命中术语。

## 三、工作台就地保存固定译法

在字幕行提供「记住译法」操作，打开简洁录入表单；预填该行原文与已有译文作为待确认内容，并明确提示缩小到要固定的原词和译法。用户确认资料集、语言和词边界后才保存，不能自动将整句修改解释为全局术语。

翻译配置区提供「添加译法」轻量入口，可不离开当前字幕创建/选择资料集并保存。保存后刷新本地资料并使检查失效；是否选用新资料仍保持明确，不能自动选整个库。记录来源为用户确认的内容，保存与审批复用现有 service；不修改正在执行任务的快照。

## 四、执行与兼容性

- 保留 FK-TK/1 数据与导入格式；revision、digest、generation、来源、本地确认与冻结请求继续校验。
- 新规则策略允许同维度自由文本要求共存，不把文本不同视作矛盾。真实术语译法冲突、身份冲突、显式禁用与强制预算限制仍保持。
- 语义变化升级执行策略标识。旧已编译任务按其冻结请求验证/恢复，未知策略继续拒绝。旧自动翻译准备尚无请求，应按旧策略编译或进入既有明确重新检查流程，不能悄悄按新策略重算。
- 资料集纯展示改名/说明不应无故使全部已确认条目退出可用；是否可安全缩小失效范围须以真实依赖和回归证明，归档及语义变更仍保留失效处理。
- 经典字幕 AI 翻译器完全独立，不增加资料入口、模式或文件转交。

## 五、设计基准与状态

沿用 `fusionkit-ui-design`、`fusionkit-pitfall-guard` 和 `qiuye-ui-quality`。参照字幕工作台资料列表与既有 `ToolPanel`/`ScrollableDialog`，使用 `ToolDetailLayout`、`ToolPageHeader`、`ClipPathTabs`（rounded/sm）以及现有表单组件。中性主题、工具色仅用于识别；面板 12px、字段 16px、列间 16px，主区优先呈现内容，不新增宣传卡片。

桌面左栏约 220–260px，主区可收缩；820px 窗口仍保持可读内容、可换行的资料集名和固定可达的弹窗操作区；更窄窗口按共用布局重排。单条长文本只撑高自身，不让表头/全列表同步变大。列表支持键盘焦点，按钮有可访问名称，弹窗由共用组件管理焦点。

必须覆盖空库、首条内容、长名称、多条批量预览、部分保存失败、无模型、目标不匹配、未确认内容、旧限制、冲突、检查进行中、启动进行中与过期计划。失败保留输入，禁止双击重复写入/启动。真实 Electron 检查中/英、浅/深、1280×860 和 820×700，先等待 preload loading 完全退出，亲自审图并修复发现的问题。
