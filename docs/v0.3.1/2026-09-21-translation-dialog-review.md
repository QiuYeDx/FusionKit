# 翻译配置与检查反馈布局

## 设计

- 翻译字幕、批量翻译的头部仅保留标题与关闭按钮。52px 高度、12px 外围留白、28px 关闭热区，标题与关闭按钮垂直居中。
- 文件名或批量范围摘要移到正文首行，与“复用设置”共享横向空间；完整文件名仍可通过 Tooltip 读取。批量文件列表保留独立展开入口。
- 资料卡片的标题、摘要属于同一内容列，固定顶部 12px 留白与 8px 阅读间距。操作按钮独立顶对齐；窄卡片换行，不通过缩小按钮热区取得对齐。
- “检查与用量”立即打开独立的 560px 可滚动弹窗，检查中、结果、问题和重试均在同一位置。正文不再静默追加结果。三项用量指标允许长标签换行；返回设置保留表单与滚动位置。
- 检查成功可在结果弹窗开始翻译；部分文件可用时仍需明确开始可用文件。既有草稿身份、计划过期、资料版本和提交权限检查保持有效。
- 片段检查与试译沿用同一结果弹窗。完成或部分试译可无请求重新查看；“重新试译”是独立明确的动作。检查期间返回会撤销试译意图，已经发出的试译正常取消并可查看返回的部分结果。
- 主动取消试译会清除旧检查计划，并忽略该次取消造成的晚到异常，避免把取消显示成权限失效；实际提交仍由当前会话的计划凭据控制。
- 普通用量检查期间可以返回设置，晚到结果不主动重开浮层；检查本身不发模型请求。只有顶层弹窗消费 Escape，关闭后恢复对应入口的焦点。

## 验证与边界

通过项目 UI 设计规范与 qiuye-ui-quality 的渲染自检流程，对中文浅色宽窗、英文深色窄窗中的单份、批量、空资料、已选长名称、检查加载、错误与结果分别观察截图和实际几何关系。

业务验收复用隔离 Electron profile、生产 preload/IPC/资料仓库及本地测试模型服务。另用受控 IPC 回包验证检查中的关闭、晚到计划与错误重试。测试模型请求不连接外部付费服务。

真实依赖边界检查发现上一轮跨工具无内容验收的 classic fixture 被放入 Studio 专属目录；已将跨工具测试及注入实现迁至 `test/integration/`，Studio 构建器只保留通用测试插件参数，没有放宽架构规则。

- 生产渲染器构建、TypeScript、preload 依赖检查、四语言完整性与文案引用检查通过；Studio 架构边界扫描 506 个文件，无错误。
- `translation-session` 与资料 UI 模型共 23 条单元测试通过。
- 共 16 条 Electron 场景通过，覆盖普通/资料翻译、批量、自动资料、试译、配置复用、翻译恢复、双语导入、结果反馈、导出与四语言兼容，以及下述双工具空转写验收；模型服务仅使用本地测试服务器。检查关闭后的晚到成功/失败回包另使用受控 IPC 返回验证。
- 移动测试目录后的双工具空转写集成验收在中文浅色、英文深色各通过一例。
- 实际截图保存在 `test-results/translation-knowledge-materials-layout/` 与 `test-results/translation-knowledge-trial/`。已人工检查窄窗长标题、用量标签、加载、错误、批量结果及试译对照，修正用量截断和背景重复错误提示。
