# 第二批：翻译时间轴锁定与 ASMR 验证

规模 M，沿用本目录设计/实施台账。角色为模块开发与验证；用户连续确认推进，承接首批记录的后续范围。本批完成代码与自动验收后报告真实素材听校的剩余限制。

## 需求与设计

- P2-01：模型仅翻译文本。解析当前 SRT 块 / LRC 行，建立分片内稳定 `cue-1`、`cue-2` ID。完整身份由 checkpoint 的任务、分片 sourceHash 和本地序号共同确定；ID 只在本次请求中有效，重试/同源恢复保持不变，不把模型 ID 当授权凭据。
- P2-02：统一请求 JSON 文本 `{ "cues": [{ "id": "cue-1", "lines": ["source line"] }] }`，响应同结构但 lines 为目标译文。拒绝缺失、多余、重复 ID，行数不匹配、空译文和嵌入换行/时间标签等结构注入。允许响应数组乱序，由程序恢复源顺序。无需供应商专属 JSON API 能力；只允许整体 JSON 或完整 JSON 代码围栏，不从任意解释中捞取局部结果。
- P2-03：程序重建 SRT 编号、时间轴和 LRC 时间/元数据标签；双语原文也从源文件复制。支持 SRT 多行、重复编号，LRC 重复时间、多时间标签、元数据、空白行。增强型 LRC 内联词时间标签暂不支持，明确拒绝而非静默损坏。新协议的格式校验失败复用已有单一有界重试；无须调用模型的元数据片直接原样提交。
- P2-04：恢复前检查已完成片的结构，符合规则的旧片保留；不符合规则的片重新排队，原译文保留在 checkpoint 字段中直到新结果替换，但 pending 状态不允许其进入上下文/最终输出。不将旧片伪称为新协议验证产物。请求和估算继续共用构造器，输出估算改为目标译文和 JSON 开销（双语原文在本地复制）。
- P2-05：只读复核已有 30 秒切片，使用独立进程重复与连续请求对照检查服务状态影响；基于明确来源的 VAD 候选区间计算长停顿跨度和候选覆盖诊断。诊断不能等同人工语音标注，不据此自动删除/添加文字或宣称召回改善。

假设：不改变用户配置面板和云模型设置，不发送真实私有素材到云服务。严格行数对应优先保障可验证的覆盖，模型不得自行合并原始字幕行。正文的语义误译、同 ID 下返回错误文字仍须语义评测，结构校验无法证明语义准确。

## 实施结果

- 模型请求已切换到 ID/文本 JSON 协议。SRT/LRC 输出由程序重建，双语原文不再依赖模型复述。允许数组乱序并按源顺序恢复，严格拒绝数量、ID、行数和结构注入错误；完整 JSON 代码围栏可接受。
- 每次 `parseResponse` 显式接收当前源分片，不在 translator 实例保存可变的当前 cue 列表；并发 worker 不会互相覆盖校验对象。
- 恢复时结构不合格的 resolved 片先转 pending，直到新结果通过校验。替换失败仍保留 checkpoint 旧译文字段，但该字段不作为上下文或最终输出使用。通过测试确认两次失败后的下一次恢复可替换旧片并给后续片提供新译文。
- 元数据片不调用模型。补齐 LRC 极小分片预算下的空白片合并，保留原空白行，避免空字符串被 checkpoint 当作未完成。
- 修复 SRT Windows CRLF 空行未按块分片的问题；运行时和估算同时采用相同边界。若旧 checkpoint 的分片边界与修正后不同，源文件模式仍遵守既有一致性检查；可使用保留源分片的恢复模式或明确重新开始，不能无声混合两套边界。
- 费用估算按目标译文与 JSON 开销计入模型输出；本地复制的双语原文不计入模型输出 token。实际账单仍按模型运行时报告累计，结构失败请求同样计费。

## ASMR：服务复用检查

在上一批工作区切片上额外做 10 次请求，源 NAS 不参与本轮实验写入或读取：

- A / VAD 关闭：两个独立进程的文本和原始边界 SHA-256 完全相同；同一进程依次使用当前 VAD、宽松 VAD、关闭 VAD 后，最后一次关闭 VAD 的结果不同于独立进程。
- B / 当前 VAD：同一进程连续两次一致；当前 → 宽松 → 当前的第一次和第三次也一致。因此不能把所有差异都归因为请求参数忘记恢复。
- 检查固定上游 commit `f049fff95a089aa9969deb009cdd4892b3e74916`：[server.cpp](https://github.com/ggml-org/whisper.cpp/blob/f049fff95a089aa9969deb009cdd4892b3e74916/examples/server/server.cpp#L782) 每次复制默认请求参数；[whisper.cpp](https://github.com/ggml-org/whisper.cpp/blob/f049fff95a089aa9969deb009cdd4892b3e74916/src/whisper.cpp#L7097) 关闭 VAD 的路径未重置前次 VAD 映射，时间戳 getter 仍依据该映射状态转换。这为观察到的跨模式时间轴差异提供代码层面的解释，但未证明全部文字差异都由该状态导致。
- FusionKit 生产 `beginInference` 已要求请求 VAD 模式匹配加载身份，加载身份变化时会回收进程；本次 51 项 serverSupervisor 回归通过。因而不把实验脚本可触发的跨模式问题宣称为生产流程中已复现的缺陷，也不无依据改动已隔离的生产生命周期。

本地实验产物在 `test-results/subtitle-quality-review/server-state/`，本次所属服务全部关闭。基准比较继续使用独立进程，未来设计无 VAD 补救时必须单独取得匹配加载身份的实例。

## ASMR：候选覆盖诊断

新增纯诊断模块 `speech-coverage-diagnostics.mjs`：合并重叠候选区间与字幕区间后计算候选覆盖，并分别报告字幕内部跨候选空隙、未被字幕覆盖的候选区间。缺失检测证据时返回 `unknown`，空候选的覆盖率为 `null`；不修改字幕，不输出“已证实静默/遗漏语音”等结论。

应用到上一批响应：B 当前组候选覆盖 100%，但一条字幕跨候选空隙 20,200 ms。C 当前组还有 520 ms 候选未覆盖；宽松组还有 2,000 ms 候选未覆盖。不同阈值的候选集合不同，因此覆盖比率不能直接当作不同方案的准确率排行榜，也不能证明这些候选中存在应转写的词。

诊断结果存于忽略目录 `test-results/subtitle-quality-review/coverage-diagnostics.json`。下一阶段补救前仍需听校 B 的长停顿和 C 的低声候选；VAD 判断本身不是独立人工真值。
