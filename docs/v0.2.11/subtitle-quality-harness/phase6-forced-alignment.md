# 第六批：固定原文声学对齐实验

- P6-01：在忽略目录的隔离 Python 环境安装固定版本 faster-whisper/CTranslate2，下载公开多语言 small 模型到工作区。使用 CPU/int8 对齐，不改已安装的 large-v3 或默认推理链。

实验依赖与模型仅位于 `test-results/subtitle-quality-review/phase6/`；源码脚本可在证实有效后整理为可复用模块。生产执行器、默认参数、正式字幕不变。若此候选不能满足负例检查，则保留证据并拒绝接入自动替换，不能用人为移动边界包装为成功。

### 验证中发现的听校记录缺口

旧页面默认前后各 1 秒，导出 schemaVersion 1 却没有记录播放设置。因此用户在 C-late-2 播放过程中听到尾音，不能直接归到标注 20.15–20.84 秒；默认实际请求范围是 19.15–21.84 秒。第四/五批将该备注当作标注框内的声学证据，结论过强，需撤回精确边界判断。

用户后续明确说明：逐片试听后，会按需要往前或往后听几秒，寻找完整的一句话，并没有将某项“前后文”设置作为标注标准。因此这些数据是自由试听的定性备注，不是逐词/逐帧标注；无需用户重填，也不将未说明的设置推定为默认值。

本批追加一个相关修复：听校页面明确显示关注范围与请求播放范围；按条目记录最近一次播放请求的范围、前后文、速度、开始/失败状态，并标为请求记录而非已听完的证明。导出升级为 schemaVersion 2，旧标注原样保留，缺失的历史播放证据保持未知。修改播放设置时停止当前区间，重播后使用新设置，避免导出记录与循环实际范围漂移。生成器允许经过数据集身份验证后嵌入旧标注，避免要求用户重填。

代码落点为 `scripts/local-subtitle/benchmark/listening-review.html`、`build-listening-review.mjs` 及其测试。此前自动浏览器已因本地 URL 策略拒绝该页面；本批不绕过限制，不把离线脚本检查当成 UI 验收。

## 选择依据

whisper.cpp 现有生产合同仅请求句级时间戳，VAD 压缩时间域的词级输出被明确丢弃；将 token 时间戳打开不等于固定原文强制对齐。

本地 FineSub 参考的 `fw_refine_backend.py` 使用 CTranslate2 相关对齐能力。实验采用公开的原版 faster-whisper/CTranslate2 路径，不运行 FineSub 的补丁后端，也不复制其整套 CUDA/PyTorch 依赖。

官方接口依据：[CTranslate2 Whisper.align](https://opennmt.net/CTranslate2/python/ctranslate2.models.Whisper.html)、[faster-whisper v1.2.1 的 find_alignment](https://github.com/SYSTRAN/faster-whisper/blob/v1.2.1/faster_whisper/transcribe.py)、[多语言 small 模型](https://huggingface.co/Systran/faster-whisper-small)。

## 固定文字实验结果

使用 faster-whisper 1.2.1 / CTranslate2 4.6.0 / CPU int8 / 8 线程；tokenizers 0.23.2、numpy 2.3.5。模型仓库 revision `536b0662742c02347bc0e980a01041f333bce120`，4 个文件合计约 486.2 MB，逐文件核对 LFS SHA-256 或 Git blob SHA-1，并保存 SHA-256 清单。没有下载 PyTorch 或替换 large-v3。

程序读取 mono PCM16/16 kHz，不拼接 VAD 片段；编码后直接给 `find_alignment` 传入固定文本 token，未调用生成或语言识别。词/token 对齐来自原版交叉注意力 DTW，未再套用启发式首词裁短、句边界偏移或字数比例分时。每例完整重建输入文字，并保留原始对齐词、token、概率及本地窗口原点。

| 用例 | 固定文字来源 | 对齐范围（原 30 秒切片内） | 发现 |
| --- | --- | --- | --- |
| B-original-full | 原当前组 ASR | 0–15.30 秒 | 文字被贴到用户描述为前段音效的位置；平均词概率约 0.075，不能作为修复 |
| B-alternative-full | 旧无 VAD 候选，未视为真值 | 0–25.26 秒 | 首字独占 0–23.56 秒，平均词概率约 0.718 仍不能保证边界正确 |
| B-alternative-local | 相同候选，20–28 秒窗口 | 20–25.26 秒 | 句尾保持，首字仍吸收窗口前部；缩窗没有真正找到首字起点 |
| B-noise-negative | 音效对照上的旧 ASR 误词 | 0–17.98 秒 | 对齐器仍给出完整字词时间，不能据此证明词句存在 |
| C-original-full | 原当前组 ASR | 0–19.34 秒 | 中间某些字/标点吸收长停顿，整体不能自动提交 |
| C-core-full | 旧局部 ASR 的核心句 | 0–19.32 秒 | 首词吸收前段，标点还占据长时间；后半句定位相对集中 |
| C-core-local | 相同核心句，16–23 秒窗口 | 16–19.34 秒 | 尾字在原切片 19.10–19.34 秒；与完整窗口的末尾近似，但不作为人工真值 |
| C-wrong-text-negative | 自造无关日文句子 | 16–19.78 秒 | 字词均有有限、非负的时间段，仍是强制匹配；结构合格不证明内容真实 |

8 例均保留输入文字，音频输入指纹不变；没有自动接受任何候选。单例耗时约 0.23–1.77 秒，首次使用某音频时包括编码，重复音频复用了编码；不包含模型下载/加载，因此不是全链路 RTF 对比。

最明显的失败是原版 DTW 的首字/标点吸收停顿，以及错误文本也能得到完整时间段。本批不采用“按平均词长截短首字”掩盖这一问题。下一步若沿用此路径，需要额外的首字声学起点证据、词内停顿识别和文字正确性检查，不能只提高平均概率阈值。

## 听校工具修复结果

生成器增加旧标注导入校验：数据集身份、3 个音频指纹、8 个区间必须匹配，标签和备注原样保留。v1 历史播放范围保持 null；v2 只能带经过范围校验的 `playback_request_only` 记录，不声称覆盖用户手动拖动时听过的全部内容。操作原生播放器控件切换自由试听；新的区间试听按钮才重新建立有界循环。

新版文件 `test-results/subtitle-quality-review/asmr-listening-review-v2.html` 已嵌入用户原来的 8 条标注；原 HTML、下载目录的 JSON 和 NAS 原文件不变。无需重填或再次提交听校。页面新增的播放记录只是今后复核的辅助信息，不能取代精确句界标注。
