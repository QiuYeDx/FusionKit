# T-SEG-04A：原段内分隔恢复接入默认转写

日期：2026-09-05。关联 R-SEG-02、R-SEG-04、R-SEG-05、R-SEG-06、R-SEG-07。用户要求连续推进，本批完成消费者、服务模式隔离、执行器调度和实际应用验证。没有提交或推送本批代码。

## 结果与范围

Windows CUDA 的日语原文转写在开启 VAD 时，默认增加有界的原文分隔恢复。继续使用受管 large-v3；没有增加用户 CTranslate2 模型适配、额外模型依赖或词时间请求。其他平台、后端和语言保持原路径。

55 秒开头的第一、第二原段分别插入 4、2 个标点或空格。原来的 8 条字幕、每个字词和全部父段起止不变。第一段现包含“そうだ、イオリだ お前は誰だ?そうか、お兄さんか”，第二段恢复笑声后的逗号及另一处空格。相对于 T-SEG-02，这次是实际默认导出的新增改善，不再只是离线预览。

**仍未解决**：开头问候、“私だ”等仍在一个长段内；第二段后部也仍缺少分隔。没有新增逐句时间，也没有证明精准对齐。T-SEG-04A 完成只表示有界分隔功能接通，不能关闭 R-SEG-02 全部目标、R-SEG-03 或整个第十二阶段。

## 实现合同

- `cue-separator-restorer.ts`：至少 6 秒、12 字、含日语假名且缺少句末标点的原段进入资格检查；源 cue 必须唯一对应主响应原段及其完整起止。较短、已换行、跨窗口裁切或恢复后的非原始 cue 不补请求。
- 完整候选段组只允许给主识别原文插入标点；原生段界只能提供中性空格。优先匹配整个父段；若其他段存在识别差异，可采用一个至少 12 个 grapheme 的、唯一最长的连续完整原生段组，仅恢复其内部。匹配在整个根窗口原文中必须唯一。没有 LCS、删字、变更台词、抽取含错词段内部相似子串或新时间。
- ICU 分词只作为边界过滤。拒绝依附词和未知单假名碎片；敬语前缀“お/ご”紧接汉字时允许在整个前缀之前消费已有候选分隔。仍不把分词当语义或声学真值。原文空白、标点和源位置保留；资源上限或歧义直接返回原 cue。
- Supervisor 只从已有 batch pin 派生移除 VAD 的候选身份，保留原模型、VAD、加速包的资源占用保护。活跃 lease/请求或其他不兼容 pin 阻止切换；先退役原 VAD 进程，再加载非 VAD 进程。下一个主任务重新按原 pin 加载 VAD；普通请求的模式身份检查没有放松。
- 执行器先完成主识别，再集中补充。仅主识别没有用过恢复/子窗/原音重试的根窗可补一次，原始 PCM 不增益；沿用主请求参数与正式 HTTP 字段合同，关闭 VAD 和词时间。连续两窗没有任何插入即停止增强；错误或 30 秒超时停止增强并保留已接受结果。超时后迟到的成功响应也丢弃。
- 新请求沿用窗口文件品牌、调用前后文件身份、响应 epoch/generation、内存保留预算和输出事务。用户取消、窗口身份错误及资源清理失败仍终止任务，不发布半成品；增强启动失败和普通推理失败不会丢失主识别结果。

所有音频及 NAS 字幕只读，推理本地执行；素材和原始响应仅在忽略目录 `test-results/subtitle-quality-review/phase12/production-separators/`，没有进入版本库。
