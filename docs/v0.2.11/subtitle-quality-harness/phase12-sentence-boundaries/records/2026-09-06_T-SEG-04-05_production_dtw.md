# T-SEG-04/05：默认转写接入受限 DTW 分句

关联 R-SEG-01/02/03/04/05/06/07。前提为用户对 12.080/14.840 秒候选反馈 aligned。首批完成现有引擎 producer 与原段内部消费；跨父段/跨窗统一规划仍未完成，不能关闭整个 T-SEG-05 或阶段 12。

## 实现

- `server-process-contract.ts` 的加载身份加入受限 `dtw_large_v3`，仅 Windows CUDA large-v3、非 VAD 推理可用；生成固定 DTW/关闭 flash attention 参数。普通模式不能复用此身份。Supervisor 仅从现有 batch pin 派生候选加载，主 VAD 退出后启动；请求模式与加载身份严格匹配，继续保留资源 pin 和取消清理。
- `server-contract.ts`/HTTP client 显式请求并保留独立 `dtwTokens`，只转换 token 点单位，不开放普通词 start/end 给生产时间规划。未计算、非整数或超限点变成 null，消费者拒绝。主 VAD 结果仍丢弃压缩词轴。
- `cue-separator-restorer.ts` 复用完整候选组唯一映射与原段归属检查，统一规划分隔和可用内部切点。原生段界/句末符提供候选位置，DTW 点提供时间；日语词内/依附词切点、缺失/倒序/退化点、组内错词不接受。保留原父段外边界，每子条至少 600 ms、每父段最多 8 切点；原有空白会因拆分落在 trim 边缘时拒绝切分，防止丢掉原文字位置。
- 已听校第二处相邻词内点相距约 1900 ms，原拟 1500 ms 间隔上限误拒正例；推理前后证据未改，设计按该已知正例修订为 2500 ms。没有重新试参数寻找更好识别，也没有硬编码日文或两个时间。
- 执行器将 DTW 复用为原有分隔候选的一次请求，根窗发生恢复时不追加；候选仍用原 PCM、30 秒截止、连续两窗未改变时停止。质量评估仅投影段字段，DTW 不成为主源文字证据或普通词轴。补充响应计入文本/对象预算，新增条数超过格式总上限则回退分隔恢复。
- 新任务 `cuePolicy=sentence_readable_dtw_v3`，后处理 schema=3；接受旧 v2 快照并应用新策略，历史文件不重写。`segment_only_v1` 仍表示主识别提供的原始时间能力，DTW 是后续受限 cue 增强，不将主源标成逐词对齐。

该批没有引入新模型、用户模型导入、云端调用或设置开关。非 large-v3 模型保留此前分隔路径，其他平台维持原有路径。
