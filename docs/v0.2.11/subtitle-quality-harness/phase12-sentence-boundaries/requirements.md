# 第十二阶段：句界、标点与时间依据重整——需求

日期：2026-09-05。规模 M，单一的本地字幕生成模块，串行推进。本文件是本阶段需求基底；[设计](design.md)、[任务](tasks.md)据此执行。沿用 `docs/v0.2.11` 存量文档根，不代表发布版本。

当前状态：分析与方案已完成，生产实现未开始。用户要求先把原因和方案写清楚，再逐步实现；本轮停在文档检查点。代码基线为已人工认可的阶段提交 `9a4c2ea`，保留此前低音量保护成果。

## 问题与目标

用户在同一音频的两份 LRC 中发现：FusionKit 把日语词句从中间切开，又把多个短句连成没有标点或空格的长串。目标是默认“开始转写”就输出有可读句界、有时间依据的字幕，直接用于播放和后续翻译。

本轮已只读确认两份实际文件，并用完整 large-v3、CUDA、Silero v6.2.0 复现 FusionKit 的前六行，文字和时间标签全部相等。原始识别的前两段缺少标点；默认 7000 ms 时长限制把 14.09 秒的 28 字文本分成 9/10/9 字，把 8.37 秒的 38 字文本分成 19/19 字。切点来自字数比例。本例 `shortCueMergeCount=0`，不是上阶段短句合并修复失效。详见[实证记录](records/2026-09-05_T-SEG-00_diagnosis.md)。

本阶段必须同时处理：模型句界信息不足、后处理错误切分、短句连接方式，以及新句界的时间来源。仅提高时长上限、补几个标点、增加一个人工复核页面，均不能关闭整个需求。

| 场景 | 行为 |
| --- | --- |

| 转写后翻译 | 先形成新的稳定字幕条目，再按既有翻译协议消费；翻译阶段不负责修复原文时间轴 |

## 需求

### R-SEG-01 禁止由长度约束制造词中截断

- 来源：用户“そ／うだ”“誰／だ”“そな／た”实例；优先级 P0。
- 默认时长、字数和行长成为显示目标，不是新增时间戳的充分条件。一个完整长句允许在有语义依据的分句处切分，不要求每条严格对应语法上的一个句子。
- 验收：将本轮两条原始响应送入生产链路，不再出现这三个切法；字符顺序与出现次数保持一致。
- 异常：没有可信内部时间时，保留原识别段。超出显示目标记录降级；超过现有文件、文本或协议硬上限则沿用明确错误，不复制文字凑条数。
- 显示换行与时间条目拆分分别决策，修改每行字符数不得重新生成按字数推算的时间点。

### R-SEG-02 短句之间必须存在可读边界

- 来源：用户可接受多个短句同一行，但不能没有标点或空格地粘连；优先级 P0。
- 保留原始标点和有意义的分隔。独立短句可独立显示；确需同一条显示时，保留标点，或在已确认的短句边界添加一个空格。
- 禁止因为相邻文本含 CJK 字符，就默认它们属于同一个词或句。续词拼接、分句组合与未知关系必须使用不同决策。
- 验收：开头问候、身份回答、自我介绍与反问、回应与笑声、后续解释可区分；可以采用用户示例的五条组织，也可以在自然分句处形成其他可读组织。不得逐字照抄参考作为识别输出。
- 异常：边界类型未知时，保留原有条目；不能任意在日文字符间插入空格。真实重复和有字词的语气词保留。

### R-SEG-03 新时间边界必须有原音依据

- 来源：例中 7.029 / 12.061 / 20.775 秒由字数比例生成；优先级 P0。
- 新时间点必须指向原媒体时间域中的已验证文本位置，来自引擎段界、具备映射证据的词/子词时间，或经过检查的局部对齐。VAD、字数、标点各自单独不能确定某个词的起止。
- 废弃默认路径的字符比例拆时；不能把它包装为“估算”后继续当作本阶段已修复。
- 验收：新增的每个时间边界都能追踪到输入证据；长静音前后没有累计漂移。依据不足时保留原段，不伪造内部词轴。
- 人工听校前不要求与参考 LRC 的 `.01` 时间逐值相等；LRC 只给起点且经过其他工具处理，不能当作原音精确标注。

### R-SEG-04 统一处理原识别段内部和相邻段之间的句界

- 来源：用户期望的“そうか…はは、知っておる”跨越本次原始 16.59 秒段界；优先级 P0。
- 用一套有界的句界规划处理拆分和合并，原 ASR 段界是证据之一。禁止“逐段平均拆，再按短时长合回”两个互相抵消的步骤。
- 保留跨窗来源、文本位置与重复仲裁依据。不能删除整词来掩盖窗口重叠引起的识别差异。
- 验收：同句跨原始段、完整短句相邻、25～30 秒跨窗续句均有正反例；每段已接受源文只消费一次。改变显示目标不改变文字覆盖。

### R-SEG-05 句界恢复与原文纠错分开

- 来源：用户要可读转写，不能借分句重写台词；优先级 P0。
- 纯句界处理只允许改变分段、显示换行和有来源的标点/分隔；不允许增删字词、顺序调整或专名替换。
- 如局部重识别产生不同文字，作为 ASR 候选独立评估和选择；不能经“补标点”接口偷偷替换。
- 默认方案在本地运行；不新增云端付费调用要求，不把音频或字幕自动发送给翻译供应商。
- 验收：每次排版有精确源位置覆盖检查；标点只能以限定插入操作出现；错误候选、缺项、重项、错序、超时均丢弃候选并保留可用原始段。

### R-SEG-06 输出、设置和翻译交接语义一致

- 来源：用户直接使用 LRC，并将字幕转入翻译；优先级 P0。
- SRT 与 LRC 使用同一个已提交的句界计划；SRT 内视觉换行投影为 LRC 单行时保留分隔。LRC 不另做分句，不丢弃同时间标签下的合法不同条目。
- 高级设置若从“最大值”改为“建议值”，必须同步文案、任务快照策略版本和配置解释，不能只改内部行为。
- 验收：生产执行器实际导出两种格式并回读；只调整显示行长时，相同句界计划的时间和文字覆盖不变；译文仍严格对应最终源条目与时间戳。
- 旧文件与已完成任务不自动重写；重转写继续走已有输出冲突策略。

### R-SEG-07 有界验证默认效果，再进行人工验收

- 来源：用户此前要求阶段成果可人工验收，本轮要求先设计后实现；优先级 P0。
- 基准最小集合：本次开头 0～55 秒、同一 `trk01` 全长、既有 B 低声/B-noise 无词音效/C 局部低声、阶段 11 独立序章全长。先定位小样本，提交人工版本前必须过全长。
- 机器必须证明：本例三个已知错误切点消失，新增切点有来源，保留可用文字，SRT/LRC 一致，NAS 指纹不变；不能只报告测试数量、字幕条数变化或格式正确。
- 人工必须评价：是否词中断开、独立短句是否可分辨、是否提前显示后半句、是否新增漏词/复读。未人工通过前不能称“整体已根治”。
- 每完成一份可用阶段包就按明确检查点交付，不通过延长研究替代默认生产接线。

## 约束与范围外

- 首要复现环境为本机 Windows x64 / CUDA / 完整 large-v3。现有 CPU/macOS 路径继续可用；某项增强未具备平台证据时保留原段，不能声称跨平台效果已通过。
- 原生推理仍最多一个活跃请求；基础 30 秒/5 秒重叠窗口、取消、输出事务和已验证的 VAD 时间域保护继续适用。
- 第一期纯后处理不得新增推理次数。时间能力选型限定在一个任务内，最多两个候选路径、三个试验输入，各一次首跑；失败只对该次故障做一次重试，不无限调参数。
- 增强路径提议的首版预算：每个待处理根窗口最多一次增强推理，任务额外模型请求不超过根窗口数；与已有质量重试共享总上限，不得再增加递归恢复层。耗时预算须实测，不把该请求上限误当耗时保证。
- 范围外：完整翻译知识库、新字幕编辑器、说话人分离、云端原文润色、全平台替换引擎、批量重写 NAS、保证所有语言和录音无误词。已确定的系统性硬切缺陷必须移除，模型词句质量按实际验收陈述。
- 文档中文；代码注释跟随现有英文习惯；产品文案同步现有四语言，技术诊断不进入字幕正文。
