# FusionKit 界面设计与验收

让新增/修改的工具页属于同一套 FusionKit 产品，并在交付前自己发现空间、密度和交互细节问题。本 Skill 保存项目约定；通用设计与自检机制由 `qiuye-ui-quality` 提供。后者不可用时仍按本文件完成任务，不依赖外部路径或强制安装。

## 设计依据

- 用户要求“世界一流、Apple / Vercel 级”表示质量要求，不表示换成其他产品的外观。明确的新视觉要求优先，不能用本 Skill 阻止用户改变设计方向。
- FusionKit 是桌面工具集：中性主题色、清晰边框、受控工具色、紧凑信息结构、明确的上传/工作/结果区域。不要凭“高级感”改成暖色编辑器、展示型大标题或大块宣传构图。
- 以相关且已认可的工具页面作为参照，复用共用组件。当前页面也可能有待修问题，不能把所有既有代码都当成不可变标准。
- 优先读 [组件与视觉约定](references/visual-contract.md)，只加载本任务相关条目。约定以 2026-09-08 本轮打磨后的源码为基线；后续已确认的设计变更应更新这里。

## 动手前的小清单

1. 读取目标页、`src/pages/Tools/_shared/ui/` 中涉及的组件及其调用侧覆盖；检查主题 token 与实际 shape / size 参数。
2. 选取相近参照：字幕工作台/转换器看列表与上传，文本翻译看任务工作区，音频页看 `AudioToolShell`，重命名看预览表。
3. 明确本次主要工作流、要保留的业务状态、最容易撑坏布局的数据和需要对齐的边。小改动用简短工作记录即可。
4. 对新页或重写页，用真实 Electron 观察参照和目标；微调只验证受影响区域及相关实例。不要把纯浏览器 mock 说成原生验收。

## 当前必须注意的视觉关系

| 关注点 | 本项目做法 |
| --- | --- |
| 共用壳层 | 使用 `ToolDetailLayout`、`ToolPageHeader` 和适当的 `ToolPanel` / `ToolConfigPanel` |
| 同类留白 | 常用面板标题、配置正文、上传区基础内边距 12px；正文按组件语义拥有 padding，不能重复叠加 |
| 分组 | 配置字段间通常 16px；工作区间通常 12px；列间 16px。不是每个 gap 都改成 12px |
| 靠角等距 | 按钮等元素靠近外层圆角时，上/右、下/右或对应左侧的实际留白优先相等；同时检查内外曲线和热区 |
| 底栏 | 按控件与必要留白控制高度；旧实现水平 12px、纵向 4px 仅为排查起点，不能凌驾于靠角等距要求；内容变多时合理换行 |
| 视图 Tab | 字幕工作台使用 `ClipPathTabs`，`shape="rounded"`、`smoothCorners`、`size="sm"`；不是 pill |
| 参数模式 | 保留适合语义的已有 radio / segmented / Select；不把视图 Tab 偏好套到参数选择器 |
| 文件元数据 | 文件名、必要摘要和视图操作共享横向空间；窄窗口合理折行或移入已有选择器 |
| 字幕正文 | 单行按内容高度呈现；长正文自然换行，编号、时间和操作顶部对齐 |
| 文档列表 | 离散条目保留选中与相邻 hover 的间隔；当前为 4px；键盘焦点清楚 |
| 名称提示 | 文件名中间省略且完整信息可访问；文件名 Tooltip 自然换行、内容自适应，最大 20rem 并受视口约束 |

## 自主审查与二次修复

实现后切换到审查视角，按顺序检查：

1. **产品一致性**：与参照页同屏比较，是否仍是 FusionKit 的同一套组件和视觉层级。
2. **空间预算**：上传区、标题、元数据、Tab、表头、底栏是否挤掉正文；横向有空位时是否仍不必要地竖向堆叠。
3. **密度与高度**：一行字幕是否因时间块或按钮被撑高；自动/显式换行后其他列是否跳到中间。
4. **边距与对齐**：上下左右、同类面板、按钮与 Tab 的边缘、刷新图标所在按钮、配置折叠区和分隔线。逐一比较靠角元素与相邻两条边的留白，看圆角之间是否均匀；先选合理尺度，不能总通过增大较小边距来“拉齐”。
5. **真实状态**：长短名称、Tooltip 打开、选中旁边 hover、焦点、禁用、错误恢复、分页首尾和视图切换。
6. **适配**：目标 Electron 窗口、深浅主题与实际长文案；检查视图及真正滚动容器，不用全局裁剪隐藏溢出。

找到问题后定位组件默认值、父子约束或局部覆盖，修复并重看对应状态。用户连续指出边距问题时，审查已授权范围内的共同来源，而非不停新增 `headerClassName` 特例。共享组件变化需要查看其他消费页；单个 Tooltip 修复不自动扩大成全工具集重写。

“构建通过”“没有横向溢出”“Tooltip 可见”均不能替代实际截图审阅。没有可处理问题且相关证据有效时交付，不为了固定轮数继续改动。

## 验证与交付

按 [Electron 验证入口](references/validation.md) 选择与影响范围匹配的检查；UI 文案变更同步 `zh / en / ja / zh-Hant` 并做项目 i18n 检查。

同时遵循本项目已有 `fusionkit-pitfall-guard`，特别是等待 loading 退出、构建入口、真实滚动容器、圆角 token 和进程清理。不要复制这些流程成另一份会过期的避坑文档。

交付说明体验变化、实际验证范围和剩余限制。结束前关闭本次启动的前端/Electron 进程并确认，保留用户原有实例。UI 优化不应顺带更改依赖或升级 lockfile。
