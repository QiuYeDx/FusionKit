# 组织与匹配设计

## 按「用户会勾选什么」来分资料集

资料集是用户在工作台勾选的单位。按需选择以下几层，不要求每个项目都建齐：

| 资料集 | 适合内容 | 不应放入 |
| --- | --- | --- |
| 通用 | 字幕保真、人称、标点、稳定的领域词 | 某部作品的人物关系与固定口癖 |
| 场景 | 护理、技术讲解、特定语域 | 未确认的实际剧情 |
| 作品／主播 | 专名、关系、有来源的背景 | 从声优、封面或目录猜测的身份 |

轻量需求可以只有一个资料集和几条术语。同一个词在通用层和作品层译法不同时不会自动覆盖，应拆在不同资料集里并告诉用户不要同时勾选，或只保留一处。

只对某个说话人或场景成立的约定，写进说明正文，例如「主播 A 自称『僕』时译为『我』」。AI 会按语境判断；没有自动的说话人识别。

## 匹配不等于翻译替换

当前匹配是 NFC 规范化后的字面匹配，大小写可配置；没有日语分词、语义消歧、正则或词干还原。

- `whole_term` 要求两侧都是 Unicode 单词边界，适合英文专词。日文连写会让它漏掉词，例如「今日は耳かきをします」中的「耳かき」。
- `literal_phrase` 不要求边界，适合完整的日文专词或短语。过短的词可能误命中其他词的一部分，因此不要把单字、短假名或多义助动词固定为术语。
- 只收有依据、有用的异写和别名，不要堆积猜测出来的活用形式。NFC 不等于 NFKC，全角半角、片假名变体不会全部自动归一。
- 长词优先：短词的命中完全落在长词之内时（如「ホロウ」在「零号ホロウ」中）只用长词，不算冲突；短词在同一句另有独立出现时照常使用。两个词只部分重叠且译法不同时仍是冲突，调整词条顺序不能解决。
- `preferred` 不是逐字替换命令；`keep_source` 要求 target 与 source 一致，命中的别名按原样保留。

「大丈夫」「いい」「ダメ」「いく」这类词更适合写成要求，而不是术语。「シャンプー」可能指洗头也可能指洗发水，资料集名叫「护理」并不代表所有句子都已消歧。翻译时要保留否定、条件、左右方位与施受关系，不要按题材预判。

## 体积

优先收录稳定、常用的词和必要的背景。过长的通用要求会加重每一批的负担。

当前执行上限：
- 选中条目 2000 条；
- 术语与要求合计 500 条；
- 每个术语连同原词最多 128 个写法。

匹配次数、扫描量、冲突比较和模型上下文另有限制。预算不足时，「优先」条目可能被省略；「必须」内容放不下时会阻止执行。

## 本地音声／双语字幕抽样经验

目录、文件名和字幕是三种不同的证据。按作品编号或版本抽样：先列出类型，再读必要的小段；不要默认处理整个音频库。保留原始文件，不要悄悄重命名或去重。

- 相同时间戳可能是交替双语、多个说话人或多行字幕。先看内容再判断，不要按奇偶行一刀切拆分。
- WAV、MP3 目录可能带重复字幕，也可能是不同版本；同名不代表同内容。
- 「已自翻」、相同时间戳或双语并存，都不能证明译文正确或经过人工确认。
- 声优与角色要分开；作品标签不能证实角色身份、年龄或关系。
- 不要把 ASR 的错听和重复固化进词表。一次性的修正属于校对，只有稳定、可复用的译法才进入资料。
