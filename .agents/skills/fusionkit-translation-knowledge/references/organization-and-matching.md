# 组织层级与匹配设计

## 组织以任务选择为中心

资料集并列存放条目，方案组合资料集与风格；对象和来源是关联实体，不是树形父级或隐含优先级。按需要选以下层次，不要求每个项目建齐：

| 层 | 适合内容 | 不应放入 |
| --- | --- | --- |
| 共通 | 字幕保真、人称、标点、稳定领域词 | 某部作品的人物关系与固定口癖 |
| 场景 | 护理、技术讲解、特定语域 | 未确认的实际剧情 |
| 作品／版本 | 专名、关系、有来源的背景 | 从声优、封面或目录猜测的身份 |
| 人物 | 有依据的称呼、确实出现的表达 | 仅被提及者的说话口吻 |

轻量请求可只有一个资料集和几条术语。多个风格只有实际选用差异时才值得建；互斥规则分开资料集，否则选中一个风格仍可能带入同集的其他规则。共通层与作品层同词异译不会自动覆盖，需限定范围或明确本次排除项。

`aboutSubjectIds` 仅分类；`scope.requiredSubjects` 是硬门槛，每一项都必须匹配，不能表达“任一人物”。普通资料默认空门槛。作品背景可限定 topic，人物口吻限定 speaker，mentioned 只代表被提及。方案的 `subjectSuggestions` 不能替用户确认当前字幕身份。

`condition: advisory` 是模型参考，不自动验证场景；决定强制生效的条件用 `requires_confirmation`。term 的 `sense` 也不会阻止错误语境中的字面命中。重要歧义可用完整词组、分场景方案或确认条件，不依赖一段免责声明。

## 匹配不等于翻译替换

当前是 NFC 规范化后的字面匹配，可配置大小写；没有日语分词、语义消歧、正则或词干还原。

- `whole_term` 检查两侧 Unicode 单词边界。英文专词通常合适；「今日は耳かきをします」的连写会使此模式漏掉「耳かき」。
- `literal_phrase` 不要求边界，适合完整日文专词／短语；过短词可能误命中其他词的一部分。避免将单字、短假名或多义助动词固定为全局术语。
- 只收有依据、有用的异写和别名，不堆积猜测活用。NFC 不等于 NFKC，全角半角和片假名变体不会全部自动归一。
- 长词内嵌短词且译法不同时可能产生冲突；“长词写前面”不解决冲突。
- `preferred` 不是逐字替换命令，`keep_source` 要求 target 与 source 一致，保留实际命中的别名原样。

「大丈夫」「いい」「ダメ」「いく」等更适合语境要求。「シャンプー」可能指洗头或洗发水，资料集名叫“护理”不代表所有句子已消歧。保留否定、条件、左右方位与施受关系，不靠题材预判。

## 体积与场景

优先稳定、经常使用的词和必要背景。过长通用规则增加每批负担，过多人物条件增加操作成本。制作术语、作品特典和不同文风按需分组。

协议单包上限并非执行预算。当前执行上限包括选中条目 2000、术语及规则 500、每术语含原词 128 个变体；匹配次数、扫描量、冲突比较和模型上下文另有限制。低于 20,000 实体不证明适合一次全选。预算不足时建议性条目可能被排除，强制内容不足则阻止执行。

## 本地音声／双语字幕抽样经验

目录、文件名和字幕是不同证据。按作品编号／版本抽样，先列类型，再读必要小段；不要默认处理整库音频。保留原始文件，不默默重命名或去重。

- 相同时间戳可能是交替双语、多说话者或多行字幕。检查内容再判断，不能按奇偶行通用拆分。
- WAV、MP3 目录可能带重复字幕，也可能是不同版本；同名不证明同内容。无必要只参考一个明确版本，不重复统计。
- “已自翻”、同时间戳和双语不证明正确或人工确认；无确认与对齐证据就不建 memory。
- 声优与角色分开；作品标签不能认证角色身份、年龄或关系。未知事实标未核实，不把目录标签变成核心背景。
- 不将 ASR 错听和重复固化成词表。一次性修正属于校对，稳定可复用译法才进入资料库。

可用「綿棒を使います」等普通虚构句检查术语匹配，同时检查另一作品的人物要求不会无条件生效。此类测试句不应标成真实参考译文或已审核素材。
