# 来源和证据的整理

研究范围由用户要求决定，尤其记录作品同名歧义、发行版本、平台和语言变体。官方本地化原文优先，其次是原始设定/开发者资料，再考虑有明确出处的二手资料。不同版本不能合并成一个无条件译名。

`web` 来源必须有实际读过的页面 URL、UTC `accessedAt`、标题和必要摘录；作者/版本放 `attribution`。不把搜索摘要、模型记忆或不可访问页面写成“已核对原文”。URL 只描述来源，不要求接收者抓取或读取文件。

用户自订译法、提供的设定和风格要求用 `user_note`，摘录用户实际要求；不要称为官方。模型建议用 `ai_proposal`，证据关系标 `inferred`，保持候选。已有 source 不必为每条复制，条目通过 `evidence` 引用。

背景的 `fact` 表示可核对的事实陈述；角色/作者被引用的说法用 `reported`；缺证据或相互矛盾用 `uncertain`，不得核心化。不要用“置信度 95%”伪装审核。必要推断说明依据，`derivedFrom` 附父条目的 ID/修订/工具计算摘要及随包证据摘录，允许不共享父条目原文。

遇到译名争议，保留不同译法的来源、版本、范围与候选状态。可以使用独立资料集表达官方与个人偏好，不能通过数组顺序暗设优先级。`sense` 是解释文本，不会自动判定场景；场景决定强制生效时，使用 `requires_confirmation`。

参考译文必须来自用户实际确认且对齐的片段。`one_to_one` 表示确认了一对一对齐，`reviewed_segment` 表示确认整段关系；后者不能擅自拆句。来源中说明原译文、确认来源和对齐关系，保留 `directReuseAllowed: false`。无此证据就省略 memory，不能编造“示例审核”。

只摘录证明条目所需的内容。不要输出 API key、凭据、私有任务路径和未经用户要求共享的字幕正文。来源文件用显示名；`contentDigest` 只有在真实计算原始字节后填写，同时用 `digestDescription` 说明计算对象。它不同于实体的 JCS 摘要。

研究报告说明哪些来源实际可访问，哪些结论仅基于用户资料，以及未解决歧义。协议验证不会验证这些事实，也不授予接收设备上的信任。
