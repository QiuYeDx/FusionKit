# 来源整理

研究范围由用户的要求决定。需要特别记下：作品同名歧义、发行版本、平台、语言变体。来源优先级：
1. 官方本地化原文；
2. 原始设定或开发者资料；
3. 有明确出处的二手资料。

不同版本的译名不能合并成一条不带条件的术语。

条目上的 `origin` 记录来源：

| 来源 | 写法 |
| --- | --- |
| 用户自订的译法、设定、风格要求 | `kind: 'manual'`，`note` 摘录用户的实际要求；不要称为官方 |
| 网页 | `kind: 'web'`，必须是实际读过的页面，填写 `url`、`title` 和 UTC `at` |
| 模型自己的推断 | `kind: 'agent'`，拿不准时设为 `enabled: false` |
| 已确认的字幕修订 | `kind: 'revision'` |
| 用户提供的文档 | `kind: 'import'` |

搜索摘要、模型记忆和无法访问的页面，都不能写成「已核对原文」。

背景只写可核对的事实。转述的说法在正文里写明出处（例如「据官方访谈……」）；未证实的内容要么不收，要么在正文前标「（未证实）」并设为 `enabled: false`。不要用「置信度 95%」伪装审核。

译名有争议时，用独立的资料集分别表达官方译名和个人偏好，并告诉用户不要同时勾选，不要靠数组顺序暗设优先级。

只摘录证明条目所需的内容。不要输出 API key、凭据、私有任务路径，也不要输出用户没有要求共享的字幕正文。研究报告要说明三件事：哪些来源实际访问过，哪些结论仅基于用户资料，还有哪些歧义没有解决。协议校验不验证这些事实。
