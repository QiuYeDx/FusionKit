# FusionKit 翻译资料准备

交付 UTF-8 `.fktk.json` 与简短使用说明。支持 FK-TK/1（`schemaVersion: 1`），按当前字幕工作台能力组织资料；协议兼容不代表资料已采纳或每条都参与请求。离线校验器已打包依赖，只需 Node.js 18+，无需 FusionKit、联网或安装 npm 包。

## 从需求到可用资料

1. 确定语言方向、作品／领域、版本与已有偏好。使用已有上下文合理决定分组；仅在关键歧义妨碍整理时询问。旧包先校验，保留其身份与约定。
2. 读 [文件协议](references/protocol-v1.md) 和 [当前能力与交付](references/application-usage.md)。第一次制作可参照 [无额外绑定的日中入门包](examples/ja-starter.fktk.json)；需要人物范围、条件或派生更新时再读 [多对象示例](examples/multi-subject.fktk.json) 与 [更新示例](examples/update.fktk.json)。示例为虚构演示，不是真实作品证据，制作新包时生成新 UUID。
3. 依据 [组织与匹配](references/organization-and-matching.md) 设计最少够用的资料集，再搜集内容。不要为凑齐对象、风格、方案或五种条目而制造信息。事实核查和本地材料抽样遵循 [证据整理](references/research-and-evidence.md)。
4. 优先提供真正参与翻译的术语、背景、要求。把共通规范、可选场景和作品专属内容分开；通用条目默认 `requiredSubjects: []`，不能把分类对象机械复制为使用门槛。只有确实依赖作品／人物的内容才限定范围。
5. 模型建议用 `ai_proposal`、证据关系 `inferred`、初始 `candidate`；真实用户约定才用 `user_note`。未证实背景用 `uncertain` 且 `core: false`。没有明确需求不设置强制术语／要求或核心背景；不能为了方便导入，把 AI 建议伪装成已采纳。
6. 按下面的验证与交付要求完成文件和说明，不只输出提示词或无法导入的表格。

## 保持可执行、可审核

- `ja → zh-Hans` 等语言标签精确匹配；`zh` 不够明确，区域变体不自动等价。资料集默认语言不替代每条 scope 的语言。
- 日文连写优先评估 `literal_phrase`，不要机械使用 `whole_term`；多义短词、活用、重叠词和大小写差异见组织参考。义项与自然语言条件不是自动语义识别器。
- 对象说明“关于谁”，不是自动说话者识别。人物专属内容必须绑定正确 speaker，提及人物不授权其口吻；不得补原文不存在的口头禅、剧情或动作。
- 风格只组合同包 rule，方案引用风格的规则资料集必须在读取集合中。相冲突的风格拆集；顺序、层级名称和“作品专用”不表示覆盖优先级。
- 方案不能携带模型、密钥、温度、时间轴或任务绑定。当前通用偏好继承与自动积累未执行，通常设 `inheritGlobalPreferences: false`、`learningSuggestion: "off"`，不要依赖它们生效。
- 表达与参考译文目前是存储能力，不参与执行。没有人工确认且对齐的字幕证据就不创建 memory；双语文件、相同时间戳或“已翻译”文件名不是审核证明。
- 来源文件只用必要显示名和摘要，不输出私人绝对路径、凭据、任务 ID 或未经要求共享的全文。网页需实际打开读取，不能把搜索摘要冒充原文。

## 更新与身份

实体 ID 使用小写 UUID v4（可用 `crypto.randomUUID()`）。已有实体实际改动才增加 revision；换名或内容改动保留 ID，重新打包／排序不提升未改实体版本。新对象用新 ID；省略旧条目不等于删除。保留未知非执行性 extensions，不通过扩展字段发明旧应用不会执行的能力。

多套独立可导入的包共享共通层时，复用完全相同的实体 ID、revision 和内容；每包仍须有全部引用依赖。不要在不同包内暗改同 ID 同版本内容。语义差异用独立条目与明确范围，向用户说明冲突，不按文件顺序覆盖。

需要 derivedFrom 时，使用协议中的 `--digest` 获取父条目 JCS 摘要并附充分脱敏证据。更高协议版本应使用匹配工具，不删字段降级。

## 验证与交付

以技能目录为当前目录，或使用脚本绝对路径：

```sh
node scripts/validate.mjs /path/to/output.fktk.json --json
```

退出码 0 表示结构及已知语义合法（可以有警告），1 为无效文件，2 为工具／IO 错误。修正全部错误后重跑。候选规则引起的 `STYLE_NOT_READY` 属于待本机采纳；真实术语冲突要解释范围，不能笼统宣称无问题。无可用 Node 时明确“未运行校验”。

另做使用检查：方案是否带齐依赖；常用词在真实或自写句中能否按字面命中；可选资料是否隔离；作品及人物条件是否需要本次绑定；是否把仅存储能力描述成参与翻译。校验器不证明来源、译法质量、语境或模型遵循情况。不要为此默认启动应用或调用付费模型。

随包简短报告：

- 范围、语言、包／协议版本和每个文件用途；多包共通层是否重复计数。
- 资料集、术语、要求、背景、候选、强制／核心条目数量；实际访问来源、未核实项与缺失证据。
- 实际校验结果和警告，区分文件合法、来源核实、本机采纳和模型执行。
- 使用路径：「翻译资料 → 导入知识包 → 待确认中筛选、选择并批量采纳 → 字幕工作台选资料／方案 → 检查或试译」。强制／核心条目及依赖归档项可能需单独处理，详见当前能力参考。
- 用一句话解释：资料集装内容，风格组合要求，方案保存搭配，对象标记领域／作品／人物。指出推荐起步方案或直接选哪几个资料集。

交付可点击的 `.fktk.json` 链接；ZIP 仅便于打包分发，不能当成翻译资料文件导入。
